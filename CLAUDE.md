# LsMsgPack

MsgPack serializer for .NET classes (like the xml and json serializers) with an optional indexed schema and type ids for polymorphic object models, plus a MsgPack explorer/debugging tool (Windows). The library is `LsMsgPackNetStandard/` (assembly and package `LsMsgPack`), on top of `LsMsgPackCore/` (assembly and package `LsMsgPack.Core`), which it shares with `LtMsgPack/` (a second serializer that writes and reads the same data without the item tree, see below). Published on nuget.org (the libraries, the formatters, `LsMsgPack.Mcp`, `LsMsgPack.TypeScript`) and npm (`@lsmsgpack/client`): **changes must be non-breaking** (since 2026.10.22): data written by released versions keeps reading, released readers read what the default settings write, and the public API is only added to (new behavior behind options or new members). A change that would break needs the maintainer's decision first; a feature added since the last release may still change until it is released.

dotnet test LsMsgPackInteropTests/LsMsgPackInteropTests.csproj -c Release
cd LsMsgPackVsCode && npm install && npm test         # the VS Code extension (TypeScript), after dotnet build of LsMsgPackVsCode/Server
dotnet test LtMsgPack.GeneratorTests                    # the source generator (snapshots, C# 7.3/.NET Standard 2.0 compile, diagnostics, contract fixtures)
dotnet test LsMsgPack.AnalyzerTests                     # the analyzers and their code fixes (source text against the libraries and the ASP.NET Core formatters)

- **Web formatters** (`LsMsgPackFormatters` ASP.NET Core, `LsMsgPackWebApiFormatters` Web API 2 + HttpClient, `LsMsgPackMvc` MVC 5 on .NET Framework) use **LtMsgPack**, not LsMsgPack (class and package names kept). Schema negotiation for x-lsmsgpack responses: request header `MsgPack-Schemas` (ids the client holds), response header `MsgPack-Schema` + `Vary`; the server writes with `WriteSchemaReference` and replaces the reference by the schema (`SchemaStore.GetInlineSchema`) when the client does not hold it or the schema is not longer than the reference. The client side is `LsMsgPackSchemaHandler` (`formatter.CreateHandler()`), which registers inline schemas (`SchemaStore.RegisterInline`) per server; `RequestDescribedSchemas` (`CreateHandler(true)`) adds `x-lsmsgpack; schema=described` to the Accept header (the TypeScript client's header when there is none), for clients with other classes. Request bodies always carry the schema inline (by design, see `docs/WebFormatters.md`). **Schema version 2 for clients without the classes** (`DescribeSchemas`, on by default, with the indexed schema, with or without negotiation): `Accept: application/x-lsmsgpack; schema=described` (`MsgPackMediaTypes.AcceptsDescribedSchema`, checked only for x-lsmsgpack responses) makes `LtMsgPackHttpSerializer` write with a second serializer (`SchemaVersion.Described`, the same `SchemaStore`: its schemas have their own ids and are negotiated alike), the body is the same; responses then have `Vary: Accept` (with `MsgPack-Schemas` when negotiated). Web API cannot set `Vary`: no workaround, the .NET readers read both versions. `ReportDifferences` (off by default, `LtMsgPackHttpSerializer.DeserializeBody`): ASP.NET Core `HttpContext.Features` + `ILogger` (Debug level, a warning with `LogDifferencesAsWarning`), Web API/HttpClient a `ConditionalWeakTable` per `HttpContent` (`GetReadDifferences()` on the content, request or response), MVC 5 `HttpContext.Items`; also the differences of a failed read (`DifferencesOf(ex)`). The formatter test projects also reference LsMsgPack, to check the bytes against it. `LsMsgPackMvcTests` (net472) builds but cannot run on Linux.

## Language and targets

- LsMsgPack targets `netstandard2.0;netstandard2.1`, LsMsgPack.Core and LtMsgPack also `net8.0` (October 2026, for the trim and AOT analyzers: `IsAotCompatible` on that target only). 2.1 exists to ask `RuntimeFeature.IsDynamicCodeSupported` (`PropertyAccessor.CanCompile`: not `IsDynamicCodeCompiled`, which is false on WebAssembly, where the typed delegates are still 3-4.7x faster than reflection) and for span APIs: write `#if NETSTANDARD2_1_OR_GREATER || NET5_0_OR_GREATER` (net8.0 does not define the NETSTANDARD symbols). .NET Framework picks 2.0, .NET 6/7 pick 2.1, .NET 8+ net8.0, so the test projects (net8.0) run the net8.0 builds; the .NET Standard builds are only compiled on Linux. System.Memory and Unsafe are package references of the .NET Standard builds only.
- **Trim and AOT annotations** (Core and LtMsgPack): the constructors of `LtMsgPackSerializer`/`LtMsgPackHttpSerializer` without a context (and `LtMsgPackSerializer.Default`) carry `[RequiresUnreferencedCode]`/`[RequiresDynamicCode]` (like `XmlSerializer`'s constructors: one warning where a reflection serializer is created, `Serialize`/`Deserialize` are not annotated); the constructors taking an `LtMsgPackContext` are not (it is prepended to the options' `Contexts`). Inside, every reflection site is fixed or suppressed with `UnconditionalSuppressMessage` and a reason from `Meta/TrimReasons.cs` (ModelTypes, TypeNames, KeptMembers, Instantiations, ImmutableFactories, Fallback): suppress at the site, not by annotating whole classes, so new reflection still warns in the net8.0 build. Framework members used by reflection are kept with `DynamicDependency` (`FrameworkTypeInfo` `Property`/`Method`/`Constructor`/`Operator`, string form with `System.Private.CoreLib` so the .NET Standard builds can name `DateOnly` etc.; net8.0 uses `typeof`). The attributes are polyfilled internally for the .NET Standard builds in Core `Meta/TrimAttributes.cs` (LtMsgPack uses them through `InternalsVisibleTo`, do not declare them again there; the Web API formatter has its own copy). The ASP.NET Core formatters run the analyzers on net8.0 (`EnableTrimAnalyzer`/`EnableAotAnalyzer`, not `IsAotCompatible`: MVC is not trimmable) with context overloads of `AddLsMsgPackSerializerFormatters`; MVC 5 (net462) has no annotations.
- netstandard2.0 compiles as **C# 7.3**: no `??=`, switch expressions, `is not`, ranges, `using` declarations or nullable annotations. `Dictionary.TryAdd` comes from `Meta/MissingExtensions.cs`.
- Style: 2-space indentation, `_camelCase` fields, explicit types rather than `var`, comments explain why. Some files use a different brace style, match the file. Most files are UTF-8 with BOM, keep it when editing with scripts (e.g. Python `encoding='utf-8-sig'`).

## How it works

- **Two phases.** Writing: object → `MsgPackItem` tree (`MsgPackSerilaizer_Pack.cs`, note the typo in the name: `SerializeObject`, `SerializeCollection`, `AddProperties`) → bytes (`MsgPackItem.WriteTo(ByteWriter)`, containers write their items into the same buffer). Reading: bytes → `MsgPackItem` tree (`MsgPackItem.Unpack`, each `Types/Mp*.Read`) → plain values (`object[]` for arrays, `KeyValuePair<object, object>[]` for maps) → objects (`MsgPackSerializer_Unpack.cs`: `ConvertDeserializeValue`, `ConvertMap`, `SetProperties`).
- **Items** (`Types/`): `MpInt` (keeps the original integer type, `DynamicallyCompact` picks the smallest encoding), `MpString`, `MpBin` (also `Guid`), `MpFloat`, `MpBool`, `MpNull`, `MpArray`, `MpMap`, `MpExt` → `MpDateTime` (type -1, timestamps) and custom extensions via `AbstractCustomExt<TSelf>` (`MpDecimal`, type 1, registered in `MsgPackSettings.CustomExtentionTypes`), `MpRoot` (several items in sequence), `MpError` (KEEPTRACK). Framework types without settable properties are written like MessagePack-CSharp does (`Meta/FrameworkTypes.cs`, Core `FrameworkTypeInfo`): `char` as an integer, `TimeSpan` and `TimeOnly` as ticks, `DateOnly` as its day number, `Uri` as its original string, a `KeyValuePair<,>` as `[key, value]` (`FrameworkTypeInfo.GetPair`, Ls `SerializePair`, Lt `TypeKind.Pair`; collections of pairs are maps), tuples as an array of their items (`GetTuple`, Ls `SerializeTuple`, Lt `TypeKind.Tuple`; the 8th item, Rest, is a nested array), multidimensional arrays as `[length0, ..., [items]]` (Ls `SerializeMultidimensional`, Lt `TypeKind.MultiArray`, Core `ConvertMultidimensional`; type names `Int32[,]`). The types with a `PlainForm` (`GetPlainForm`/`ToPlain`: `Half` float32, `Version`/`StringBuilder` text, `CultureInfo` name, `Rune` code point, `nint`/`nuint` integers, `Memory<byte>`/`ReadOnlyMemory<byte>`/`ArraySegment<byte>` bin, `Complex` `[real, imaginary]`, `BigInteger`/`Int128`/`UInt128` an integer when they fit in 64 bits, otherwise extension type -2 in big-endian two's complement, minimal length, as the proposals of msgpack/msgpack#206 agree) are written as their plain value (Ls `FrameworkTypes.PackPlain` in `MsgPackItem.Pack` after the custom extensions, Lt `TypeKind.Plain`/`WritePlain`) and read by `FrameworkTypeInfo.TryConvert`/`TryConvertItems`/`TryConvertExtension` (also MessagePack-CSharp's bin for big integers). `DateOnly`/`TimeOnly`/`Half`/`Rune`/`Int128`/`UInt128` are found by name (.NET Standard does not have them), conversions by reflection (`Operator`). Immutable and frozen collections are filled by their static factory (`CollectionInfo.FindFactory`: `CreateRange`, `ToFrozenSet`...; `IImmutable*` interfaces map to their implementations), `BitArray` by its `bool[]` constructor. A non-public framework type (the `FrozenSet` of `ToFrozenSet()`, LINQ iterators) gets no type id (`SerializationRules.IsHiddenFrameworkType`): no reader resolves its name, the reader creates the declared type. Other **framework** types without settable properties (but with readable ones or public fields) are refused with a `MsgPackException` when an object of them is planned (`SerializationRules.ThrowIfUnsupportedFrameworkType`, cached per type: Ls `SerializeObject`, Lt `ObjectPlan`/`ReadPlan`, Core `ConvertMap`/`ConvertArray`), as are `Type` and `MemberInfo` (the data would pick types). A custom extension for such a type is asked first. Ls and Core only check when the type has no serialized properties (the check is a dictionary lookup, the properties are cached: measured 3-7% on writing when it ran per object). Types of other assemblies without settable properties still become an empty map.
- **Unknown extensions** (a type code without a registered custom extension) stay an `MpExt` in the unpacked tree (`MsgPackItem.UnpackedValue`, used by `MpArray`, `MpMap` and the serializer's root): they are converted to `byte[]` or kept as `MpExt` (object), anything else throws. Their bytes used to be converted like `bin` (a 16 byte extension became a Guid).
- **Objects** are arrays of their values by default (see the array layout below), or with `ObjectLayout.Map` maps from property id to value. The property id is the name, or what an `IMsgPackPropertyIdResolver` returns (`PropertyNameResolvers`), or with the indexed schema the index of the name in the schema. Filters: static ones decide per property (`FilterNonSettable`, `FilterIgnoredAttribute`, `FilterStatic`), dynamic ones per value (`FilterDefaultValues`: default values are omitted, empty strings are written like the JSON serializers do unless `omitEmptyStrings`; LtMsgPack's typed `IncludeByDefault` mirrors it and only takes that path for the default configuration). `FilterIgnoredAttribute` recognizes "ignore" attributes by full type name (`IgnoreAttributes` flags; where it looks: `IgnoreAttributeLookup`, the property itself, the overridden ones, interfaces, per preset as its library, default everywhere; no references to those libraries, System.Text.Json's `Condition` and PolyType's `Ignore` read by reflection), its `Like<Library>` presets are checked against those libraries in `IgnoreAttributeTests` (interop). Filters are immutable: the results are cached per filter array.
- **Array layout** (`MsgPackOptions.ObjectLayout.Array`, the default, writing only): an object is an array of its values in `PropertyOrder` (Ls `SerializeAsArray`, Lt `ObjectPlan.WriteArray`), nil for a value the dynamic filters leave out. Trailing nils are kept by default (the same bytes as MessagePack-CSharp's `[Key(n)]`, `IntegerKeys_SameBytesAsArrays`) and left out with `TrimTrailingNulls` (Lt reserves the array header and patches it, `MsgPackWriter.PatchArrayHeader`; nil is the only one byte value 0xC0). `MsgPackMediaTypes.ToPlain` and the `LtMsgPackPresets` for other libraries switch to `ObjectLayout.Map`. A type id wraps it: `{ "": typeId, "@": [values] }`; without a type id an ambiguous value throws (`SerializationRules.ThrowIfUnresolvableAsArray`). Readers take an array assigned to an object type by position (Core `ValueConverter.ConvertPositional`, Lt `ObjectReader.ReadPositional`): with the indexed schema the positions are matched by the names of the schema (the writer's order does not matter), without it the reader's own order must match the writer's. A nil sets the value the writer leaves out (`FullPropertyInfo.NilValue`, cached in `PropertyAttributeSet.Nil`: the `[DefaultValue]` when it fits the property and the reader's `DynamicFilters` have a `FilterDefaultValues` (`MsgPackOptions.LeavesOutDefaultValues`), otherwise the type's default: null as JSON reads it; Lt `PropReader.ReadNil`), a value missing after the end of the array leaves the property as the constructor made it (like a key that is not in a map; also what `TrimTrailingNulls` trims), extra values are skipped. Until October 2026 a nil also kept the constructor's value (`ExplicitNullKeepsTheConstructorValue`, replaced by the maintainer's decision: null could not be read into an initialized property, unlike JSON); the bytes did not change, only reading. The one case nil cannot tell apart: a null where a non-null `[DefaultValue]` is left out too reads as the `[DefaultValue]` (analyzer LSMP006). `omitEmptyStrings` empty strings read as null. The ids are still resolved before the type id and the values, so the schema is the same as for maps.
- **Former property ids** (`FullPropertyInfo.FormerId`): until October 2026 `AttributePropertyNameResolver` did not find `[JsonPropertyName]`/`[JsonProperty]` (looked up by the wrong key) and did not read `[XmlArray]`/`[DataMember]`, so data written then has the .NET name (or its schema index) for those properties. `ResolvePropertyId` records that id when one of those attributes gives the id (`TryGetFormerId`: the XML name, else the earlier resolvers, the schema without adding to it (`IdOfName`), the name), `KeepUnambiguousFormerIds` drops the ones that are another property's id or former id and sets `MsgPackOptions._formerIds`, and only then does `ValueConverter.SetProperties` read the key of a former id when the map lacks the id (Lt and Gen read through Core with custom resolvers). The attribute names are read once per property (`PropertyAttributeSet.Names`). Without the schema custom resolvers run per object: keep this path allocation-free.
- **Case-insensitive names** (`MsgPackOptions.PropertyNameCaseInsensitive`, off by default, on in the HTTP serializer): reading maps keyed by names, a key that is no property name sets the one property whose name equals it ignoring case (none when several do, nor when the exact name is in the map too). Lt: `ReadPlan.FindByName` calls `FindOrMatchIgnoringCase` only when the next property does not have the exact name (kept apart: the extra code in `FindByName` measured 2-3% on reading names, option off too): the next property ignoring ASCII case when the first byte differs only in case and no property collides with it (`_ambiguous`), the exact scan, then ASCII keys and names compared as bytes, other ones as strings (20 × 100 invoices with camelCase keys: 7.7 ms exact, 26 ms with a string per key, 12.3 ms now); Core: `ValueConverter.SetProperties` counts the keys it set and runs `SetIgnoringCase` only when some are left (`ReportUnknownKeys` does not report the matched ones). With the indexed schema (since October 2026): the names of an entry are bound to the reader's properties ignoring case by the same rules, once per entry (`ComplexTypeDef.IdsIgnoringCase`: Core `GetId` (cached on the entry per reader class) and `PropertiesByPosition`, Lt `BoundSchema.Bind`), and `BindReaderTypes` follows the properties ignoring case. For camelCase writers (the TypeScript client).
- **Reserved map keys**: `""` holds the type id and `"@"` the content of a wrapped value (`MsgPackSerializer.TypeIdKey` / `ContentKey`). A collection is written as an array (a dictionary as a map), and only wrapped in a map when it needs a type id or properties (`SerializeEnumerableAttribute.SerializeProperties`).
- **Type ids** are added when the value's type differs from the declared type (`AddTypeIdOption.IfAmbiguious`, default). They are short type names by default (`AddTypeIdOption.FullName` for full names), and resolved again by name when reading (`Meta/TypeResolver.cs`). Generic arguments are written as `List<Int32>` (parsed back by `SplitByParsing`, recursive descent), a class nested in a generic class with its own arguments per class joined by `+`: `Outer<Int32>+Inner`, `Gen<Int32>+NestedGen<String>` (the short name starts at the outermost generic class; until October 2026 the short name threw and the full name was the outer class's).
- **Anonymous types** (since October 2026, docs/schema.md "Anonymous types"; before: an empty map/array, `FilterNonSettable` left their get-only properties out): `FilterNonSettable` keeps the properties of anonymous types (`SerializationRules.IsAnonymous`: top-level, not public, compiler generated, `<>`/`VB$` + `AnonymousType`), `PropertyAccessor` sets their fields (`<Name>i__Field`, VB `$Name`) when reading into one. A type with an anonymous type (itself, or as a generic argument/element: `SerializationRules.HasAnonymousType`, cached) never gets a type id (`NeedsTypeId`, no reader resolves it) and is named without the compiler's prefix (`TypeResolver.AnonymousName`: `AnonymousType0<Int32, String>`; `<>f__...` made released readers throw on the whole schema). Placement (`WritesByNames`/`EntersByNames`, both serializers must agree, `CrossLibraryTests` corpus): where declared and not below an object with an anonymous type (the root, the elements of a root collection; a root `Page<anon>` too, but its `Data` is below it) it is written like any class (schema entry; the reader pairs the root); a value with an anonymous type not written as its declared type (`object`), and every such object below an object with an anonymous type (v1 readers cannot pair below an unresolvable class), is a map of names (`FullPropertyInfo.GetNamedProps`: the static filters' shared instances, names from non-schema property id resolvers), any layout, no schema entry; Ls passes `byNames` through `SerializeObject` and its helpers (`SerializeByNames`), Lt `WriteContext.ByNames` (reset with `Depth`), `WriteTypeInfo.HasAnonymousType` makes those types `BoxedHandler`s so `WriteWithAnonymousType` decides, `NamesPlan`. `SchemaTypes` follows the same context. Readers: with the schema, a map whose keys are all strings (`ValueConverter.HasOnlyNames`) is matched by name (`GetNamedProps`), no entry needed (Lt falls to Core through `Slow`). Released readers: 26.1+ read the root/root collection, all read the maps as `object`, maps read into a class throw "no schema entry". `PayloadValidation` counts mixed kinds in a dictionary only when v2 declares it `dict` (a v1 map with string keys may be such an object).
- **Immutable classes** (since October 2026, docs/schema.md "Immutable classes"; before: properties without a public setter were left out, a `Money(decimal amount, string currency)` arrived empty): Core `ObjectConstructor` (cached per type, also replaces the parameterless constructor cache of `Instances`) picks `[JsonConstructor]`/`[SerializationConstructor]` (by full name) or the only public constructor without a public parameterless one, binds parameters to properties by name (ignoring case, exact first) and type, and is used (`WithValues`) only when it takes a property without a public setter; not for framework types, collections, anonymous types. `FilterNonSettable` keeps those properties (`ObjectConstructor.Sets`). Reading (fallback path only): `Instances.CreateObjectOrArguments` returns an `ObjectConstructor.Arguments` that stands for the object, `ValueConverter.Assign` collects into it, `Created` calls the constructor (missing bound values: `NilValue`; parameters without a property: their default) then sets the other properties; `ReadDifferences` reports its class (`ClassOf`) and replaces it by the created object in the samples (`Created`). LtMsgPack: `GetReadPlan` returns null for these types, so they go through `Slow`; the generated code writes them, does not read them. Also with `ObjectCreation.Uninitialized`.
- **Computed and get-only properties** (since October 2026, docs/schema.md "Computed and get-only properties"; before: left out): `FilterNonSettable` keeps properties without any setter (`CanWrite` false; not static, not declared by a framework assembly) per its `GetOnlyProperties` flags (`Collections`: the type has Add, `GetOnlyCollection.IsFillable`; `Computed`: the others; default `All`, `None` = the old output; new constructor `FilterNonSettable(GetOnlyProperties, bool onlyPublic = true)`). Private setters are not affected (left out with `onlyPublic`). Reading is decided by the `PropertyInfo` only (`PropertyAccessor`, global): a collection is filled (`Fill`: the getter's collection cleared, then the items of the value read; `GetOnlyCollection.Fill`: IDictionary, IList, else ICollection<T> by reflection; read-only, fixed size, null getter or nil: left), any other property without a setter that no constructor takes is `Computed` (`FullPropertyInfo.IsComputed`): Core `ValueConverter` skips its value before converting (still counted as a known key), Lt `PropReader.Create` gives a `ComputedPropReader` (skips). The generator's `unrolled` (`TypeWalker.KeptByDefault`) predicts the default. A released reader throws on an object of a class whose properties were all left out before (array layout, also with the schema), and the array layout without the schema shifts positions both ways (documented).
- **Indexed schema** (`UseInexedSchema`, on by default): each `Serialize`/`Deserialize` call is a **session** with its own `IndexedSchemaTypeResolver` and a clone of the settings (`MsgPackSerializer.WithSchema`). The payload is a map `{ typeName: [propertyName, ...] }` followed by the body, in which property keys and type ids are indexes into that map. The resolver is both a type resolver and a property id resolver. Resolvers are consulted from **last to first**: the schema is added last to the type resolvers (asked first) and first to the property id resolvers (asked last, so custom property ids win). Readers look property ids up by name in the schema of the payload, so schema contents may change between versions. Reading into other classes than the writer's (`IndexedSchemaTypeResolver.BindReaderTypes`, once per root type and schema, called by both readers before the body): the root's class is the first entry, the others follow from the declared types of the writer's properties with the same names (ignoring case with `PropertyNameCaseInsensitive`); each reader class gets the writer's entry in `ByType`. Without the writer's classes (names that do not resolve: a client of a server) a v2 schema pairs them (`SchemaBytes.Parse` keeps per property the entry its type holds, `ComplexTypeDef.ValueEntries`/`ContentEntry`, and `RootEntry`; `RootDef`/`ValueDef`), v1 only the root (first entry); a type id of an unresolved entry gives the reader class paired with it (`PairedWith`). An object (with values) of a class without an entry throws (`ThrowIfNoEntry`, in `ValueConverter` before the ids are resolved, which would add an entry), until differences can be reported.
- **Schema version 2** (`MsgPackOptions.SchemaVersion = SchemaVersion.Described`, writing only; docs/schema.md "Version 2"): each property `[name, type]` or `[name, type, default]` (portable kinds `int`, `guid`, `datetime`..., an entry index, `["list", T]`...; the default of `[DefaultValue]` when `FilterDefaultValues` leaves it out), `["@", type]` first in an entry that is not an object, and a last entry `""` with `[["@", rootType]]`, for readers without the classes (JavaScript). Written by Core `Schema/DescribedSchema.cs` for both serializers (the same bytes, `CrossLibraryTests.SameBytesAndValuesDescribed`): `IndexedSchemaTypeResolver.Pack(byteOrder, root, settings)`, LtMsgPack's inline path through `DescribedInlineSchemas` (cached per root type and sequence of `SchemaTypeInfo`s). It asks the options two internal virtuals: `HasCustomExtension` and `SerializePlainValue` (the default as the body encodes it, `MsgPackSettings`/`LtMsgPackOptions` serialize it without the schema). Readers take both versions (`SchemaBytes.Parse(raw, settings, out SchemaVersion)`: v2 is recognized by the `""` entry, which is not a type, and `"@"` items are not properties; the .NET readers keep the names only). The version is hashed into the `SchemaId` (`Compute(bytes)` reads it from the bytes, writers pass it), writer sessions are keyed by it (`SessionKey`), `SessionState.Root` gives the root type when a store publishes. `SchemaBytes.Repack` converts a schema's byte order by copying every value (lengths, integers, floats, timestamps; other extensions as they are). Not negotiated over HTTP yet.
- **Cached schema** (`SchemaStore`, `Schema/`): sessions kept between calls. Writing with `WriteSchemaReference` keeps one session per root type and settings (`SchemaStore.SessionKey`: type resolvers, static filters, property id resolvers, `AddTypeIdOptions`, `EndianAction`, `PropertyOrder`, arrays compared by reference) and writes `D8 02` + a 16 byte `SchemaId` (truncated SHA-256 over a format version byte and the schema packed in the specification's byte order) instead of the schema. Reading looks the id up in the store (`SchemaProvider` or `MissingSchemaException` when missing) or, with the schema inline, recognizes the schema by its bytes (`CacheInlineSchemas`); the inline format is unchanged. A published `SchemaSession` is **frozen** (shared by threads, `settings._schemaFrozen`, `IndexedSchemaTypeResolver.IsFrozen`): a call that needs a new type, property or cache entry gets the internal `SchemaGrowthException`, then repeats the work under the state's lock with a copy (`Thaw`) that is published in its place (writing: a new schema id, appended only, so older ids stay valid). `IndexedSchemaTypeResolver.Unpack` reads the schema from the bytes (`SchemaBytes`), without `MsgPackItem`s. **Complete schemas** (`MsgPackOptions.CompleteSchemas`, part of the `SessionKey`; on in the HTTP serializer, `LtMsgPackHttpOptions.CompleteSchemas`): the first writer session of a root type (`SchemaStore.NewWriter`, also `PrepareWriter` / `LtMsgPackSerializer.PrepareSchema` / `LtMsgPackHttpSerializer.PrepareSchema` before anything is written) gets the entries of `Schema/SchemaTypes.cs` (depth first from the root, as a writer adds them: a concrete class with statically included properties, or one that gets a type id; properties, elements, dictionary keys/values, pairs, tuples, nullables; after a non-sealed class or interface the classes deriving from it in the assemblies the root reaches, by full name), so its id only depends on the types and settings (the same in every process; lsmsgpack-ts writes them for clients). Values outside it still grow the session.
- **Reporting differences** (`ReadDifferences`, Core `Differences/`, docs/ReadDifferences.md): the `Deserialize` overloads with `out ReadDifferences` (Ls static, Lt instance, `SerializerUnderTest`) count unknown properties, extra array values, unmatched classes (no schema entry: skipped and reported instead of `ThrowIfNoEntry`, now `SkipIfNoEntry`; a reader class `BindReaderTypes` found for two writer classes is remembered in `_ambiguous` and named in `Difference.WriterClasses`) and unresolved type ids (`UnresolvedTypeException`, caught in `ConvertMap`: skipped; without the schema `TypeResolver.ResolveOrReport` reads a name that is not found as the declared type, as before, and reports it; LtMsgPack's reporting path leaves such names to Core; types that are found but do not fit still throw) and values that do not convert (`InvalidValue`) per class and name. Errors (`Difference.IsError`: InvalidValue, UnmatchedClass, skipped UnresolvedType) follow `MsgPackOptions.ReadErrors` (`FailFast` default: throw; `FailDeferred`: skip, then `ReadErrorsException` from `ReadDifferences.Collect`; `ReportAndContinue`: skip; the last two collect also without the out parameter). Skippable means **marked at the origin** (`ReadDifferences.NotConverted`/`MarkNotConverted`, `ex.Data[NotConvertedKey]`, only while collecting: conversions in `ValueConverter`, Lt `Slow`, `IntegerReader` overflow, Guid strings) and caught per property (Core `ReadProperty`, Lt one handler per object in `ReadReporting`/`ReadPositionalReporting`, which rewinds to the value's start and skips it); setter/constructor exceptions, parse errors and security checks are never marked. The usual path has no exception handlers (`ConvertLeafMarked`, `SetElement` split: a handler on every value cost LsMsgPack 5%), keep up to 10 sample objects, and find their paths only in `GenerateReport`/`PathOf` (a walk from `Root` over the statically included properties). The collector is per call: `MsgPackOptions._differences` on a copy of the settings (`WithDifferences`, copied by `Clone`, so the session copies collect too), LtMsgPack `ReadContext.Differences` + `SlowSettings` copy. Core hooks: `ValueConverter.SetProperties` (`ReportUnknownKeys`, before the values) and `ConvertPositional`; the parents for unmatched classes are a stack (`Push`/`Pop`). LtMsgPack: `ObjectReader.ReadReporting`/`ReadPositionalReporting` are copies of `Read`/`ReadPositional` with the hooks, chosen by `ReadContext.Unusual` (also `SlowObjects`), so the usual loop has no checks (inline checks and a generic struct switch both measured 2-5% slower in names mode): keep the copies the same. A repeated read (`SchemaGrowthException`) calls `Reset`. Exceptions get the differences in `Exception.Data` (exception filter `AttachTo`). Nils in arrays are not counted.
- **Names of property id resolvers in the schema** (since October 2026, by the maintainer's decision: not readable by released readers with the same resolver): with the indexed schema, a string id a custom property id resolver gives (`AttributePropertyNameResolver`'s JSON names...) is the property's name in the entry (`FullPropertyInfo.SchemaName`/`SchemaNameOf`, `ComplexTypeDef.ParseProps`, `DescribedSchema.Find`) and its id is the index (`ResolvePropertyId` → `IndexedSchemaTypeResolver.IdOfSchemaName`). Readers of older data (the .NET name in the schema, the resolver's id as the key; `AttributeNamesReadReleasedSchemas` has bytes of the released packages): the id stays the string when the entry lacks it, `ValueConverter.BindOlderNames` matches the array layout by the .NET name. Two properties with the same name throw in `ParseProps`. Lt reads and writes these through Core (custom resolvers are `SlowObjects`/`IdMode.Session`).
- **Resolving the properties of a type** (`FullPropertyInfo.GetSerializedProps`): in a session, `GetStaticallyIncludedProps` creates the properties once and runs the static filters (with `PropertyId` = name), then the ids are resolved for the kept ones. `IndexedSchemaTypeResolver.GetComplex` takes the names from the same list. Without a session (no schema) the old order is kept: the id is resolved first, then the static filters.
- **Property order** (`MsgPackOptions.PropertyOrder`, `FullPropertyInfo.GetProperties(Type, MsgPackOptions)`, decided once per type): `Reflection` (default, what `Type.GetProperties()` returns, the output so far), `Alphabetical` (ordinal), `Declaration` (base classes first, then by metadata token; an override keeps the position of the property it overrides), `Explicit` (`[DataMember(Order = n)]` first, then the others in declaration order), `TypeThenDeclaration` (by `PropertyType.ToString()`, which has no assembly names, then declaration order). It orders the map entries and the names in the schema; readers look properties up by name, so any order reads with any other. Both serializers get it through `GetSerializedProps`/`GetStaticallyIncludedProps`.

## LtMsgPack

`LtMsgPack/` (assembly and package `LtMsgPack`, references only `LsMsgPack.Core`): `LtMsgPackSerializer` (instance per `LtMsgPackOptions : MsgPackOptions`, the options are copied) writes the **same bytes** as LsMsgPack with the same settings and reads the same values, 4-7x faster than Json.NET on the invoices. `CrossLibraryTests` checks bytes and read values for a corpus in all settings (EndianAction × DynamicallyCompact × names/inline/reference): run it after changing either serializer.

- **Writing**: `IO/MsgPackWriter` has LsMsgPack's encodings (MpInt with and without DynamicallyCompact, MpString, MpBin, MpFloat, MpDateTime, MpExt). `Writing/`: a typed `ValueHandler<T>` per declared type (no boxing, typed getters via `Delegate.CreateDelegate`), `ObjectPlan` per type. A value of another runtime type goes through `Serializer.WriteBoxed`, which mirrors LsMsgPack's `SerializeObject`/`SerializeCollection`/`SerializeElements` (classification in `TypeKind`, in the order of `MsgPackItem.Pack`) and uses Core's `SerializationRules`. Property and type ids (`WriteContext`): names; `IdMode.Inline` builds the schema of the call in the same order as LsMsgPack's session (`InlineSchema`: a type is added when its property ids are resolved, if it has properties, or when its type id is written; the elements of a wrapped collection come before its type id, so they are written to a rented writer first); `IdMode.Session` uses a Core `SchemaSession` (schema references via `SchemaStore.RunWriter`, or per call with custom property id resolvers or custom dynamic filters).
- **Reading**: typed `ValueReader<T>` (`Reading/`) read the formats they expect and otherwise rewind to the start of the value and read it as LsMsgPack does: `MsgPackReader.ReadPlain` (what `MsgPackItem.UnpackedValue` returns) + Core's `ValueConverter`. `ObjectReader<T>` handles maps with the type id as first key and keys by name or schema index (`BoundSchema` binds the schema's property names to the local properties), and arrays (`ObjectLayout.Array`, also wrapped as `{ "": typeId, "@": [...] }`) by position; anything else (a type id elsewhere, `"@"`, custom resolvers) takes the LsMsgPack way. Schemas read inline are cached by their bytes (the options' `SchemaStore` or a private one), with Core's `SchemaStore.Entry.RunReader`.
- **Options of other libraries** (LtMsgPack only, the defaults write what LsMsgPack writes): `GuidFormat`, `DecimalFormat`, `BigIntegerFormat` (and Core's `UnspecifiedDateTimeKind` and `DateTimeOffsetFormat`, shared), decided per type in `WriteTypeInfo` (kinds `GuidString`, `DecimalString`, `DateTimeOffsetArray`/`DateTimeOffsetMoment`, `BigIntegerBinary`, no cost per value), and the built-in `NerdbankGuidExtension`. Decimals as strings (`DecimalFormat.String`, MessagePack-CSharp's format) are formatted and parsed by `IO/DecimalText` when the mantissa fits in 64 bits (the same text as `decimal.ToString`, the same value and scale as `decimal.Parse`; anything else goes to those). `LtMsgPackPresets` combines them for MessagePack-CSharp, Nerdbank.MessagePack and generic (Python, JS...) peers: `PresetTests` in the interop project checks them against those libraries' defaults (MessagePack-CSharp: the same bytes). Documented in `docs/Compatibility.md`.
- **Differences** (documented, by design): custom property id resolvers are asked once per type (plan) in names mode, not per call; duplicate map keys: the last one wins (LsMsgPack: the first); properties are set in the order of the data (LsMsgPack: last to first); unknown extensions become `MsgPackExtension` (LsMsgPack: `MpExt`); custom extensions derive from `LtExtension<T>` (not `ICustomExt`, which creates items); no KEEPTRACK.
- netstandard2.0 build: C# 7.3 like the library, `Span` from System.Memory, `Unsafe` from System.Runtime.CompilerServices.Unsafe.

## Analyzers

`LsMsgPack.Analyzers/` (DiagnosticAnalyzer, Roslyn 4.8, netstandard2.0) and `LsMsgPack.Analyzers.CodeFixes/` (CodeFixProvider, apart because it needs Workspaces, which the command line compiler does not load: RS1038) are packed into the LsMsgPack.Core package (`analyzers/dotnet/cs`, `buildTransitive/LsMsgPack.Core.props` exposes `LsMsgPackAnalyze`). LsMsgPack and LtMsgPack reference Core, and the formatters LtMsgPack, with `PrivateAssets="none"`: otherwise NuGet writes `exclude="Build,Analyzers"` into the dependency and the analyzers (and the generator, for the formatters) do not reach the users. The repository's own projects do not run them (project references without output); to try them on a project: `-p:CustomAfterMicrosoftCommonTargets=<targets adding an Analyzer item>`. docs/Analyzers.md.

- Rules (`Rules.cs`): LSMP001 initialized property without `[DefaultValue]`, LSMP002 `[DefaultValue]` differs from what the constructor sets (also: nothing sets it), LSMP003 `[DefaultValue]` of another type (`object.Equals` never matches), LSMP004 a property declared as object / a framework interface or abstract class / an untyped collection (`OpenPart`), LSMP005 the same for reads (`Deserialize<object>`, action parameters), LSMP006 a nullable property whose `[DefaultValue]` equals its non-null initial value (null is nil in the array layout, the same as the left out `[DefaultValue]`), LSMP001/LSMP002 now only matter for maps and trimmed arrays (their messages say maps), LSMP007 reads into `object` or a string-keyed dictionary of object (`WithoutNames`: no property names in the array layout / with the schema), LSMP008 a serialized type uses a class of another assembly no analyzer checked (`OtherAssemblies`: not the framework's, LsMsgPack's or NuGet packages' (`NuGetPackageRoot`, `.nuget/packages`), only classes with settable properties; an assembly is checked when it has `[assembly: AssemblyMetadata("LsMsgPackAnalyze", "AllTypes")]`, which `buildTransitive/LsMsgPack.Core.props` writes for `LsMsgPackAnalyze=AllTypes`). `AllTypes` also runs the analyzer in a project referencing only Core. The code fix gets its text from `Diagnostic.Properties` (`Argument`, `Initializer`), computed by the analyzer; tokens are made without elastic trivia (the IDE's formatter would reformat the declaration and the usings).
- Only the serialized types (`ModelTypes`, once per compilation, when the first property is analyzed, a cancelled search is not kept): roots from serializer calls (syntactic prefilter on names, then the operation), generic wrappers of them (`Wrappers`, type parameters followed to the callers, also through interface methods), `[LtMsgPackSerializable]`, controller actions when a formatter assembly is referenced (by assembly name), the static type of the `value`/`error` argument of ASP.NET Core's `ControllerBase` result methods (`Ok(value)`, `CreatedAtAction`, `BadRequest(error)`... `ResultMethods`) and of `new ...ObjectResult(value)` (for actions returning `IActionResult`), Web API client calls; then properties, elements, generic arguments, base classes and the source classes deriving from a reached type. `LsMsgPackAnalyze=AllTypes` for projects of models. Symbol and operation actions, not compilation end actions: the IDE shows them live and offers the fixes.
- What the constructor sets (`InitialValue`): the property initializer, the initializer of the field the getter returns, the last assignment in the parameterless constructor's body; constants only, converted to the property type (`IConversionOperation`). Not for types without a parameterless constructor (created uninitialized, so a left out value stays the type's default). Empty strings are not flagged.

## TypeScript generator (lsmsgpack-ts)

`LsMsgPackTypeScript/` (net8.0 .NET tool, assembly `LsMsgPackTs`, package `LsMsgPack.TypeScript`, docs/TypeScriptModels.md): loads the user's compiled assemblies (`ModelAssemblies`, as the MCP server's read-as: deps.json and shared frameworks; LsMsgPack's assemblies stay the tool's) and writes the models file (`TypeScriptWriter`: enums as const objects, interfaces, a class per class/struct with `extends`, `declare readonly $type` (the union of the class and its derived ones), fields initialized with the constructor values (`Defaults`: created twice with a pause, differing values get the type's default and a warning; nested objects `Object.assign(new X(), {...})`), and `defineModels({...})` with the type name and the declared type of every property in the described schema's grammar with `['class', typeName]`) and the schema set (`SchemaSetWriter`: `LtMsgPackHttpSerializer.PrepareSchema(root, true)` with the server's options, base64 per root). `--property-names camelCase` (`GeneratorOptions.Field`, STJ's `JsonNamingPolicy.CamelCase`; fields, interface members, the pair type and default literals, `propertyNames` in `defineModels`, which keeps the .NET names; colliding field names are a `UsageException`). ## Source generator

`LtMsgPack.Generator/` (Roslyn 4.8 incremental generator, netstandard2.0, packed into the LtMsgPack package under `analyzers/dotnet/cs` with `buildTransitive/LtMsgPack.props`, docs/SourceGenerator.md). It writes contexts: classes with `[LtMsgPackSerializable(typeof(T))]` deriving from `LtMsgPackContext`, and the context of the assembly (`[assembly: LtMsgPackGenerate(Include = AllTypes | Serializable | DataContract | JsonSerializable)]` or the MSBuild properties `LtMsgPackGenerate`, `LtMsgPackContextName`, `LtMsgPackAutoRegister`; `GeneratedMsgPackContext` in the root namespace). `TypeWalker` collects the roots and the types they reach (property types, elements, type arguments, base classes) as equatable models, `Emitter` writes C# 7.3 (no `??=`, switch expressions, `#nullable`): `Default`, a constructor passing the contract version, `AddTypes` (`DynamicDependency` when the compilation has it), a writer/reader class per concrete class, and a `[ModuleInitializer]` (C# 9+, polyfilled attribute) calling `GeneratedTypes.Register`.

- **Contract** (`LsMsgPack.Generated` in Core, `LtMsgPack.Generated`; public, `[EditorBrowsable(Never)]`, may change between releases; version 2 (October 2026): `ReadPositional` sets a nil's value (`GeneratedCapabilities.ReadPositionalNil`, `o.X = default(T)` for members without `[DefaultValue]`, `PropReader.ReadNil` for the others), the runtime does not use version 1's `ReadPositional`, which kept the constructor's value): `GeneratedContract.MinSupported..Current` is the range of versions the runtime uses, otherwise the context is ignored (`IsUsable`); also when `AddTypes` hits missing members. Additive changes raise `Current` only (new capabilities are optional virtuals or `GeneratedCapabilities` flags whose absence means "the runtime does it"), never add abstract members to the types generated code derives from. `ContractFixtureTests` compiles the frozen output of every supported released version (`LtMsgPack.GeneratorTests/Fixtures/v*`, see its README) against the runtime; until the first release v1 may still be rewritten from the snapshot. `Emitter.ContractVersion` must equal `GeneratedContract.Current` (a test checks).
- **Contexts and the registry**: a serializer registers its contexts (constructor + options' `Contexts`) with `GeneratedTypes.Register` when `UseRegisteredContexts` is on (the default), because Core (`Instances.Create` asks the registered creator before reflection, `CollectionInfo` the registered `FromItems`) only sees the registry. Off: it neither uses nor adds to the registry, which the test adapters rely on (`TestMsgPackContext` has `AutoRegister = false` so the Ls/Lt runs keep the runtime paths): never create a serializer with `TestMsgPackContext` and the registry on in tests.
- **Tier 1** (accessors, creators, instantiations): `GeneratedValues` factories create descriptions whose subclasses `new` the generic handlers and readers (`IGeneratedInstantiations.Instantiate`), so AOT compilers see them. The runtime asks the options' `Contexts`, then the registry (`UseRegisteredContexts`), where it used reflection: `PropWriter/PropReader.Create`, `ReadPlan` creator, `Serializer.Instantiate` (replaces `MakeGenericType` in `CreateHandler`/`CreateReader`); Core's `PropertyAccessor` and `Instances` use registered ones (LsMsgPack). A generated property is used only when declaring type, name and type equal the runtime's `PropertyInfo` (stale models). Asked when plans are built, never per value.
- **Tier 2** (`GeneratedObjectCode<T>`, a generated subclass per concrete class): `GeneratedMember`s are the class's properties as `FullPropertyInfo.GetProperties` sees them (inherited ones too, in the predicted reflection order: derived class first). `Serializer.GeneratedWritePlan` maps each plan position to a member id once per plan (`-1`: the generated code would write it otherwise than these options do, e.g. `GuidFormat.String`, a custom extension, `[DefaultValue]`), not at all with custom dynamic filters or `AddTypeIdOption.Always`. `ObjectPlan` keeps headers, type ids, `BeginObject` and depth and calls `Write` (a loop with a switch over the map; keys for maps, nil for left out values in arrays, trimming) or `WriteUnrolled` (array layout untrimmed, when the map equals `UnrolledIds`). Reading: `PropReader.GeneratedId` per property (`ReadMember`), `ObjectReader.ReadPositional` calls the generated loop, the map loop `ReadValue` per value; a value in another format leaves the position and the runtime `PropReader` converts it (identical exceptions and `NotConverted` marking). The reporting paths (`Unusual`) stay runtime. Leaf kinds: string, integers, float/double, bool, char, enums, Guid, DateTime, TimeSpan, decimal (built-in extension), nullables of those; nested objects and collections go through the runtime (which uses their generated code).
- Measured (October 2026): unrolled vs a switch over the map in the prototype: write 17% slower with the switch, read 10%, one call per property 54%/26%: so the loop with a switch plus unrolled writing, reading by switch only. Invoices, JIT: write 1.6x, read 1.13-1.15x over the runtime plans (arrays); WebAssembly AOT write 7.4-8.4x, read 2.8x. Reading is dominated by UTF-8 decoding and `ToLocalTime`.
- Not covered (runtime): structs (boxed), `init`-only and non-public setters (reflection, info `LTMP004`), private types, types only met through type ids unless listed: `LTMP010` (`TypeWalker.ReportUncovered`, only reported when `PublishTrimmed`/`PublishAot`/`IsAotCompatible`/`IsTrimmable`, exposed by the props) names properties of an interface, abstract class or object type (also elements and dictionary values) that no concrete class of the context fits (object always). Generator diagnostics have external-file locations (`LocationInfo`): `#pragma` does not suppress them, `NoWarn`/`.editorconfig` severity does. - **What NativeAOT needs for collections the runtime fills** (Core `CollectionInfo`/`ValueConverter`): `TypeWalker.AddImplied` also describes the element array `T[]` (not for dictionaries filled by `Add`), the concrete class of an interface (`ConcreteOf`, mirrors `CollectionInfo.GetConcreteType`), and keeps the static factory class of immutable/frozen collections (`TypeModelKind.Factory`, a `DynamicDependency(PublicMethods)` only). Immutable/frozen collections get `GeneratedValues.Collection<T, TElement>(items => Factory.CreateRange<...>(items))` (`FactoryCall` mirrors `CollectionInfo.FindFactory`; Core `GeneratedType.FromItems`), since `MakeGenericMethod` fails for value types under NativeAOT. `CollectionInfo` finds `IDictionary<,>`/`ICollection<>` among the interfaces of the type (`FindInterface`), never with `MakeGenericType`. The smoke test (`LtMsgPackAotSmokeTest`) covers these with the `Extras` class; `run.sh` publishes with `TrimmerSingleWarn=false` and fails on any `warning IL` line. To check a context passed only to the constructor, run it once with `<LtMsgPackAutoRegister>false</LtMsgPackAutoRegister>` (the "registered" lines then pass only because the explicit runs registered it).

## Caches and their scope

| Cache | Key | Scope |
|---|---|---|
| `FullPropertyInfo.Cache` | PropertyInfo | global, only without property id resolvers. Shared by settings with different static filters, so nothing filter dependent is kept on them (`StaticallyIgnored` is only set on the instances of a session or of custom resolvers) |
| `FullPropertyInfo.SharedPropsCaches` | static filter array (by reference, `ConditionalWeakTable`), then Type, one per `PropertyOrder` | global, only without property id resolvers and without a session. The settings remember the cache of their array (`_sharedPropsCache`). Replace the filter array to change filters, an array changed in place keeps its results (like `SchemaStore.SessionKey`). `StaticPerOrder` (same keys) keeps what the static filters keep with the name as id for `GetStaticallyIncludedProps`: each session gets copies (it sets its ids on them), so the filters run once per type, not per call |
| `FullPropertyInfo.OrderedPropertiesCache` | Type, one per `PropertyOrder` (not `Reflection`) | global, static metadata |
| `FullPropertyInfo.AttributesCache`, `GetProperties` cache | PropertyInfo / Type | global, static metadata |
| `MsgPackOptions._serializedPropsCache`, `_staticPropsCache` | Type | one session (set by `WithSchema` or `SchemaSession.Apply`, not copied by `Clone()`/`CloneOptions()`). Property ids are schema indexes, never share them between sessions. With the schema as the only property id resolver, `IndexedSchemaTypeResolver.TryAssignIds` gives each property its position when the entry has the same names in the same order (made from these properties, or the writer had the same ones), without the name lookups |
| `ComplexTypeDef.ByPosition` | the session's property array (by reference) | one schema entry: the reader's properties at the positions of the entry (`ValueConverter.PropertiesByPosition`, array layout), one immutable reference (frozen entries are read by several threads) |
| `SchemaStore` schemas, inline schemas, writer and reader sessions | `SchemaId` / schema bytes / `SessionKey` | one store (shared by the settings that use it). Received schemas limited by `MaxSchemas`, sessions frozen once published |
| `PropertyAccessor.Cache` | PropertyInfo | global. Reflection for the first 100 calls, then typed delegates (`Delegate.CreateDelegate` into `TypedAccessor<TTarget, TValue>`), unless the runtime does not support dynamic code (NativeAOT) or `MsgPackOptions.CompilePropertyAccessors` is off |
| `CollectionInfo`, `ObjectConstructor` (parameterless constructor, constructor taking the values), `FilterDefaultValues.DefaultInstances`, `SerializationRules.HasAnonymousType` | Type | global |
| `TypeResolver` name caches | name / Type | global, guarded by one (re-entrant) lock |

Custom property id resolvers without the schema are consulted on every call (by design, they may have their own cache).

## Invariants and gotchas

- **Keep the output stable.** Performance changes must not change the bytes or the round trip results: verify with the `lsmsgpack-perf` skill (A/B equivalence and benchmark against master).
- **Leaf items write themselves** through `WriteTo` only when `GetType() == typeof(ThatType)`, because a subclass (e.g. a user's custom extension) may override `ToBytes`, which must still be used. `ToBytes` and `WriteTo` share one private writer per type, so they cannot drift apart.
- **Property ids must be unique per type** and must not be `""` or `"@"`: `FullPropertyInfo.ThrowIfIdsNotUnique` checks this once per type, the map entries are then collected in arrays without checks.
- **Exceptions of property getters/setters** are rethrown as they are (not as `TargetInvocationException`), whether the accessor still uses reflection or a bound delegate.
- The parameterless `MsgPackItem()` constructor allocates a new `MsgPackSettings` (50-70 ns). Use the constructors taking the settings in hot paths (see `AbstractCustomExt.CreateNew`).
- **Culture-sensitive string APIs are slow on Linux** (ICU): always pass `StringComparison.Ordinal` (`EndsWith`, `StartsWith`, `IndexOf(string)`, `Compare`).
- Reading from a `Stream`: use `ReadExactly` and `ReadByteExactly` (`MsgPackItem`), `Stream.Read` may return fewer bytes than asked (network streams). Data that ends early throws "Unexpected end of data." like LtMsgPack (LsMsgPack used to read the missing bytes as zeros: `cd 01` became 256). Lengths and counts from headers are checked against the rest of the data before anything is allocated for them (`MsgPackVarLen.SlotsFor` and `ReadBytes`, LtMsgPack `MsgPackReader.Count`; only when `CanSeek`): KEEPTRACK allocates the slots the data can fill and reads up to its end (the explorers show truncated data), without it the reader throws.
- Endianness: MsgPack is big-endian, `EndianAction` can override it. `ByteWriter.WriteEndian` writes the same bytes as `BitConverter.GetBytes` followed by `SwapEndianChoice`.
- `DateTime` values are returned as local time by default, MsgPack timestamps do not keep the `DateTimeKind`: compare with `ToUniversalTime()` in tests. `MsgPackOptions.ReadDateTimeKind` (Local, Utc, Unspecified = the UTC clock time; `MsgPackOptions.FromTimestamp`, used by `MpDateTime.Value` and LtMsgPack's `MsgPackReader.TryReadDateTime`/`ReadPlain`; `TryReadTimestamp` is UTC) and `UnspecifiedDateTimeKind` (Unspecified written as Local or Utc, `ToTimestamp`) are shared by both serializers; `Utc` + `Unspecified` round trips an Unspecified clock time in any time zone. A `DateTimeOffset` read from a timestamp gets the local offset for Local, zero otherwise (`OffsetOfTimestamp`). `DateTimeOffset` is written as `MsgPackOptions.DateTimeOffsetFormat` says (shared, moved from LtMsgPack): `TimestampAndOffset` (default, `[the moment as a timestamp, offset minutes as a short]`, Nerdbank's bytes), `Timestamp` (the moment, the offset is lost: the format before October 2026) or `ClockTimeAndOffset` (MessagePack-CSharp). The arrays look the same, readers take them as the option says (`OffsetOfArray`, Core `TryConvertItems`, Lt `DateTimeOffsetReader`/`DateTimeOffsetArrayReader`) and a bare timestamp in any format. Timestamps before 1970 round the seconds down, the nanoseconds are always added (`MpDateTime.DateTimeToEpoch`), as the spec requires.
- **Values read into other types** (`ValueConverter.ConvertScalar`, as the JSON serializers read the text): into `string` numbers (invariant), `true`/`false`, timestamps (ISO 8601), bin 16 as a Guid, other bins as base64; strings into Guids and enums (by name, ignoring case). Number map keys become string keys, except with the indexed schema (`ConvertKey` throws: the keys of an object are indexes, indistinguishable from a dictionary's numbers), and an array that is not `[key, value]` pairs read into a dictionary throws a `MsgPackException` (no names). An object read untyped (`object`, `Dictionary<string, object>`) only has names with `ObjectLayout.Map` without the schema.
- Reading maps uses `MapConversionEqualityComparer`: numbers are equal across types (`(byte)3` equals the property id `(int)3`), strings and integers take a fast path.
- **Type injection** (docs/security.md): a type picked by the data (type id, schema name, custom resolver) must be assignable to the declared type, checked in `TypeResolver.Resolve` (Core, so both serializers) before the instance is created; names with `,` `[` `]` `&` `*` are refused in `TypeResolver.ResolveName` (`Type.GetType` would load the named assembly). Framework assemblies (`TypeResolver.IsFrameworkAssembly`) only offer their public types (`IsVisible`, `TypeResolver.Visible`, also when caching an assembly): `Complex` used to resolve to an internal CoreLib struct. `NativeAssemblies` (searched for names) has the collection assemblies, System.Runtime.Numerics and System.Collections.Immutable when it can be loaded. The optional `MsgPackOptions.TypeGuard` (`IMsgPackTypeGuard`, `AllowedTypesGuard`) is asked only when the picked type differs from the declared one: in `TypeResolver.Resolve` and in LtMsgPack's `ObjectReader` fast path (which does not go through `Resolve`). A new place that creates instances of a type from the data must do the same checks (`TypeInjectionTests`).
- **Type names are short by default**, so the classes of an assembly that is searched for types need unique names: two test classes both called `Assorted` (nested in different test classes) make deserializing either of them throw "Type assignment dilamma" where both fit (`TypeResolver.Pick` keeps the concrete candidates assignable to the declared type, a name that fits one is not cached). Give test classes unique names.
- Every `Deserialize` registers the assemblies the root type reaches (`TypeResolver.CacheReachableAssemblies`: generic arguments, element types, base types, public property types, not framework assemblies; once per root type), so `Deserialize<List<T>>` finds `T`. Types that are not reachable (implementations in other assemblies, values declared as `object`) still need `MsgPackTypes.CacheAssemblyTypes(typeof(T))` (Core; `MsgPackSerializer`/`LtMsgPackSerializer.CacheAssemblyTypes` delegate), or an `AllowedTypesGuard` that allows them (`AllowAssembly` registers the assembly, `Allow` the type alone: `TypeResolver.CacheType`). docs/schema.md (polymorphic class-hierarchy support) explains the lookup order to users. The names of a schema are resolved when it is read without throwing: an entry whose name was not resolved is found by the name of the type that is read (`IndexedSchemaTypeResolver.TryGetDef`) or resolved with the declared type when a type id needs it (then it throws "Unable to resolve type").
- `Type.GetProperties()` without binding flags also returns **public static properties**: `FilterStatic` (in `Default_StaticFilters`) leaves them out, so the data cannot set shared state. Static filters set without it still serialize (and set) settable static properties.
- **`MsgPackOptions.ObjectCreation`** (Core `Instances`, LtMsgPack `ReadPlan.Creator`): `Constructor`, `ConstructorOrUninitialized` (default), `Uninitialized`. Constructor exceptions are passed on as they are (`Activator`'s and `new T()`'s `TargetInvocationException` unwrapped), an uninitialized object always gets `GC.SuppressFinalize` (finalizers of never constructed objects can end the process, see docs/security.md; a mode keeping them was dropped: not faster). Weak references are never created uninitialized (the GC crashes on them, `SuppressFinalize` or not). Collections and dictionaries always use their constructor (`Instances.CreateCollection`). Uninitialized creation costs ~55 ns on .NET 8 (compiled `new T()` ~12 ns, `MemberwiseClone` of a prototype ~51 ns): not a speed option on .NET (Core). On .NET Framework (netstandard2.0 build: no compiled constructor calls, `Activator` is slow) `Uninitialized` can be faster, not measured (documented as such). A `FastFactory<T>` (static readonly `Expression`-compiled `Func<T>`) was tried: 10-12 ns like LtMsgPack's `DynamicMethod` creator, but 63 µs to compile per type (`DynamicMethod` 2.2 µs); for LsMsgPack (a `Type`, so a dictionary lookup per call) 20.5 ns against 22 ns for `Activator`: not adopted.
- **`MsgPackOptions.MaxDepth`** (256, shared by both serializers): reading refuses arrays and maps nested deeper (LsMsgPack: `MsgPackItem.Unpack` passes the depth to `MpArray`/`MpMap.Read` via `_depth`, the exception is marked in `Exception.Data` so the levels above do not wrap it; under KEEPTRACK it becomes an `MpError`), writing refuses deeper objects and collections (cycles; LsMsgPack: the `depth` parameter of `SerializeObject`). Without it, deep data ended in a stack overflow, which ends the process.

## Performance

The baseline is **System.Text.Json** (default options, as ASP.NET Core uses it), since October 2026; Json.NET is about half as fast. Numbers from the `BenchmarkInvoices` test (100 invoices × 20 rounds, Release, i7-7700K, one run, speed relative to System.Text.Json; STJ source generation writes 1.33x and reads 1.0x):
- **LtMsgPack with the source generator** (arrays): write 5.6x (indexed) / 6.4x (reference) / 6.3x (no schema), read 5.2-5.8x (see docs/SourceGenerator.md).
- **LtMsgPack**: write 3.1x (indexed) / 3.5x (reference) / 2.9x (names), read 4.2x / 4.4x / 3.8x. `ObjectLayout.Array` (the default): write 3.7x (indexed) / 4.0x (reference) / 4.2x (no schema), read 4.7-4.9x. Payload 65-69% (indexed), 53-57% (reference), 95% (names). A single `Address` (per call cost): 0.18 µs write and 0.23 µs read (System.Text.Json 0.38 / 0.60 µs).
- **LsMsgPack**: write 0.33x (indexed) / 0.38x (reference) / 0.36x (names), read 0.40x / 0.49x / 0.41x (inline schema with a store 0.48x). `ObjectLayout.Array` (the default): write 0.37x (indexed), read 0.54x. Without a `SchemaStore` each call builds its schema session: the static filter results are cached globally and copied, the ids assigned by position (round of October 2026: -25% writing, -20% reading with the indexed schema).
- End to end in ASP.NET Core (TestServer, one invoice per request): the msgpack formatters take ~21 µs per GET and ~34 µs per POST, System.Text.Json ~40 µs / ~52 µs. The framework is most of it.

What the LtMsgPack round of October 2026 found with `perf` (do not undo): `UTF8Encoding.GetBytes` costs 10-15 ns per call (strings up to 16 chars are written by a loop, longer ones in one pass with the header moved when needed; on .NET 8 see the round below), `Buffer.BlockCopy` checks types (span copies for keys), `decimal != 0m` is a call (`DecimalHandler.IsZero`), `new T()` of a class is `Activator.CreateInstance` (compiled after 100 calls), and per call: the inline schema is recognized by comparing its bytes with the last one (`SchemaHit`), the published session's settings and binding are shared (`SessionShared`, LtMsgPack does not change settings during a call), the plans remember their last session binding / ids, `TypeResolver.CacheAssembly` checks lock-free first. The formatters read the request body from the pipe in place (.NET 8).

The round of October 21, 2026 (strings, the same bytes and values; A/B with `lt/bench.sh`): reading checks ASCII with `Ascii.IsValid` and decodes it with `Encoding.Latin1` (net8.0 only; `UTF8Encoding.GetString` validates in a second pass: reads 12-16% faster, one `Address` 25%), writing narrows ASCII with `Ascii.FromUtf16` from 9 chars on (net8.0; non-ASCII text continues with the encoder from the first such char, the header stays where it was reserved) and up to 8 chars as two overlapping blocks of 4 or 2 chars (`ShortAscii`, little-endian; the loop otherwise), and throws with formatted messages are in helpers so `EnterContainer`, `ThrowIfUnresolvableAsArray`/`WithSchema` and `MsgPackReader.Count` inline (generator write -11%, runtime write -7%).

Ideas not done yet:
- The remaining time of LsMsgPack is the `MsgPackItem` tree (building it, and converting it back to objects). LtMsgPack does without it.
- LtMsgPack reading: `DateTime` values cost ~5% in `ToLocalTime` (needed: LsMsgPack returns local time; a cache by hour or by value would have to reproduce the offset and the ambiguous-DST bit exactly, not done). Writing: the virtual calls per property (`PropWriter` → `ValueHandler`).
- Reading: `ConvertMap` builds a dictionary per object to look up property ids, with the schema the keys are indexes that could address an array directly. Every value still becomes an `MsgPackItem` and then a boxed value.

Profiling on Linux: see the `lsmsgpack-perf` skill. `perf` works with `DOTNET_PerfMapEnabled=1` **and** `DOTNET_EnableWriteXorExecute=0` (otherwise the JIT code is double mapped and has no symbols), and needs `kernel.perf_event_paranoid` ≤ 1 (only the user can lower it). `dotnet-trace` stacks were unreliable.
