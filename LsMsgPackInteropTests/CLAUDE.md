# Interop tests

Checks what MessagePack-CSharp and Nerdbank.MessagePack read of LsMsgPack's output and the other way around (the invoice model with property names, byte equality per type, and the known differences: Guid, decimal, `DateTimeKind.Unspecified`, `DateTimeOffset`, polymorphism, omitted defaults, the indexed schema). `PresetTests` checks `LtMsgPackPresets` against those libraries' defaults (MessagePack-CSharp: the same bytes), `IgnoreAttributeTests` the `Like<Library>` presets of `FilterIgnoredAttribute`.

- A format change can make these fail: update the test when the change is intended, and mention it.
- `docs/Compatibility.md` documents the settings per library (from these tests): keep it in sync.
- `BenchmarkLibraries` (`TestCategory=Benchmark`, run with `--logger "console;verbosity=detailed"`) times the three libraries in their fastest setups (MessagePack-CSharp's source-generated formatters, asserted to exist; PolyType's generated shapes; LtMsgPack with and without `TestMsgPackContext`) and asserts that the `MessagePackCSharp()` preset rows write MessagePack-CSharp's bytes. `docs/Comparison.md` has a run: update its tables when the numbers change noticeably. The other models are filled by a reflection copy, not through JSON (Json.NET changes decimal scales, the bytes then differ).
- `BenchmarkGame` (same category and setups): the messages of a 16 player game (`PlayerState` with `Vec3` struct properties, `WorldSnapshot` of 15 states), ns and allocations per message, written to a new `byte[]` and to a reused buffer; the schema reference rows import the writer's store once (a handshake). The `Vec3 class` rows show LtMsgPack without its boxed struct path. `docs/Comparison.md` ("Game messages") has a run. Velocities at rest are `default(Vec3)`: `sin * 0` can be -0.0, which the default value filter leaves out (read back as 0.0).
- The shared test classes and adapters work as in the unit tests (see `../LsMsgPackNetStandardUnitTests/CLAUDE.md`); this project adds the Nerdbank Guid to `LtSerializer.ExtensionEquivalents`.
