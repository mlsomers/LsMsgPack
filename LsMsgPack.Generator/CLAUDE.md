# Source generator

`LsMsgPack.Generator/`: Roslyn 4.8 incremental generator, netstandard2.0, packed into the LsMsgPack package under `analyzers/dotnet/cs` with `buildTransitive/LsMsgPack.props`, docs/SourceGenerator.md. Tests: `LsMsgPack.GeneratorTests` (snapshots, C# 7.3/.NET Standard 2.0 compile, diagnostics, contract fixtures), `LsMsgPackAotSmokeTest/run.sh`.

It writes contexts: classes with `[LsMsgPackSerializable(typeof(T))]` deriving from `LsMsgPackContext`, and the context of the assembly (`[assembly: LsMsgPackGenerate(Include = AllTypes | Serializable | DataContract | JsonSerializable)]` or the MSBuild properties `LsMsgPackGenerate`, `LsMsgPackContextName`, `LsMsgPackAutoRegister`; `GeneratedMsgPackContext` in the root namespace). `TypeWalker` collects the roots and the types they reach (property types, elements, type arguments, base classes) as equatable models, `Emitter` writes C# 7.3 (no `??=`, switch expressions, `#nullable`): `Default`, a constructor passing the contract version, `AddTypes` (`DynamicDependency` when the compilation has it) listing the types by number and `Describe(int)` with a nested class `LsMsgPackType{n}` per type (see Cold start), a writer/reader class per concrete class, and a `[ModuleInitializer]` (C# 9+, polyfilled attribute) calling `GeneratedTypes.Register`.

- **Contract** (`LsMsgPack.Generated` in Core, `LsMsgPack.Generated`; public, `[EditorBrowsable(Never)]`, may change between releases; version 2: `ReadPositional` sets a nil's value (`GeneratedCapabilities.ReadPositionalNil`, `o.X = default(T)` for members without `[DefaultValue]`, `PropReader.ReadNil` for the others); version 3: structs, see below; `ReadMap`; `Describe`; sets, dictionaries and collection interfaces, see below; version 4: fields, see below; `WriteUnrolledMap`, `WriteUnrolledTrimmed`, `WriteFormats`; version 5: maps keyed by names read straight-line, see Reading below (`GeneratedIO.NamesInOrder`, `KeyIs`, `LongKeyIs`)): `GeneratedContract.MinSupported..Current` is the range of versions the runtime uses, otherwise the context is ignored (`IsUsable`); also when `AddTypes` hits missing members. Additive changes raise `Current` only (new capabilities are optional virtuals or `GeneratedCapabilities` flags whose absence means "the runtime does it"), never add abstract members to the types generated code derives from. `ContractFixtureTests` compiles the frozen output of every supported released version (`LsMsgPack.GeneratorTests/Fixtures/v*`, see its README) against the runtime. It compiles all versions first and registers their types (`MsgPackTypes.CacheAssemblyTypes`): the process-wide short-name cache (`TypeResolver.UsedNameCache`) is filled when a name has one class, so with v3 and v4 both declaring `Shop.Money` the second would read the schema's `Money` as the first's struct; with all registered the name is ambiguous and the readers pair the entries by the class read. `Fixtures/v4` is the invoice model with a public field (`Address.PostalCode`), a struct field by reference (`Money.Precision`) and a private `[DataMember]` field (`InvoiceLine`, UnsafeAccessor). `Fixtures/v5` is the same model (the snapshot's context without its header line). `Emitter.ContractVersion` must equal `GeneratedContract.Current` (a test checks).
- **Contexts and the registry**: a serializer registers its contexts (constructor + options' `Contexts`) with `GeneratedTypes.Register` when `UseRegisteredContexts` is on (the default), because Core (`Instances.Create` asks the registered creator before reflection, `CollectionInfo` the registered `FromItems`) only sees the registry. Off: it neither uses nor adds to the registry, which the test adapters rely on (`TestMsgPackContext` has `AutoRegister = false` so the Debug and Ls test runs keep the runtime paths): never create a serializer with `TestMsgPackContext` and the registry on in tests.
- **Tier 1** (accessors, creators, instantiations): `GeneratedValues` factories create descriptions whose subclasses `new` the generic handlers and readers (`IGeneratedInstantiations.Instantiate`), so AOT compilers see them. The runtime asks the options' `Contexts`, then the registry, where it used reflection: `PropWriter/PropReader.Create`, `ReadPlan` creator, `Serializer.Instantiate` (replaces `MakeGenericType` in `CreateHandler`/`CreateReader`); Core's `PropertyAccessor` and `Instances` use registered ones (LsMsgPackDebug). A generated property is used only when declaring type, name and type equal the runtime's `PropertyInfo` (stale models). Asked when plans are built, never per value.
- **Tier 2** (`GeneratedObjectCode<T>`, a generated subclass per concrete class): `GeneratedMember`s are the class's properties as `FullPropertyInfo.GetProperties` sees them (inherited ones too, in the predicted reflection order: derived class first). `Serializer.GeneratedWritePlan` maps each plan position to a member id once per plan (`-1`: the generated code would write it otherwise than these options do, e.g. a custom extension, `[DefaultValue]`; `GuidFormat.String`/`DecimalFormat.String` only for code without `GeneratedCapabilities.WriteFormats`), not at all with custom dynamic filters or `AddTypeIdOption.Always`. Members of `GeneratedKind.None` with an accessible getter are read by the generated code and go to the runtime's handler of their type through `GeneratedWritePlan.Value<T>` (what `PropWriter.Write` does after its getter, handler per position made at the first value: no getter delegate and no virtual call; with the other changes of that round a game state 19% faster on .NET 8, 9% on .NET 10, a snapshot 20% / 5%, with names 25% / 19%); `Runtime` remains for inaccessible getters, positions without a member and the code of older versions. `ObjectPlan` keeps headers, type ids, `BeginObject` and depth and calls `Write` (a loop with a switch over the map; keys for maps, nil for left out values in arrays, trimming), `WriteUnrolled` (array layout untrimmed, when the map equals `UnrolledIds`), `WriteUnrolledTrimmed` (array layout with `TrimTrailingNulls`, when the map equals `UnrolledIds`: `GeneratedWritePlan.UnrolledTrimmed`, chosen in `WriteBoxed` for classes, in `WriteStructTrimmed` for structs; marks the last value that is not nil where the code writes one, the runtime's writers (`Value<T>`/`Runtime`) by the byte check of `Write`'s loop; returns the count, `end` the position after it) or `WriteUnrolledMap` (maps, also a collection's with `SerializeProperties`, when the map equals `UnrolledIds`: `GeneratedWritePlan.UnrolledMap`, `GeneratedCapabilities.WriteUnrolledMap`; returns the count; for classes chosen in `WriteBoxed`, see `../LsMsgPack/CLAUDE.md`). Reading: `PropReader.GeneratedId` per property (`ReadMember`), `ObjectReader.ReadPositional` and `ReadGeneratedMap`/`ReadByRef` call the generated loops `ReadPositional` and `ReadMap` (the keys through `GeneratedIO.TryReadKey`; `ReadValue` per value is only for the code of versions 1 and 2). Maps keyed by names (version 5): `ReadMap` first calls `ReadNames` when `GeneratedIO.NamesInOrder(c, plan)` returns the plan's properties (`ReadPlan.NamesInOrder`: they are `UnrolledIds` in that order, `Serializer.InUnrolledOrder`; not with the indexed schema or `PropertyNameCaseInsensitive`): straight-line, position i reads the next entry when its key is member `UnrolledIds[i]`'s name with the smallest string header (`Emitter.Key`), compared by `GeneratedIO.KeyIs` with the little-endian words as constants (`Emitter.Word`, the same as `CompiledReader.Word`; keys over 32 bytes `LongKeyIs` with a `static readonly byte[]`), the value read inline when `prop.GeneratedId` is that member (otherwise the runtime's `PropReader`); it returns the position after the last property read, and the loop reads the entries left from there (another order, unknown keys, other headers). By parts of 16 members for wide classes (`ReadNamesPart{n}`, `NoInlining`), as the unrolled writers. The same code as the runtime's compiled readers (`CompiledReader.Names`); the keys are always the members' .NET names (`FullPropertyInfo.Name`), so constants are safe once the order is checked; a value in another format leaves the position and the runtime `PropReader` converts it (identical exceptions and `NotConverted` marking). The reporting paths (`Unusual`) stay runtime. Leaf kinds: string, integers, float/double, bool, char, enums, Guid, DateTime, TimeSpan, decimal (built-in extension), nullables of those; nested objects and collections go through the runtime (which uses their generated code). Immutable classes (constructor taking the values) are written, not read.
- **The runtime writes the same code** (`LsMsgPack/Writing/CompiledWriter.cs`, see `../LsMsgPack/CLAUDE.md`): `CompiledObjectCode<T>`/`CompiledStructCode<T>` implement `Write`/`WriteUnrolled`/`WriteUnrolledMap` of this contract (their `Write` of a trimmed array is already straight-line, so no `WriteUnrolledTrimmed`; the formats are constants of the plan) with expression trees per plan, mirroring `Emitter.Omitted`/`WriteValue`. A change to how the generated writers write a kind (or to `GeneratedWritePlan`/`GeneratedIO`) goes into both; `CompiledWriterTests` and the corpus of `CrossLibraryTests` ("Compiled") check the runtime's. It reads with the same code too (`LsMsgPack/Reading/CompiledReader.cs`, mirroring `Emitter.ReadValue`, `Fast` and `Ranged`: arrays straight-line per plan, maps with the indexed schema by the loop with a switch; `CompiledReaderTests`): a change to how the generated readers read a kind (or to `GeneratedReadPlan`/`GeneratedIO`'s reading) goes into both as well.
- **Non-public properties**: `GenerateOptions.NonPublic` (`[LsMsgPackGenerate(NonPublicProperties)]`, MSBuild `LsMsgPackNonPublicProperties`, default `Attributed`; the declared contexts are combined with the options for it), `TypeWalker.IsNonPublicCandidate`/`OptsIn` mirror Core, members after the public ones (never `Unrolled`), inaccessible accessors of covered properties through `[UnsafeAccessor]` (`GenerateOptions.UnsafeAccessors`, `Emitter.Accessors`; not generic or virtual: reflection), `TypeModel.KeepNonPublic` adds `NonPublicProperties` to the `DynamicDependency`. The unit test assembly's context is generated with `All`. Computed properties: `TypeWalker.KeptByDefault` and its own `IsNeverWritten` predict Core's default.
- **Fields** (contract version 4; docs/SourceGenerator.md): no new contract API, a field is a `GeneratedValues.Property`/`StructProperty` like a property (a type cannot declare a property and a field of one name), found by `GeneratedType.FindMember(MemberInfo)` (declaring type, name and `FullPropertyInfo.TypeOf`; `GeneratedTypes.FindMember`), which Core `PropertyAccessor(FieldInfo)`, LsMsgPack `PropWriter.CreateForField`/`PropReader.CreateForField` (not for readonly) and `RowMapper.Setter` ask first. `GenerateOptions.Fields` (`[LsMsgPackGenerate(Fields)]` wins over the MSBuild property `LsMsgPackFields`, declared in **Core's** `buildTransitive/LsMsgPack.Core.props` so the analyzers read the same; `ParseFields`; default `Attributed`) must equal the runtime's `SerializedFields`. `TypeWalker.IsFieldCandidate`/`IsFieldOfState` mirror `FullPropertyInfo.IsFieldCandidate` (not static, const, implicitly declared or `AssociatedSymbol` backing fields, `<` and VB's `$` names, `[CompilerGenerated]`, fixed buffers, pointer/ref struct types, event fields of other assemblies), `IsFieldStruct` mirrors `SerializationRules.IsFieldStruct` (a framework struct with a public mutable instance field, not a tuple/`KeyValuePair`/`Nullable`): described as `TypeModelKind.Struct` with its public fields only, kept for NativeAOT, `DefaultCheck` = `default(T).Equals(v)` when it has `IEquatable<T>` (as `StructDefault.TypedEquals`). `GetMembers(type, fieldStruct)` collects the candidates in 4 passes (public properties, non-public properties, public fields, non-public fields; each class's own first) and only then drops every candidate whose name a candidate of a more derived class has, whatever the kind (as `FindMembers`). `Unrolled` of a field = `KeptByDefault(field)`: opted in (or field struct), not ignored (`[NonSerialized]` too), readonly only when not `IsNeverWritten` (a readonly field has no setter described). Emitter: a field's UnsafeAccessor is `[UnsafeAccessor(UnsafeAccessorKind.Field, Name = "_x")] static extern ref T LsMsgPackFieldN(D o)` (`ref D o` for structs), one per field for both get and set (the `ref` return does both), not for generic declaring types (needs .NET 9): reflection. `DynamicDependency`: `PublicFields` whenever the type declares a public instance field (as for public properties: a runtime with `SerializedFields.Public` still finds them when trimmed, the smoke test's "public-fields" run checks it), `NonPublicFields` when it declares a described non-public candidate (`Kept`, `TypeModel.KeepPublicFields`/`KeepNonPublicFields`). `MemberModel.Inherited`: an inherited member is accessed as `((Base)o).X`, since `o.X` binds to a member of the same name declared by the derived class (a public field hiding a base property the runtime does not serialize, a compile error). Tests: `GeneratedFieldsTests.Members_AsTheRuntimeSeesThem` (members = `FullPropertyInfo.GetMembers`, same order), the generator tests `Fields_*`, `ParseFields`, `FieldStructs_DescribedByTheirFields`.
- **A method with the code of every property only once per object**: its frame is zeroed per call and grows with the class (814 bytes for 114 properties). `ReadValue`, called per value, made reading maps slower than the runtime on wide classes (real SDK models of 70-190 properties, `Generic()` preset: reading 0.94-1.55x the time of the runtime; 0.75-0.96x with `ReadMap`), which the invoices of 10-15 properties did not show. Benchmark wide classes too, and keep `ObjectReader.Read` small: the `ReadMap` call inlined there cost the runtime's maps 2-5%.
- **Cold start**: a context is listed at first (`GeneratedTypeSet.Add(Type, int)`, a `typeof` per type) and each type described on its first lookup (`GeneratedContext.TryGetType`, `Describe`; old code adds descriptions, which still works). Each type has its own class so its lambdas are in a closure class of their own: one class with the lambdas of all types has to be loaded whole. 86 types with 1060 properties: load 191 -> 2.8 ms, first write of a small class 215 -> 30 ms (without generated code 28 ms), of a class of 190 properties 260 -> 110 ms (68 ms: its big methods are JIT compiled at tier 0).
- **Debug builds**: generated code is in the user's assembly, so `Optimize=false` means unoptimized, while the library's package is optimized: the generated code is then slower than the runtime plans (1.2-1.9x). Reported as info `LSMP111` (once per compilation with a context), not avoided: skipping the generated code in Debug would run other code than Release. Measure in Release.
- Measured: unrolled vs a switch over the map: write 17% slower with the switch, read 10%, one call per property 54%/26%: so the loop with a switch plus unrolled writing (arrays and maps), reading by switch only.
- **Unrolled maps** (`WriteUnrolledMap`, A/B on .NET 8): the invoices with the generated code, maps write 4.58-4.63 -> 3.62-3.66 ms (indexed) and 4.34-4.39 -> 3.54-3.58 ms (names), 9-10% faster than the compiled writers (which the generated code keeps, PGO profiles it); game states with names 246-268 -> 210-222 ns, snapshots 3.35-3.44 -> 2.77-3.07 µs; arrays and the runtime's plans unchanged.
- **Formats of other libraries** (`GeneratedCapabilities.WriteFormats`, version 4): `GeneratedWritePlan.GuidString`/`DecimalString`, `Fits` takes `TypeKind.GuidString`/`DecimalString` for the code that has the flag. Reading: `GeneratedCapabilities.ReadFormats` (version 4), `GeneratedReadPlan.GuidString`/`DecimalString`, the generated readers call `GeneratedIO.TryReadGuid(r, p, ...)`/`TryReadDecimal(r, p, ...)`: bin 16 or the built-in extension first, the strings only on a miss (no test per value in the default formats; `DecimalStringReader` reads the extension in place too, so `ReadMember` takes decimals as strings only with the built-in extension), the texts `GuidText`/`DecimalText` parse, anything else left to the runtime's reader. `Generic()` preset, class of 120 properties, read: 2562-2687 -> 2068-2113 ns (all values 3095 -> 2521). A type with `Guid` or `decimal` members gets a second copy of each unrolled writer (`WriteUnrolledFormats`, `WriteUnrolledMapFormats`, `WriteUnrolledTrimmedFormats`, with their parts) that tests the formats per value, from locals read once per call (`FormatLocals`); the overrides write the binary formats and call the copy when `p.GuidString || p.DecimalString`. A test per value in the one writer made the invoices 2% slower (arrays without the schema 2.40-2.43 -> 2.45-2.51 ms, also with locals or the branch written out), with the copies they are the same as before. `Write`'s loop tests per value (it is not the fast path). `GeneratedIO.GuidString`/`DecimalString` call `MsgPackWriter`'s, which are `NoInlining` (a `stackalloc` inlined into a writer gives the whole method a larger frame and a stack cookie).
- **Wide classes: parts and shared locals** (`Emitter.UnrolledPart`, `ValueLocals`). With tiered PGO the JIT inlines the writers' calls of the first ~22 members of a method and then stops (its inline budget; Tier1 listing of a class of 120 properties: getters, `Nullable.HasValue`, `DateTime.Ticks`, `GeneratedIO.Utc` became calls), so the unrolled writers of more than 16 members call `...Part{n}` methods of 16 members each (`NoInlining`; 8 or 24 measured the same). A class of 120 leaf properties (map with names, FilterDefaultValues): 1560-1630 -> 980-1030 ns (compiled writers 1050-1110); arrays 785-801 -> 576-607 ns (compiled 560-626). Each writer declares one local per value type, shared by its members (as the compiled writers): a block-scoped local per member is an IL local of its own (137 in that class); no measurable effect alone, kept so the JIT's locals stay few. Tried: `AggressiveOptimization` on the writers (no PGO: the wide class as fast as the compiled writers, but invoice arrays 3-5% slower), parts of `Write`'s switch (a call per value for the members past the first 16: trimmed arrays of the wide class 1340 -> 1630 ns). `Write`'s loop is 1.7x slower than the compiled writers on such a class (orders other than the predicted one): with a JIT the plan compiles a writer after `CompileWritersAfter` objects written by the loop (see `../LsMsgPack/CLAUDE.md`, Compiled writers); NativeAOT and WebAssembly keep the loop. A class of 120 properties (12 each of string, int, long, double, bool, DateTime, int?, enum, Guid, decimal; A/B on .NET 8): trimmed arrays 1339-1363 -> 605-618 ns with `WriteUnrolledTrimmed` (compiled writers 707-716 -> 600-628 ns, marking the known nils too), the `Generic()` preset 2149-2181 -> 1289-1296 ns with `WriteFormats` (all values 2159-2174 -> 1435-1442; compiled writers 1532-1534 -> 1316-1395), then 1084-1091 ns with Guids formatted as UTF-8 in place (`MsgPackWriter.GuidString`, net8.0). Invoices, JIT: write 1.6x, read 1.13-1.15x over the runtime plans (arrays); WebAssembly AOT write 7.4-8.4x, read 2.8x. Reading is dominated by UTF-8 decoding and `ToLocalTime`.
- **Structs** (`TypeModelKind.Struct`, roots of `AllTypes`/`Serializable`/`DataContract` too; not ref structs): `GeneratedValues.Struct<T>(creator, code, StructProperty<T, V>(name, (ref T o) => o.X, (ref T o, V v) => o.X = v)...)` (Core `StructGetter`/`StructSetter`, `GeneratedStructProperty`: LsMsgPackDebug's `PropertyAccessor` gets boxed accessors that work on the box through `Unsafe.Unbox`; explicitly typed `ref` lambdas, C# 7.3 infers no ref parameters). The creator only for a declared parameterless constructor (`HasCreator`), otherwise `StructCreator<T>` (what `ReadPlan.ByRef` recognizes). `GeneratedStructType<T>` (`IGeneratedStruct`: `Serializer.StructPlans` also without dynamic code) instantiates `ObjectHandler`/`ObjectReader`/`StructComputedPropReader`. Tier 2: `GeneratedStructCode<T>` (no struct constraint, so the plans generic over any T call it with `Unsafe.As`; its boxed overrides unbox through `StructUnboxer<T>`, which `GeneratedValues.Struct` sets) is the same code with `ref T o`; the runtime's members through `GeneratedWritePlan.Runtime<T>(..., ref o, ...)` and `GeneratedIO.Read`/`ReadNil(prop, ref o)` (by reference when the prop is `ByRef`, otherwise a copy in a box); `ObjectPlan.WriteStruct`/`ObjectReader.ReadByRef`/`ReadPositionalByRef` call it (see `../LsMsgPack/CLAUDE.md`). UnsafeAccessors of a struct take it by `ref`. `IsDefault` (`GeneratedCapabilities.IsDefault`, `TypeModel.IsDefault`, `TypeWalker.DefaultCheck`): the default check of `FilterDefaultValues` as `StructDefault` compiles it (fields of auto-properties and accessible fields against their defaults, nested structs, typed `Equals` of record structs and of framework types with `IEquatable<T>`), only for source structs where every field is readable (the struct's own private fields and private auto-property getters through UnsafeAccessors: placeholders `\u0001n\u0001` in `TypeModel.IsDefault`, the accessors in `TypeModel.DefaultAccessors` which the emitter writes; a readonly private field is read through a `ref` field accessor, which works on .NET 10; otherwise null: the runtime compares, boxed without dynamic code, which allocated 128 B per write of the smoke test's route); `ObjectHandler` uses it instead of `StructDefault` (`LsStructTests.DefaultCheck_Generated_SameAsValueTypeEquals`). `init` properties of structs (record structs) go through by-reference UnsafeAccessors like the others (without UnsafeAccessor: reflection, `LSMP104`, a box).
- **`init`-only setters**: `o.X = v` only compiles in an object initializer, so accessible ones go through `[UnsafeAccessor]` too, whatever `GenerateOptions.NonPublic` says, since the runtime sets them with every option (`TypeWalker.CanSet`; `CanUseAccessor` has the limits both share). UnsafeAccessor ignores the setter's `modreq(IsExternalInit)`. The cost was only where delegates can't be bound (NativeAOT): with the JIT, the runtime already binds a typed delegate to them. Objects created by a constructor taking the values never call the generated code (`ReadPlan.WithValues`).
- Not covered (runtime): `init`-only and non-public setters the UnsafeAccessor can't call (before .NET 8, generic classes, virtual properties) and non-public setters `NonPublic` doesn't cover (reflection, info `LSMP104`), private types, types only met through type ids unless listed: `LSMP110` (`TypeWalker.ReportUncovered`, only reported when `PublishTrimmed`/`PublishAot`/`IsAotCompatible`/`IsTrimmable`, exposed by the props) names properties of an interface, abstract class or object type (also elements and dictionary values) that no concrete class of the context fits (object always). Generator diagnostics have external-file locations (`LocationInfo`): `#pragma` does not suppress them, `NoWarn`/`.editorconfig` severity does.
- **What NativeAOT needs for collections the runtime fills** (Core `CollectionInfo`/`ValueConverter`): `TypeWalker.AddImplied` also describes the element array `T[]` (not for dictionaries filled by `Add`), the concrete class of an interface (`ConcreteOf`, mirrors `CollectionInfo.GetConcreteType`), and keeps the static factory class of immutable/frozen collections (`TypeModelKind.Factory`, a `DynamicDependency(PublicMethods)` only). Immutable/frozen collections get `GeneratedValues.Collection<T, TElement>(items => Factory.CreateRange<...>(items))` (`FactoryCall` mirrors `CollectionInfo.FindFactory`; Core `GeneratedType.FromItems`), since `MakeGenericMethod` fails for value types under NativeAOT. `CollectionInfo` finds `IDictionary<,>`/`ICollection<>` among the interfaces of the type (`FindInterface`), never with `MakeGenericType`. The smoke test (`LsMsgPackAotSmokeTest`) covers these with the `Extras` class; `run.sh` publishes with `TrimmerSingleWarn=false` and fails on any `warning IL` line (gcc via `-p:CppCompilerAndLinker=gcc` when clang is missing). To check a context passed only to the constructor, run it once with `<LsMsgPackAutoRegister>false</LsMsgPackAutoRegister>` (the "registered" lines then pass only because the explicit runs registered it).
- **Sets, dictionaries, collection interfaces** (contract version 3): exact `HashSet<T>` and `Dictionary<TKey, TValue>` are `GeneratedValues.HashSet`/`Dictionary` (`TypeModelKind.HashSet`, `Dictionary`), a generic interface whose `ConcreteOf` is a `List<T>`, `HashSet<T>` or `Dictionary<TKey, TValue>` is `GeneratedValues.CollectionInterface` (the concrete class is described by `AddImplied`), so NativeAOT has the typed handlers and readers (`Serializer.InstantiateCollection`, `InterfaceReader`). Code of older versions describes them with `Collection<T>`: typed with dynamic code, boxed without. NativeAOT, dynamic code off (20 entries, or 1000 for the set, read): `Dictionary<string, int>` 3.9 -> 1.2 µs, `Dictionary<int, object>` 9.7 -> 2.0 µs, `HashSet<int>` 82 -> 16 µs, `IList<object>` 8.7 -> 1.7 µs; writing 1.3-4.6x. Core's `CollectionInfo.GetConcreteType` tries its candidates one at a time for the same reason (an `IList<struct>` has no `HashSet<struct>` there).
- **ShouldSerialize methods** (`FilterShouldSerialize` finds them by name): `TypeWalker.ShouldSerializeMethods` lists the public parameterless `bool ShouldSerialize*()` methods a described class or struct declares (`TypeModel.KeptMethods`), the emitter keeps each with `[DynamicDependency("ShouldSerializeX()", typeof(T))]` on `AddTypes`; the runtime decides which members they belong to. Test `ShouldSerializeMethods_Kept`; not in the NativeAOT smoke test yet.
- WebAssembly: the `wasm-tools` workload is only in the user-local SDK `~/.dotnet/dotnet` (10.0.x), not in the system SDKs.
