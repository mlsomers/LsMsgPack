# ObjectDebugger

netstandard2.0, KeepTrack configurations like the library. Used by all three UIs (MsgPackExplorer `MsgPackExplorer.Objects.cs`, the VS Code inspector, the MCP server): they run both validations and reuse the reconstruction for the objects pane.

- **Reconstruction**: rebuilds the object tree of a payload without its types (`RootObject.Reconstruct(MpRoot, SchemaStore)`). With schema version 2 (`SchemaInfo.Version`, `RootType`, `SchemaType.PropertyTypes`/`PropertyDefaults`/`ContentType`, `DeclaredType`) the declared types are used instead of inferring (members get `DeclaredType`/`DeclaredTypeText`, and `DefaultText` for a nil that was left out); `SchemaType.Describe` writes the properties with their types for the UIs. Otherwise untyped values with a schema are inferred in `ObjectReconstructor` (schema order = first occurrence depth first, shape, slots, kinds), marked `TypeIsGuess`. The slots of an array or map that an error cut off (KEEPTRACK allocates what the data could fill) are `Node.Unread`: the inference skips their keys and values but counts them for the length the header claims. A DateTimeOffset (`[timestamp, offset]`) fits a type with two properties: `RootObject.RetryWithValues` tries the places where one introduced a type (`Suspects`) as values when values later contradict a type (`Unexplained`), and keeps the attempt with the fewest.
- `ObjectAssessment` decides when the explorers open the objects pane by themselves (`ObjectConfidence`: Certain for a schema or type ids, High for maps with the same identifier-like keys, Medium for one such map with values of different kinds, Low for text keys; the explorers use High, VS Code setting `lsmsgpack.showObjectsAt`).
- **Search** (`ItemSearch`): strings containing the text and values it converts to; it only walks into arrays and maps under KEEPTRACK.
- **Validation beyond single items** (`PayloadValidation`, KEEPTRACK, on the reconstructed `RootObject`; LsMsgPack's `MsgPackValidation` validates single items): the schema, type ids, shapes of framework types with a type id, and `ValidationSeverity.SecurityVulnerability` for places declared as object (a type id on a wrapped scalar or a framework type, values of different kinds in a property of an object with a type id or a dictionary with string keys; not inferred types, the inference may be wrong), refused type names and known gadget names (distinctive names only: type names are short).
- **Streams** (`ReadStreams`): `SplitPayloads` leaves out `MpStreamIndex`/`MpStreamTail`/`MpStreamSidecar` (`IsStreamPart`), `Reconstruct(item, store, data)` registers each inline schema of the data in a store of the call (`KeepInline`, sets `SchemaInfo.Id`) so later references (`PerStream`) find it, a payload gets the index entry starting at its offset (`RootObject.Entry`, `EntryText`), `ItemSearch` walks the index's `Content`. The hosts pass the data, show the index's content by field name and the chunks (role `chunk`), and skip validating chunks and the tail's elements (fixed types).
- Tests: `ObjectDebuggerTests`, `ValidationTests` (KEEPTRACK only: the test project defines it in the KeepTrack configurations).
