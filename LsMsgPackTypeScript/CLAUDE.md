# lsmsgpack-ts (TypeScript model generator)

net8.0 .NET tool, assembly `LsMsgPackTs`, package `LsMsgPack.TypeScript`, docs/TypeScriptModels.md. Generators write models only, never endpoints or API descriptions (x-lsmsgpack is a wire format under an existing API, not an API description).

- Loads the user's compiled assemblies (`ModelAssemblies`, as the MCP server's read-as: deps.json and shared frameworks; LsMsgPackDebug's assemblies stay the tool's) and writes the models file (`TypeScriptWriter`: enums as const objects, interfaces, a class per class/struct with `extends`, `declare readonly $type` (the union of the class and its derived ones), fields initialized with the constructor values (`Defaults`: created twice with a pause, differing values get the type's default and a warning; nested objects `Object.assign(new X(), {...})`), and `defineModels({...})` with the type name and the declared type of every property in the described schema's grammar with `['class', typeName]`) and the schema set (`SchemaSetWriter`: `LsMsgPackHttpSerializer.PrepareSchema(root, true)` with the server's options, base64 per root).
- `--property-names camelCase` (default) or `dotnet` (`GeneratorOptions.Field`, STJ's `JsonNamingPolicy.CamelCase`): fields, interface members, the pair type and default literals; `propertyNames` is always written in `defineModels` (a file without it reads as `'dotnet'`), which keeps the .NET names; colliding field names are a `UsageException`. With the options' `PropertyNamingPolicy` the list has the written names (`ModelProperty.WrittenName`, Core's `FullPropertyInfo.WrittenName`) and the fields are named from them (`Name` stays the .NET name: the key of the initial values); enums by `EnumNames.Of(type, settings)` (`EnumNamingPolicy`). Test `NamingPoliciesOfTheOptions`.
- Roots: `--root`, `[LsMsgPackSerializable]`, `--solution` (MSBuildWorkspace 5.6, the last version with a net8.0 build, + `LsMsgPack.Analyzers` `ModelTypes.FindUses`, symbols mapped to runtime types by metadata name; results unwrapped from Task/ActionResult, `IAsyncEnumerable<T>` to `List<T>`: `SolutionRoots.Unwrap`), `--all-types`.
- `ModelSet` walks like Core's `SchemaTypes` (the same kinds as `DescribedSchema.WriteType`, `SpecOf`) but keeps abstract classes, interfaces and enums, only of the user's assemblies. TypeScript types follow `NullabilityInfoContext` (without annotations: properties nullable, elements not). Core and the analyzers give it their internals (`InternalsVisibleTo("LsMsgPackTs")`).
- Converters: `ModelSet.Visit`/`SpecOf` follow the surrogate of `MsgPackOptions.ConverterFor` (the attribute's, and the options' when `--options` gives the server's: `Clone` keeps them; test `ConvertersOfTheOptionsAreTheirSurrogates`); a converted reference type keeps its nulls when the surrogate is a struct (`Spec.FromReference`: `number | null` for a class converted to `double`, by the same nullability rules as a reference type), `Defaults.Value` converts a default value with `ToSurrogateBoxed`; a member's own converter: `ModelProperty.Converter`, `ModelSet.SpecOf(ModelProperty)` (`['?', surrogate]` for a nullable member), `Defaults.Surrogate`; a binary converter is `bin`, with an extension code `any` (`SurrogateSpec`). Test `ConvertedTypesAreTheirSurrogates`.
- F# unions (docs/FSharp.md): `VisitCases` visits the case classes (closed generic ones too, which the candidates scan misses), `WithUnionCases` gives a spec of a union its fieldless case names (`Spec.CaseNames`: `Shape | 'Empty'`) and, for a union whose own values are names (the converter's `string`), the classes of its cases with fields (`Spec.CaseClasses`: `'A' | 'B' | E`); `TypeScriptWriter.CaseNamesType`. Only the TS types change, not `defineModels`. Two unions with a case of the same name give `Ok` and `Ok_2` with one type name: the client keys models by type name (open). An F# library's own bin has no FSharp.Core.dll (its types fail to load): the test passes the copy in its own output. Test `FSharpTypesAsTheServerWritesThem`.
- The client side (`defineModels`) is in `clients/typescript/src/models.ts`: keep the grammar in sync. Tests: `LsMsgPackTypeScriptTests` (models, defaults, schema ids equal the server's, `--solution`).
