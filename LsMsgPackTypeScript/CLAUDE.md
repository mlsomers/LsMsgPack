# lsmsgpack-ts (TypeScript model generator)

net8.0 .NET tool, assembly `LsMsgPackTs`, package `LsMsgPack.TypeScript`, docs/TypeScriptModels.md. Generators write models only, never endpoints or API descriptions (x-lsmsgpack is a wire format under an existing API, not an API description).

- Loads the user's compiled assemblies (`ModelAssemblies`, as the MCP server's read-as: deps.json and shared frameworks; LsMsgPackDebug's assemblies stay the tool's) and writes the models file (`TypeScriptWriter`: enums as const objects, interfaces, a class per class/struct with `extends`, `declare readonly $type` (the union of the class and its derived ones), fields initialized with the constructor values (`Defaults`: created twice with a pause, differing values get the type's default and a warning; nested objects `Object.assign(new X(), {...})`), and `defineModels({...})` with the type name and the declared type of every property in the described schema's grammar with `['class', typeName]`) and the schema set (`SchemaSetWriter`: `LsMsgPackHttpSerializer.PrepareSchema(root, true)` with the server's options, base64 per root).
- `--property-names camelCase` (default) or `dotnet` (`GeneratorOptions.Field`, STJ's `JsonNamingPolicy.CamelCase`): fields, interface members, the pair type and default literals; `propertyNames` is always written in `defineModels` (a file without it reads as `'dotnet'`), which keeps the .NET names; colliding field names are a `UsageException`.
- Roots: `--root`, `[LsMsgPackSerializable]`, `--solution` (MSBuildWorkspace 5.6, the last version with a net8.0 build, + `LsMsgPack.Analyzers` `ModelTypes.FindUses`, symbols mapped to runtime types by metadata name; results unwrapped from Task/ActionResult, `IAsyncEnumerable<T>` to `List<T>`: `SolutionRoots.Unwrap`), `--all-types`.
- `ModelSet` walks like Core's `SchemaTypes` (the same kinds as `DescribedSchema.WriteType`, `SpecOf`) but keeps abstract classes, interfaces and enums, only of the user's assemblies. TypeScript types follow `NullabilityInfoContext` (without annotations: properties nullable, elements not). Core and the analyzers give it their internals (`InternalsVisibleTo("LsMsgPackTs")`).
- The client side (`defineModels`) is in `clients/typescript/src/models.ts`: keep the grammar in sync. Tests: `LsMsgPackTypeScriptTests` (models, defaults, schema ids equal the server's, `--solution`).
