# Analyzers

`LsMsgPack.Analyzers/` (DiagnosticAnalyzer, Roslyn 4.8, netstandard2.0) and `LsMsgPack.Analyzers.CodeFixes/` (CodeFixProvider, apart because it needs Workspaces, which the command line compiler does not load: RS1038) are packed into the LsMsgPack.Core package (`analyzers/dotnet/cs`, `buildTransitive/LsMsgPack.Core.props` exposes `LsMsgPackAnalyze`). LsMsgPackDebug and LsMsgPack reference Core, and the formatters LsMsgPack, with `PrivateAssets="none"`: otherwise NuGet writes `exclude="Build,Analyzers"` into the dependency and the analyzers (and the generator, for the formatters) do not reach the users. The repository's own projects do not run them (project references without output); to try them on a project: `-p:CustomAfterMicrosoftCommonTargets=<targets adding an Analyzer item>`. docs/Analyzers.md. Tests: `LsMsgPack.AnalyzerTests` (source text against the libraries, the ASP.NET Core formatters and the HttpClient package).

- Rules (`Rules.cs`): LSMP001 initialized property without `[DefaultValue]`, LSMP002 `[DefaultValue]` differs from what the constructor sets (also: nothing sets it), LSMP003 `[DefaultValue]` of another type (`object.Equals` never matches), LSMP004 a property declared as object / a framework interface or abstract class / an untyped collection (`OpenPart`), LSMP005 the same for reads (`Deserialize<object>`, action parameters), LSMP006 a nullable property whose `[DefaultValue]` equals its non-null initial value (null is nil in the array layout, the same as the left out `[DefaultValue]`); LSMP001/LSMP002 only matter for maps and trimmed arrays (their messages say maps). LSMP007 reads into `object` or a string-keyed dictionary of object (`WithoutNames`: no property names in the array layout / with the schema). LSMP008 a serialized type uses a class of another assembly no analyzer checked (`OtherAssemblies`: not the framework's, LsMsgPack's or NuGet packages' (`NuGetPackageRoot`, `.nuget/packages`), only classes with settable properties; an assembly is checked when it has `[assembly: AssemblyMetadata("LsMsgPackAnalyze", "AllTypes")]`, which `buildTransitive/LsMsgPack.Core.props` writes for `LsMsgPackAnalyze=AllTypes`). LSMP009 a JSON document type (`JsonPart`: `JsonElement`, `JsonDocument`, `JsonNode` and Json.NET's `JToken`, with their subclasses, also as an element or generic argument; properties including get-only ones, and the uses of calls and actions both ways; the serializers refuse System.Text.Json's (`ThrowIfUnsupportedFrameworkType`; `JsonObject`/`JsonArray` are collections, see Core's CLAUDE.md), Json.NET's are written as their own properties and read back empty; `JsonNode` is left out of LSMP004). `AllTypes` also runs the analyzer in a project referencing only Core. LSMP010 a public field the default `SerializedFields.Attributed` leaves out (see Fields below).
- **Fields** (`Fields.cs`, mirrors Core's `FullPropertyInfo.IsFieldCandidate`/`PropertyAttributeSet.OptsIn` and the generator's `TypeWalker.IsFieldCandidate`/`OptsIn`: keep the three equal; `FieldTests.SameFieldsAsTheRuntime` compares with what the runtime writes per mode). The mode is the runtime's static filters, invisible here: `Fields.ModeOf` reads `[assembly: LsMsgPackGenerate(Fields = ...)]` (wins) or the MSBuild property `LsMsgPackFields` (Core's `buildTransitive` props, shared with the generator), `Attributed` by default. A serialized field (`AnalyzeField`, symbol action on fields) goes through the property rules (`AnalyzeMember`: readonly = no setter, only LSMP009), `ModelTypes` follows the types of serialized fields, `ValuesConstructor` binds parameters to public fields too (as `ObjectConstructor`, whatever the mode), `OtherAssemblies` counts public mutable fields as settable state. LSMP010 only in `Attributed`, not for ignored fields (`IsIgnored`, also `[NonSerialized]`), types that mark their members (`[DataContract]`, `[MessagePackObject]` with keys), fields whose opting in would not round trip (`WouldRoundTrip`: never-written and JSON document types; readonly ones only when fillable or taken by the values constructor). Field declarations of several variables share their attributes: no attribute fix there (`sharedAttributes`), the initializer fix is per variable.
- The code fixes: `DefaultValueCodeFix` (LSMP001-003, properties and fields) gets its text from `Diagnostic.Properties` (`Argument`, `Initializer`), computed by the analyzer; `FieldCodeFix` (LSMP010: add `[DataMember]`, make it an auto-property, `field:` target for attributes not allowed on properties, not for `volatile`). Tokens are made without elastic trivia (the IDE's formatter would reformat the declaration and the usings).
- Only the serialized types (`ModelTypes`, once per compilation, when the first property is analyzed, a cancelled search is not kept): roots from serializer calls (syntactic prefilter on names, then the operation), generic wrappers of them (`Wrappers`, type parameters followed to the callers, also through interface methods), `[LsMsgPackSerializable]`, controller actions when a formatter assembly is referenced (by assembly name), the static type of the `value`/`error` argument of ASP.NET Core's `ControllerBase` result methods (`Ok(value)`, `CreatedAtAction`, `BadRequest(error)`... `ResultMethods`) and of `new ...ObjectResult(value)`, minimal APIs (`MsgPackResults.MsgPack(value)`/`Results.Extensions.MsgPack(value)`: the type argument, the value's static type when object; `MsgPackBody<T>` (reads) and `MsgPackResult<T>` (writes) wherever a `GenericNameSyntax` names them, `FromTypeName`, also a syntax node action for the live diagnostics), Web API client calls (`ReadAsAsync`, `ObjectContent`, and the package's `MsgPackHttpClientExtensions`/`MsgPackStreamExtensions`); then properties, elements, generic arguments, base classes and the source classes deriving from a reached type. `LsMsgPackAnalyze=AllTypes` for projects of models. Symbol and operation actions, not compilation end actions: the IDE shows them live and offers the fixes. lsmsgpack-ts uses `ModelTypes.FindUses` for `--solution`.
- What the constructor sets (`InitialValue`): the property initializer, the initializer of the field the getter returns, the last assignment in the body of the parameterless constructor or of the one taking the values (`ValuesConstructor`, keep it equal to Core's `ObjectConstructor`; its parameters' properties are not checked: they get the value the writer leaves out); constants only, converted to the property type (`IConversionOperation`). Not for types created uninitialized (no parameterless constructor and none taking the values). Empty strings are not flagged.
