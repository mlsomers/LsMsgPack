# LsMsgPack.SignalR

Package `LsMsgPack.SignalR` (netstandard2.0 + net8.0, on `Microsoft.AspNetCore.SignalR.Common` 8.x, not the shared framework: the .NET client of non-web apps needs it too): an `IHubProtocol` on LsMsgPack. Gaps checklist item 10 (`~/GitRepositories/LsMsgPack-Gaps/CHECKLIST.md`: the maintainer's decisions). Tests `LsMsgPack.SignalRTests`; the TypeScript side is `clients/typescript/src/signalr.ts` (`@lsmsgpack/client/signalr`, test-server `TestHub.cs`).

- **The envelope is Microsoft's MessagePack protocol** for both names (`HubFrame` writes, `HubEnvelope` reads: the same fields, smallest encodings, checks and error texts as `MessagePackHubProtocolWorker` of release/8.0). "messagepack" (`AsMessagePack`) must keep writing the bytes of Microsoft's `MessagePackHubProtocol`: `ProtocolTests.AsMessagePack_WritesTheBytesOfMicrosoftsProtocol` compares every message type, the live tests run Microsoft's .NET and JS clients against it.
- **Values**: written as their runtime type with the public `Serialize(object, Type, IBufferWriter)` into the frame (`HubFrame` is the `IBufferWriter`, one per thread; the first 5 bytes are left free for the VarInt length, written in front at the end: no copy); read in place with the internal `Serializer.Deserialize(type, buf, pos, end, out consumed)` (`InternalsVisibleTo("LsMsgPack.SignalR")` in `LsMsgPack/AssemblyInfo.cs`, so the package depends on exactly its LsMsgPack version). No indexed schema or schema references, forced on a copy of the options: SignalR serializes a message once for all the connections of a group (`SerializedHubMessage`).
- **Defaults** (`LsMsgPackHubProtocolOptions.DefaultSerializerOptions`): "lsmsgpack" = `LsMsgPackPresets.LsMsgPack()` with maps, every value written (no dynamic filters: JS gets complete objects without a schema), Guids as text; "messagepack" = `MessagePackCSharp()` + `EnumFormat.Name` (SignalR's resolver: DynamicEnumAsStringResolver, ContractlessStandardResolver). Both `PropertyNameCaseInsensitive`. Limits as the HTTP options (`MaxObjects`/`MaxItems`/..., replacing the serializer options' values).
- **Registration** (`LsMsgPackProtocolDependencyInjectionExtensions`, namespace `Microsoft.Extensions.DependencyInjection` like `AddMessagePackProtocol`): named options per protocol name, `TryAddEnumerable` with a factory; the "messagepack" registration has its own type (`MessagePackNamedProtocol`) so both can be added. Overloads with an `LsMsgPackContext` carry no trim annotations (AOT).
- Binding failures as Microsoft's (`InvocationBindingFailureMessage`, `StreamBindingFailureMessage`, a completion with an error for a result of the wrong type, an unknown invocation's result skipped), `RawResult` kept as a copy of its bytes and written back raw, an unknown message type returns false (ignored).
- NativeAOT: `LsMsgPackAotSmokeTest` writes an invocation with its invoice for both names (`hub-lsmsgpack`, `hub-messagepack` in golden.txt; "messagepack" without the invoice's shapes: no type ids, an abstract class can't be read) and checks the generated code's bytes and values; `LsMsgPackAotReflectionTest` the same without the generator (the protocol constructors without a context keep `Serializer.ReflectionInstantiations` on net8.0 only: the .NET Standard build has no `DynamicDependency` it can see).
- Docs: docs/SignalR.md, Wizard/Setup-SignalR.md; the debuggers' side (`HubCapture`, `MpHub*` items) is in `../LsMsgPackDebug/CLAUDE.md`.
- Benchmark: `ProtocolBenchmark` (`TestCategory=Benchmark`, Release); numbers in the checklist. It warms up with a tenth of the calls and runs all protocols in one process: on master (612192f) a scratch harness with 2 s of warm-up per case read the small message in 506-516 ns where the checklist has 688 ns; after the round of 2026-11-21 this benchmark shows 487 ns. Where a read goes (round of 2026-11-21, see `../LsMsgPack/CLAUDE.md`): the serializer most of it, the envelope (frame, headers, target, arguments, the message) ~80 ns, each argument its own `Deserialize` call (an `int` ~30 ns; the alternating root types cost nothing measurable). The test binder has no `GetTarget`, so the benchmark decodes the target to a string, SignalR's binders do not.
