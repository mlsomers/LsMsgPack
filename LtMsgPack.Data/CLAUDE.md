# LtMsgPack.Data

Add-on package for ADO.NET data readers (docs/DataReader.md), apart from LtMsgPack so applications without databases don't carry it. It uses the internals of LtMsgPack and Core (`InternalsVisibleTo("LtMsgPack.Data")` in `LtMsgPack/AssemblyInfo.cs` and Core `Meta/AssemblyInfo.cs`), so the package depends on exactly its LtMsgPack version (`[x.y.z]`, target `ExactProjectReferenceVersions` in the csproj; check with `dotnet pack` and the nuspec). Tests and benchmark: `LtMsgPack.DataTests` (Dapper and Microsoft.Data.Sqlite as test dependencies only).

- **Rows** (`RowPlan`, one per column set, the last one kept per serializer in `DataCache`, a `ConditionalWeakTable` keyed by LtMsgPack's `Serializer`): a `ColumnWriter<T>` per column (the IDataRecord typed getter, `DbDataReader.GetFieldValue<T>` for other types, boxed `GetValue` when the generic code can't be made), written with the serializer's `ValueHandler<T>`, so the format options apply. Value-type columns are written as `Nullable` properties: only DBNull is nil or left out, a 0 stays a 0. The first row decides the field types (SQLite gives the current row's); a reader without rows still gets its columns (`FieldType` falls back to object). Names must be unique, not empty or `"@"`. The schema: v1 `{ typeName: [names] }`, v2 `DescribedSchema.WriteColumns` (value types as `["?", T]`, root `["list", 0]`), in the options' byte order (`PayloadSchema`) and the spec's (`CanonicalSchema`, for the store).
- **Streams** (`StreamWriterDataExtensions`, `TableWriter`): per result set an index entry when the writer keeps one (`BeginEntry(identifier, MsgPackDataStreams.ContentType)`, metadata `"columns"` = `[[name, type FullName, data type name]]`, `PointColumn` → `AddPoint(ColumnTypes.PlainKey(value))` where the value changes), `MsgPackStreamWriter.WriteHead(CanonicalSchema, version)`, `WriteArrayStart`, each row through `BeginValue`/`EndValue` (rolled back on an exception), `WriteEnd`. `WriteResultSets` skips result sets without columns. Async: `ReadAsync` + `FlushIfFullAsync` per row.
- **`MsgPackDataReader`** (`DbDataReader`): `ReadHead(typeof(object))`, the columns from `TryGetHeadSchema` (parsed as plain values: the root entry `""` of v2 says which entry the rows have, otherwise the first), types from the entry's metadata (`ColumnTypes.FromName`, a fixed list of framework types: the data never picks a type), else the v2 kinds (`FromKind`), else object; rows read whole with `GetValue` (arrays by position, maps by position or name) and converted to the column types by `ValueConverter`. Sequential (`NextResult` skips the rest of a table with `Skip`) or at an entry (`Seek`, one table). Async variants mirror the sync ones.
- **`RowSerializer`** (`SerializeRows`): one payload, the bytes of `Serialize(List<T>)` (rows buffered for the header; inline schema or, with `WriteSchemaReference`, `SchemaStore.AddWritten` + the reference). No custom dynamic filters.
- **`RowMapper<T>`** (`ReadRows`/`EnumerateRows`): the `ReadPlan`'s properties and creator; columns matched by `[Column]` (by class name) or the property id, then ignoring case, then ignoring underscores; `[NotMapped]` skipped; typed getter + setter (generated or bound delegate) when the column has the property's type, or when the property type's getter reads the first row (SQLite converts); otherwise `GetValue` + `ValueConverter`; DBNull leaves the constructor value. Classes created by their constructor (`ReadPlan.WithValues`): boxed values into `ObjectConstructor.Arguments`, then `Create`.
- Measured (`BenchmarkRows`, Release, i7-7700K, 10 000 invoice rows): in memory `ReadRows` 237 ns/row vs Dapper 412, `WriteTable` 356 ns (25 B/row) vs Dapper + `Serialize` 847; SQLite native types `ReadRows` 2568 vs Dapper 2898 (SQLite's `IsDBNull` ~65 ns per column is most of the difference to a hand-written loop). Ideas not done: skipping `IsDBNull` for NOT NULL columns (`GetSchemaTable`'s `AllowDBNull`), `GetChars`/`GetBytes` chunks (`WriteStringStart`) for large values with `CommandBehavior.SequentialAccess`.
