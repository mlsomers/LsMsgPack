# LtMsgPack.Data

Add-on package for ADO.NET data readers (docs/DataReader.md), apart from LtMsgPack so applications without databases don't carry it. It uses the internals of LtMsgPack and Core (`InternalsVisibleTo("LtMsgPack.Data")` in `LtMsgPack/AssemblyInfo.cs` and Core `Meta/AssemblyInfo.cs`), so the package depends on exactly its LtMsgPack version (`[x.y.z]`, target `ExactProjectReferenceVersions` in the csproj; check with `dotnet pack` and the nuspec). Tests and benchmark: `LtMsgPack.DataTests` (Dapper and Microsoft.Data.Sqlite as test dependencies only).

- **Rows** (`RowPlan`, one per column set, the last one kept per serializer in `DataCache`, a `ConditionalWeakTable` keyed by LtMsgPack's `Serializer`): a `ColumnWriter<T>` per column (the IDataRecord typed getter, `DbDataReader.GetFieldValue<T>` for other types; `BoxedColumnWriter<T>` with `GetValue` for object and byte[], and when the generic code can't be made: DBNull is the NULL, no IsDBNull), written with the serializer's `ValueHandler<T>`, so the format options apply. Value-type columns are written as `Nullable` properties: only DBNull is nil or left out, a 0 stays a 0. The first row decides the field types (SQLite gives the current row's); a reader without rows still gets its columns (`FieldType` falls back to object). Names must be unique, not empty or `"@"`. The schema: v1 `{ typeName: [names] }`, v2 `DescribedSchema.WriteColumns` (value types as `["?", T]`, root `["list", 0]`), in the options' byte order (`PayloadSchema`) and the spec's (`CanonicalSchema`, for the store).
- **Streams** (`StreamWriterDataExtensions`, `TableWriter`): per result set an index entry when the writer keeps one (`BeginEntry(identifier, MsgPackDataStreams.ContentType)`, metadata `"columns"` = `[[name, type FullName, data type name]]`, `PointColumn` → `AddPoint(ColumnTypes.PlainKey(value))` where the value changes), `MsgPackStreamWriter.WriteHead(CanonicalSchema, version)`, `WriteArrayStart`, each row through `BeginValue`/`EndValue` (rolled back on an exception), `WriteEnd`. `WriteResultSets` skips result sets without columns. Async: `ReadAsync` + `FlushIfFullAsync` per row.
- **`MsgPackDataReader`** (`DbDataReader`): `ReadHead(typeof(object))`, the columns from `TryGetHeadSchema` (parsed as plain values: the root entry `""` of v2 says which entry the rows have, otherwise the first), types from the entry's metadata (`ColumnTypes.FromName`, a fixed list of framework types: the data never picks a type), else the v2 kinds (`FromKind`), else object. Rows typed (`ColumnValues.cs`): per table a `ColumnValue<T>` per column with the serializer's `ValueReader<T>` (a fixed list of types, no `MakeGenericType`; object columns `ReadPlain`), the row framed whole by the stream reader (`GetWhole`; async: `BufferCurrentAsync` first), then each column read from the bytes with a private `ReadContext` (leaf readers only use `R`, `SlowSettings` and `Depth` 1, so a value that does not convert throws as the serializer's conversion does, not `RootValue`); arrays by position, maps by position or name, nil (a row or a value) is NULL (`IsNull`). Typed getters: `column is ColumnValue<T>`, otherwise the boxed value through `ValueConverter`. Sequential (`NextResult` skips the rest of a table with `Skip`) or at an entry (`Seek`, one table). Async variants mirror the sync ones.
- **NULL checks** (`NullChecks`, in the column writers and the mapper's typed setters): the first `CheckedRows` (64) rows of a call check every column with IsDBNull; then, when the reader's type is known to throw for a NULL in its typed getters (`CanSkip`, learned by `Learn` at the first NULL a check finds: the getter is called once on it), a column without a NULL so far (`_hadNull`, per plan/mapper, only set to true) is read with the getter alone, in a separate method with the try block (`WriteUnchecked`/`SetUnchecked`: keeps the checked path as it was, an `out` local there cost 10-20 ns per row); an exception whose `IsDBNull` is true (exception filter) is the NULL and sets `_hadNull`. Not `GetSchemaTable`'s `AllowDBNull`: ~10 ms per query on SQLite, and NOT NULL for the outer side of a LEFT JOIN (`NullChecksTests`). A reader whose getters return a value for a NULL (the tests' `ColumnarReader`; `ThrowingColumnarReader` throws, a type of its own because the knowledge is per reader type) is always checked.
- **`RowSerializer`** (`SerializeRows`): one payload, the bytes of `Serialize(List<T>)` (rows buffered for the header; inline schema or, with `WriteSchemaReference`, `SchemaStore.AddWritten` + the reference). No custom dynamic filters.
- **`RowMapper<T>`** (`ReadRows`/`EnumerateRows`): the `ReadPlan`'s properties and creator; columns matched by `[Column]` (by class name) or the property id, then ignoring case, then ignoring underscores; `[NotMapped]` skipped; typed getter + setter (generated or bound delegate) when the column has the property's type, or when the property type's getter reads the first row (SQLite converts); otherwise `GetValue` + `ValueConverter`; DBNull leaves the constructor value. Classes created by their constructor (`ReadPlan.WithValues`): boxed values into `ObjectConstructor.Arguments`, then `Create`.
- Measured: see docs/DataReader.md "Performance" (`BenchmarkRows`, Release, i7-7700K, 10 000 invoice rows). On SQLite with native types `ReadRows`, `SerializeRows` and `WriteTable` are at the hand-written loop (~1.9 µs/row, the provider). Reading a dump back with `MsgPackDataReader` (`BenchmarkRows.DumpReader`, in memory, 10 columns, at the index entry): `Read` alone ~250 ns/row, `GetValues` ~415 (boxing), typed getters 5-12 ns each, `ReadAsync` + `GetValues` ~525.
- Ideas not done: `GetChars`/`GetBytes` chunks for large values: on Microsoft.Data.Sqlite 8 they are worse (GetChars chunks of a 20M char text re-decode from the start: 7 s per value instead of 20 ms; GetBytes materializes the blob anyway; `GetChars(null)` for the length costs 3x `GetString` on short strings), so only as an option for providers that stream (SqlClient/Npgsql with `CommandBehavior.SequentialAccess`), and the row is buffered whole for its rollback unless large values flush in the middle of a row (a str/bin of unknown length).
