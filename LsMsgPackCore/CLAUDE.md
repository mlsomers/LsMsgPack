# LsMsgPack.Core

The part of the format and behavior both serializers share (`LsMsgPack` = `LsMsgPackNetStandard/`, `LtMsgPack`). Same namespaces as LsMsgPack (`LsMsgPack.*`).

- Contents: `MsgPackMediaTypes` (`ToPlain<T>` works for both libraries' settings), `MsgPackTypes` (`CacheAssemblyTypes`, the serializers' methods of that name delegate), `MsgPackOptions` (the format settings, abstract; LsMsgPack's `MsgPackSettings` adds custom extensions, the KEEPTRACK settings and buffers; `LtMsgPackOptions` the Lt options), `MsgPackTypeId`, `MsgPackException`, `Meta/` (`FullPropertyInfo`, `PropertyAccessor`, `TypeResolver`, `CollectionInfo`, `Instances`, `ObjectConstructor`, `ByteWriter`, `NumericTypes`, `MapConversionEqualityComparer`, `SerializationRules` (writing decisions: type ids, collections), `ValueConverter` (converting unpacked values), `FrameworkTypeInfo`), `TypeResolving/` (interfaces, attributes, filters, resolvers, `IndexedSchemaTypeResolver`), `Schema/`, `Differences/`, `Streaming/` (escape codes, the stream index model), `Generated/` (the source generator's contract, see `LtMsgPack.Generator/CLAUDE.md`).
- Core must not reference LsMsgPack: shared helpers live here and the old LsMsgPack members delegate (`MsgPackItem.SwapEndianChoice`, `MpString.DefaultEncoding` → `MsgPackOptions.StringEncoding`, `MsgPackMeta.NumericTypes`, the header writers in `ByteWriter`). Internals are visible to `LsMsgPack`, `LtMsgPack`, `LsMsgPackUnitTests` (and `LsMsgPackTs`). Resolver and filter interfaces take `MsgPackOptions`.
- Two internal virtuals of the options are used by the described schema: `HasCustomExtension` and `SerializePlainValue`.

## Trim and AOT annotations (Core and LtMsgPack)

The constructors of `LtMsgPackSerializer`/`LtMsgPackHttpSerializer` without a context (and `LtMsgPackSerializer.Default`) carry `[RequiresUnreferencedCode]`/`[RequiresDynamicCode]` (one warning where a reflection serializer is created, like `XmlSerializer`; `Serialize`/`Deserialize` are not annotated); the constructors taking an `LtMsgPackContext` are not (it is prepended to the options' `Contexts`). Inside, every reflection site is fixed or suppressed with `UnconditionalSuppressMessage` and a reason from `Meta/TrimReasons.cs` (ModelTypes, TypeNames, KeptMembers, Instantiations, ImmutableFactories, Fallback): suppress at the site, not by annotating whole classes, so new reflection still warns in the net8.0 build. Framework members used by reflection are kept with `DynamicDependency` (`FrameworkTypeInfo` `Property`/`Method`/`Constructor`/`Operator`, string form with `System.Private.CoreLib` so the .NET Standard builds can name `DateOnly` etc.; net8.0 uses `typeof`). The attributes are polyfilled internally for the .NET Standard builds in `Meta/TrimAttributes.cs` (LtMsgPack uses them through `InternalsVisibleTo`, do not declare them again there; the Web API formatter has its own copy).

## Format and behavior

- **Objects** are arrays of their values by default (array layout), or with `ObjectLayout.Map` maps from property id to value. The property id is the name, or what an `IMsgPackPropertyIdResolver` returns (`PropertyNameResolvers`), or with the indexed schema the index of the name in the schema. Filters: static ones decide per property (`FilterNonSettable`, `FilterIgnoredAttribute`, `FilterStatic`), dynamic ones per value (`FilterDefaultValues`: default values are omitted, empty strings are written as the JSON serializers do unless `omitEmptyStrings`; LtMsgPack's typed `IncludeByDefault` mirrors it and only takes that path for the default configuration). `FilterIgnoredAttribute` recognizes "ignore" attributes by full type name (`IgnoreAttributes` flags; where it looks: `IgnoreAttributeLookup`, the property itself, overridden ones, interfaces, per preset as its library, default everywhere; no references to those libraries, System.Text.Json's `Condition` and PolyType's `Ignore` read by reflection), its `Like<Library>` presets are checked in `IgnoreAttributeTests` (interop). Filters are immutable: results are cached per filter array.
- **Array layout** (`ObjectLayout.Array`, the default, writing only): an object is an array of its values in `PropertyOrder` (Ls `SerializeAsArray`, Lt `ObjectPlan.WriteArray`), nil for a value the dynamic filters leave out. Trailing nils are kept by default (the same bytes as MessagePack-CSharp's `[Key(n)]`) and left out with `TrimTrailingNulls` (Lt reserves the array header and patches it, `MsgPackWriter.PatchArrayHeader`). `MsgPackMediaTypes.ToPlain` and the `LtMsgPackPresets` for other libraries switch to `ObjectLayout.Map`. A type id wraps it: `{ "": typeId, "@": [values] }`; without a type id an ambiguous value throws (`SerializationRules.ThrowIfUnresolvableAsArray`). Readers take an array assigned to an object type by position (`ValueConverter.ConvertPositional`, Lt `ObjectReader.ReadPositional`): with the indexed schema positions are matched by the schema's names (the writer's order does not matter), without it the reader's order must match the writer's. A nil sets the value the writer leaves out (`FullPropertyInfo.NilValue`, cached in `PropertyAttributeSet.Nil`: the `[DefaultValue]` when it fits the property and the reader's `DynamicFilters` have a `FilterDefaultValues` (`MsgPackOptions.LeavesOutDefaultValues`), otherwise the type's default, as JSON reads null; Lt `PropReader.ReadNil`); a value missing after the end of the array leaves the property as the constructor made it (like a key not in a map; also what `TrimTrailingNulls` trims), extra values are skipped. The one case nil cannot tell apart: a null where a non-null `[DefaultValue]` is left out too reads as the `[DefaultValue]` (analyzer LSMP006). `omitEmptyStrings` empty strings read as null. The ids are still resolved before the type id and the values, so the schema is the same as for maps.
- **Attribute names** (`AttributePropertyNameResolver`): `[JsonPropertyName]`, `[JsonProperty]`, `[XmlAttribute]`, `[XmlElement]`, `[XmlArray]`, `[DataMember]` (in a `[DataContract]`), read once per property (`PropertyAttributeSet.Names`). Without the schema custom resolvers run per object: keep this path allocation-free. With the indexed schema, a string id a custom property id resolver gives is the property's name in the entry (`FullPropertyInfo.SchemaName`/`SchemaNameOf`, `ComplexTypeDef.ParseProps`, `DescribedSchema.Find`) and its id is the index (`ResolvePropertyId` → `IndexedSchemaTypeResolver.IdOfSchemaName`). Data with the .NET name in the schema and the resolver's id as the key (`AttributeNamesReadReleasedSchemas`): the id stays the string when the entry lacks it, `ValueConverter.BindOlderNames` matches the array layout by the .NET name. Two properties with the same name throw in `ParseProps`. Lt reads and writes these through Core (custom resolvers are `SlowObjects`/`IdMode.Session`).
- **Case-insensitive names** (`MsgPackOptions.PropertyNameCaseInsensitive`, off by default, on in the HTTP serializer; for camelCase writers such as the TypeScript client): reading maps keyed by names, a key that is no property name sets the one property whose name equals it ignoring case (none when several do, nor when the exact name is in the map too). Lt: `ReadPlan.FindByName` calls `FindOrMatchIgnoringCase` only when the next property does not have the exact name (kept apart: extra code in `FindByName` cost 2-3% on reading names with the option off): the next property's camelCase name (`PropReader.SetCamelName`: System.Text.Json's `CamelCase` for ASCII letters, only for properties no other one equals ignoring case) compared as bytes, the next property ignoring ASCII case when the first byte differs only in case and no property collides (`_ambiguous`), the scan for the exact or camelCase name, then ASCII keys and names compared ignoring case as bytes, other ones as strings (20 × 100 invoices with camelCase keys: 7.2 ms exact, 8.1 ms camelCase, 26 ms with a string per key). Core: `ValueConverter.SetProperties` counts the keys it set and runs `SetIgnoringCase` only when some are left (`ReportUnknownKeys` does not report the matched ones). With the indexed schema the names of an entry are bound to the reader's properties ignoring case by the same rules, once per entry (`ComplexTypeDef.IdsIgnoringCase`: `GetId` (cached on the entry per reader class) and `PropertiesByPosition`, Lt `BoundSchema.Bind`), and `BindReaderTypes` follows the properties ignoring case.
- **Reserved map keys**: `""` holds the type id and `"@"` the content of a wrapped value (`MsgPackSerializer.TypeIdKey` / `ContentKey`). A collection is written as an array (a dictionary as a map), and only wrapped in a map when it needs a type id or properties (`SerializeEnumerableAttribute.SerializeProperties`).
- **Type ids** are added when the value's type differs from the declared type (`AddTypeIdOption.IfAmbiguious`, default). Short type names by default (`AddTypeIdOption.FullName` for full names), resolved again by name when reading (`Meta/TypeResolver.cs`). Generic arguments are written as `List<Int32>` (parsed back by `SplitByParsing`, recursive descent), a class nested in a generic class with its own arguments per class joined by `+`: `Outer<Int32>+Inner`, `Gen<Int32>+NestedGen<String>` (the short name starts at the outermost generic class).
- **Framework types** without settable properties (`Meta/FrameworkTypeInfo`, Ls `Meta/FrameworkTypes.cs`) are written as MessagePack-CSharp does: `char` as an integer, `TimeSpan` and `TimeOnly` as ticks, `DateOnly` as its day number, `Uri` as its original string, a `KeyValuePair<,>` as `[key, value]` (`GetPair`, Ls `SerializePair`, Lt `TypeKind.Pair`; collections of pairs are maps), tuples as an array of their items (`GetTuple`, Ls `SerializeTuple`, Lt `TypeKind.Tuple`; the 8th item, Rest, is a nested array), multidimensional arrays as `[length0, ..., [items]]` (Ls `SerializeMultidimensional`, Lt `TypeKind.MultiArray`, `ConvertMultidimensional`; type names `Int32[,]`). Types with a `PlainForm` (`GetPlainForm`/`ToPlain`: `Half` float32, `Version`/`StringBuilder` text, `CultureInfo` name, `Rune` code point, `nint`/`nuint` integers, `Memory<byte>`/`ReadOnlyMemory<byte>`/`ArraySegment<byte>` bin, `Complex` `[real, imaginary]`, `BigInteger`/`Int128`/`UInt128` an integer when they fit in 64 bits, otherwise extension type -2 in big-endian two's complement, minimal length, as the proposals of msgpack/msgpack#206 agree) are written as their plain value (Ls `FrameworkTypes.PackPlain` in `MsgPackItem.Pack` after the custom extensions, Lt `TypeKind.Plain`/`WritePlain`) and read by `FrameworkTypeInfo.TryConvert`/`TryConvertItems`/`TryConvertExtension` (also MessagePack-CSharp's bin for big integers). `DateOnly`/`TimeOnly`/`Half`/`Rune`/`Int128`/`UInt128` are found by name (.NET Standard lacks them), conversions by reflection (`Operator`). Immutable and frozen collections are filled by their static factory (`CollectionInfo.FindFactory`: `CreateRange`, `ToFrozenSet`...; `IImmutable*` interfaces map to their implementations), `BitArray` by its `bool[]` constructor. A non-public framework type (the `FrozenSet` of `ToFrozenSet()`, LINQ iterators) gets no type id (`SerializationRules.IsHiddenFrameworkType`): the reader creates the declared type. Other framework types without settable properties (but with readable ones or public fields) are refused with a `MsgPackException` when an object of them is planned (`SerializationRules.ThrowIfUnsupportedFrameworkType`, cached per type: Ls `SerializeObject`, Lt `ObjectPlan`/`ReadPlan`, Core `ConvertMap`/`ConvertArray`), as are `Type` and `MemberInfo` (the data would pick types) and System.Text.Json's document types. A custom extension for such a type is asked first. Ls and Core only check when the type has no serialized properties (a check per object cost 3-7% on writing). User classes without settable properties become an empty map (never refused).
- **Anonymous types** (docs/schema.md "Anonymous types"): `FilterNonSettable` keeps their properties (`SerializationRules.IsAnonymous`: top-level, not public, compiler generated, `<>`/`VB$` + `AnonymousType`), `PropertyAccessor` sets their fields (`<Name>i__Field`, VB `$Name`) when reading into one. A type with an anonymous type (itself, or as a generic argument/element: `SerializationRules.HasAnonymousType`, cached) never gets a type id (`NeedsTypeId`) and is named without the compiler's prefix (`TypeResolver.AnonymousName`: `AnonymousType0<Int32, String>`). Placement (`WritesByNames`/`EntersByNames`, both serializers must agree, `CrossLibraryTests` corpus): where declared and not below an object with an anonymous type (the root, the elements of a root collection; a root `Page<anon>` too, but not its `Data`) it is written like any class (schema entry; the reader pairs the root); a value with an anonymous type not written as its declared type (`object`), and every such object below an object with an anonymous type, is a map of names (`FullPropertyInfo.GetNamedProps`: the static filters' shared instances, names from non-schema property id resolvers), any layout, no schema entry; Ls passes `byNames` through `SerializeObject` and its helpers (`SerializeByNames`), Lt `WriteContext.ByNames` (reset with `Depth`), `WriteTypeInfo.HasAnonymousType` makes those types `BoxedHandler`s so `WriteWithAnonymousType` decides, `NamesPlan`. `SchemaTypes` follows the same context. Readers: with the schema, a map whose keys are all strings (`ValueConverter.HasOnlyNames`) is matched by name (`GetNamedProps`), no entry needed (Lt falls to Core through `Slow`). `PayloadValidation` counts mixed kinds in a dictionary only when v2 declares it `dict`.
- **Immutable classes** (docs/schema.md "Immutable classes"): `ObjectConstructor` (cached per type, also the parameterless constructor cache of `Instances`) picks `[JsonConstructor]`/`[SerializationConstructor]` (by full name) or the only public constructor without a public parameterless one, binds parameters to properties by name (ignoring case, exact first) and type, and is used (`WithValues`) when it takes a property without a public setter (`Required`, then also with `ObjectCreation.Uninitialized`), or, as System.Text.Json, when every parameter takes a property or has a default value and the type is a class or the constructor is marked (a struct keeps its default constructor; a parameter for no property, e.g. a service: not called, uninitialized); `TakesValues(ObjectCreation)` decides; not for framework types, collections, anonymous types. Called through `ConstructorInvoker` on net8.0 (16 ns, `ConstructorInfo.Invoke` 30 ns). `FilterNonSettable` keeps those properties (`ObjectConstructor.Sets`). Reading in Core: `Instances.CreateObjectOrArguments` returns an `ObjectConstructor.Arguments` standing for the object, `ValueConverter.Assign` collects into it, `Created` calls the constructor (missing bound values: `NilValue`; parameters without a property: their default) then sets the other properties; `ReadDifferences` reports its class (`ClassOf`) and replaces it by the created object in the samples (`Created`). LtMsgPack: `ReadPlan.WithValues` (`ConstructorPlan`), the plan's props are `ArgumentReader`s reading into `ConstructorValues` (boxed: parameters, then the other properties, `NotRead`); the constructor is called as soon as the bits of the parameters whose properties are read (`Awaited`) are cleared, later properties are set directly by their typed `PropReader` (`_setter`), earlier ones by `PropReader.SetBoxed`; a parameter's duplicate key after that is skipped; `ObjectReader` finishes with `WithValues.Create`. The reporting paths leave these types to Core (`Slow`); the generated code writes them, does not read them. 600 objects with `Order(string customer)`: 101 µs (parameterless 66 µs, uninitialized 120 µs, Core's path 428 µs); `Array.Clone` was 52 ns, `new` + `Array.Copy` 19 ns. The analyzer predicts the constructor (`ValuesConstructor`, keep it equal).
- **Computed and get-only properties** (docs/schema.md): `FilterNonSettable` keeps properties without any setter (not static, not declared by a framework assembly) per its `GetOnlyProperties` flags (`Collections`: the type has Add, `GetOnlyCollection.IsFillable`; `Computed`: the others; default `All`; constructor `FilterNonSettable(GetOnlyProperties, bool onlyPublic = true)`). Private setters are left out with `onlyPublic`. Reading is decided by the `PropertyInfo` only (`PropertyAccessor`, global): a collection is filled (`Fill`: the getter's collection cleared, then the items read; `GetOnlyCollection.Fill`: IDictionary, IList, else ICollection<T> by reflection; read-only, fixed size, null getter or nil: left), any other property without a setter that no constructor takes is `Computed` (left out when its type is never written: `Type`, `MemberInfo`, delegates, arrays of them, `SerializationRules.IsNeverWritten`) (`FullPropertyInfo.IsComputed`): Core `ValueConverter` skips its value before converting (still a known key), Lt `PropReader.Create` gives a `ComputedPropReader`. The generator's `unrolled` (`TypeWalker.KeptByDefault`, its own `IsNeverWritten`) predicts the default.
- **Non-public properties** (docs/schema.md, off by default): `FilterNonSettable(GetOnlyProperties, NonPublicProperties)` (`None`, `Attributed`: opt-in attributes by full name in `IncludeAttributes` (`[JsonInclude]`, Json.NET `[JsonProperty]`, `[DataMember]`, both `[Key]`, `[PropertyShape]` without `Ignore = true`, any name with "Include"; `PropertyAttributeSet.OptsIn`), `All`). The candidates depend on it: `FullPropertyInfo.GetProperties(Type, NonPublicProperties)` = public ones, then `NonPublicCandidates` (walks the base classes `DeclaredOnly`; not explicit implementations, `[CompilerGenerated]` (a record's `EqualityContract`), framework-declared), hiding over both; caches per mode (`PropertiesCache`, `OrderedPropertiesCache` per order × mode). The mode comes from the static filter array (`SharedPropsCache.NonPublic`, `FullPropertyInfo.NonPublicOf`), so every cache keyed by the array (and `SchemaStore.SessionKey`) separates it. `FilterNonSettable.UsesNonPublic`: the non-public setters (and getters of get-only properties) of the included ones count. `BindReaderTypes` and `SchemaTypes.FindAssemblies` follow the non-public candidates too.
- **Resolving the properties of a type** (`FullPropertyInfo.GetSerializedProps`): in a session, `GetStaticallyIncludedProps` creates the properties once and runs the static filters (with `PropertyId` = name), then the ids are resolved for the kept ones; `IndexedSchemaTypeResolver.GetComplex` takes the names from the same list. Without a session (no schema) the id is resolved first, then the static filters.
- **Property order** (`MsgPackOptions.PropertyOrder`, `FullPropertyInfo.GetProperties(Type, MsgPackOptions)`, decided once per type): `Reflection` (default, `Type.GetProperties()`), `Alphabetical` (ordinal), `Declaration` (base classes first, then metadata token; an override keeps the position of the property it overrides), `Explicit` (`[DataMember(Order = n)]` first, then declaration order), `TypeThenDeclaration` (`PropertyType.ToString()`, then declaration order). It orders map entries and schema names; readers look properties up by name.

## Indexed schema

- **Indexed schema** (`UseInexedSchema`, on by default): each `Serialize`/`Deserialize` call is a **session** with its own `IndexedSchemaTypeResolver` and a clone of the settings (`MsgPackSerializer.WithSchema`). The payload is a map `{ typeName: [propertyName, ...] }` followed by the body, in which property keys and type ids are indexes into that map. The resolver is both a type resolver and a property id resolver. Resolvers are consulted **last to first**: the schema is added last to the type resolvers (asked first) and first to the property id resolvers (asked last, so custom property ids win). Readers look property ids up by name in the payload's schema, so schema contents may change between versions. Reading into other classes than the writer's (`BindReaderTypes`, once per root type and schema, called by both readers before the body): the root's class is the first entry, the others follow from the declared types of the writer's properties with the same names; each reader class gets the writer's entry in `ByType`. Without the writer's classes (names that do not resolve) a v2 schema pairs them (`SchemaBytes.Parse` keeps per property the entry its type holds, `ComplexTypeDef.ValueEntries`/`ContentEntry`, `RootEntry`; `RootDef`/`ValueDef`), v1 only the root (first entry); a type id of an unresolved entry gives the reader class paired with it (`PairedWith`). An object (with values) of a class without an entry throws (`ThrowIfNoEntry`, in `ValueConverter` before the ids are resolved), unless differences are reported.
- **Schema version 2** (`SchemaVersion.Described`, writing only; docs/schema.md "Version 2"): each property `[name, type]` or `[name, type, default]` (portable kinds `int`, `guid`, `datetime`..., an entry index, `["list", T]`...; the default of `[DefaultValue]` when `FilterDefaultValues` leaves it out), `["@", type]` first in an entry that is not an object, and a last entry `""` with `[["@", rootType]]`, for readers without the classes (JavaScript). Written by `Schema/DescribedSchema.cs` for both serializers (same bytes, `CrossLibraryTests.SameBytesAndValuesDescribed`): `IndexedSchemaTypeResolver.Pack(byteOrder, root, settings)`, LtMsgPack's inline path through `DescribedInlineSchemas` (cached per root type and sequence of `SchemaTypeInfo`s). Readers take both versions (`SchemaBytes.Parse(raw, settings, out SchemaVersion)`: v2 is recognized by the `""` entry, `"@"` items are not properties; .NET readers keep the names only). The version is hashed into the `SchemaId` (`Compute(bytes)` reads it from the bytes, writers pass it), writer sessions are keyed by it (`SessionKey`), `SessionState.Root` gives the root type when a store publishes. `SchemaBytes.Repack` converts a schema's byte order by copying every value. Over HTTP it is negotiated by the Accept header (see `LsMsgPackFormatters/CLAUDE.md`).
- **Cached schema** (`SchemaStore`, `Schema/`): sessions kept between calls. Writing with `WriteSchemaReference` keeps one session per root type and settings (`SchemaStore.SessionKey`: type resolvers, static filters, property id resolvers, `AddTypeIdOptions`, `EndianAction`, `PropertyOrder`, `CompleteSchemas`, arrays compared by reference) and writes `D8 02` + a 16 byte `SchemaId` (truncated SHA-256 over a format version byte and the schema packed in the spec's byte order) instead of the schema. Reading looks the id up in the store (`SchemaProvider` or `MissingSchemaException`) or, with the schema inline, recognizes the schema by its bytes (`CacheInlineSchemas`). A published `SchemaSession` is **frozen** (shared by threads, `settings._schemaFrozen`, `IndexedSchemaTypeResolver.IsFrozen`): a call that needs a new type, property or cache entry gets the internal `SchemaGrowthException`, then repeats the work under the state's lock with a copy (`Thaw`) published in its place (writing: a new schema id, appended only, so older ids stay valid). `IndexedSchemaTypeResolver.Unpack` reads the schema from the bytes (`SchemaBytes`), without `MsgPackItem`s.
- **Complete schemas** (`MsgPackOptions.CompleteSchemas`; on in the HTTP serializer): the first writer session of a root type (`SchemaStore.NewWriter`, also `PrepareWriter` / `LtMsgPackSerializer.PrepareSchema` / `LtMsgPackHttpSerializer.PrepareSchema`) gets the entries of `Schema/SchemaTypes.cs` (depth first from the root, as a writer adds them: a concrete class with statically included properties, or one that gets a type id; properties, elements, dictionary keys/values, pairs, tuples, nullables; after a non-sealed class or interface the classes deriving from it in the assemblies the root reaches, by full name), so its id only depends on the types and settings (the same in every process; lsmsgpack-ts writes them for clients). Values outside it still grow the session.

## Reporting differences

`ReadDifferences` (`Differences/`, docs/ReadDifferences.md): the `Deserialize` overloads with `out ReadDifferences` (Ls static, Lt instance) count unknown properties, extra array values, unmatched classes (no schema entry: skipped and reported, `SkipIfNoEntry`; a reader class `BindReaderTypes` found for two writer classes is remembered in `_ambiguous` and named in `Difference.WriterClasses`), unresolved type ids (`UnresolvedTypeException`, caught in `ConvertMap`: skipped; without the schema `TypeResolver.ResolveOrReport` reads a name that is not found as the declared type and reports it; LtMsgPack's reporting path leaves such names to Core; types found but not fitting still throw) and values that do not convert (`InvalidValue`) per class and name. Errors (`Difference.IsError`: InvalidValue, UnmatchedClass, skipped UnresolvedType) follow `MsgPackOptions.ReadErrors` (`FailFast` default: throw; `FailDeferred`: skip, then `ReadErrorsException` from `ReadDifferences.Collect`; `ReportAndContinue`: skip; the last two collect also without the out parameter). Skippable means **marked at the origin** (`ReadDifferences.NotConverted`/`MarkNotConverted`, `ex.Data[NotConvertedKey]`, only while collecting: conversions in `ValueConverter`, Lt `Slow`, `IntegerReader` overflow, Guid strings) and caught per property (Core `ReadProperty`, Lt one handler per object in `ReadReporting`/`ReadPositionalReporting`, which rewinds to the value's start and skips it); setter/constructor exceptions, parse errors and security checks are never marked. The usual path has no exception handlers (`ConvertLeafMarked`, `SetElement` split: a handler on every value cost LsMsgPack 5%), keeps up to 10 sample objects, and finds their paths only in `GenerateReport`/`PathOf` (a walk from `Root` over the statically included properties). The collector is per call: `MsgPackOptions._differences` on a copy of the settings (`WithDifferences`, copied by `Clone`, so session copies collect too), LtMsgPack `ReadContext.Differences` + `SlowSettings` copy. Core hooks: `ValueConverter.SetProperties` (`ReportUnknownKeys`, before the values) and `ConvertPositional`; the parents for unmatched classes are a stack (`Push`/`Pop`). LtMsgPack: `ObjectReader.ReadReporting`/`ReadPositionalReporting` are copies of `Read`/`ReadPositional` with the hooks, chosen by `ReadContext.Unusual` (also `SlowObjects`), so the usual loop has no checks (inline checks and a generic struct switch both measured 2-5% slower): keep the copies the same. A repeated read (`SchemaGrowthException`) calls `Reset`. Exceptions get the differences in `Exception.Data` (exception filter `AttachTo`). Nils in arrays are not counted.

## Caches and their scope

| Cache | Key | Scope |
|---|---|---|
| `FullPropertyInfo.Cache` | PropertyInfo | global, only without property id resolvers. Shared by settings with different static filters, so nothing filter dependent is kept on them (`StaticallyIgnored` is only set on the instances of a session or of custom resolvers) |
| `FullPropertyInfo.SharedPropsCaches` | static filter array (by reference, `ConditionalWeakTable`), then Type, one per `PropertyOrder` | global, only without property id resolvers and without a session. The settings remember the cache of their array (`_sharedPropsCache`). Replace the filter array to change filters, an array changed in place keeps its results (like `SchemaStore.SessionKey`). `StaticPerOrder` (same keys) keeps what the static filters keep with the name as id for `GetStaticallyIncludedProps`: each session gets copies (it sets its ids on them), so the filters run once per type, not per call |
| `FullPropertyInfo.OrderedPropertiesCache` | Type, one per `PropertyOrder` (not `Reflection`) | global, static metadata |
| `FullPropertyInfo.AttributesCache`, `GetProperties` cache | PropertyInfo / Type | global, static metadata |
| `MsgPackOptions._serializedPropsCache`, `_staticPropsCache` | Type | one session (set by `WithSchema` or `SchemaSession.Apply`, not copied by `Clone()`/`CloneOptions()`). Property ids are schema indexes, never share them between sessions. With the schema as the only property id resolver, `IndexedSchemaTypeResolver.TryAssignIds` gives each property its position when the entry has the same names in the same order, without the name lookups |
| `ComplexTypeDef.ByPosition` | the session's property array (by reference) | one schema entry: the reader's properties at the positions of the entry (`ValueConverter.PropertiesByPosition`, array layout), one immutable reference (frozen entries are read by several threads) |
| `SchemaStore` schemas, inline schemas, writer and reader sessions | `SchemaId` / schema bytes / `SessionKey` | one store (shared by the settings that use it). Received schemas limited by `MaxSchemas`, sessions frozen once published |
| `PropertyAccessor.Cache` | PropertyInfo | global. Reflection for the first 100 calls, then typed delegates (`Delegate.CreateDelegate` into `TypedAccessor<TTarget, TValue>`), unless the runtime does not support dynamic code (NativeAOT) or `MsgPackOptions.CompilePropertyAccessors` is off |
| `CollectionInfo`, `ObjectConstructor`, `FilterDefaultValues.DefaultInstances`, `SerializationRules.HasAnonymousType` | Type | global |
| `TypeResolver` name caches | name / Type | global, guarded by one (re-entrant) lock |

Custom property id resolvers without the schema are consulted on every call (by design, they may have their own cache).

## Invariants and gotchas

- **Property ids must be unique per type** and must not be `""` or `"@"`: `FullPropertyInfo.ThrowIfIdsNotUnique` checks once per type, the map entries are then collected in arrays without checks.
- **Exceptions of property getters/setters** are rethrown as they are (not as `TargetInvocationException`), whether the accessor uses reflection or a bound delegate.
- Endianness: MsgPack is big-endian, `EndianAction` can override it. `ByteWriter.WriteEndian` writes the same bytes as `BitConverter.GetBytes` followed by `SwapEndianChoice`.
- **DateTime**: values are returned as UTC by default, timestamps do not keep the `DateTimeKind` (compare with `ToUniversalTime()` in tests). `ReadDateTimeKind` (Utc default, Local, Unspecified = the UTC clock time; `MsgPackOptions.FromTimestamp`, used by `MpDateTime.Value` and Lt `MsgPackReader.TryReadDateTime`/`ReadPlain`; `TryReadTimestamp` is UTC) and `UnspecifiedDateTimeKind` (Utc default; Unspecified written as Utc or Local, `ToTimestamp`): Utc and Unspecified values keep their clock time in any time zone as System.Text.Json reads them (the Kind becomes Utc), a Local value the moment. A `DateTimeOffset` read from a timestamp gets the local offset for Local, zero otherwise (`OffsetOfTimestamp`). `DateTimeOffset` is written as `DateTimeOffsetFormat` says: `TimestampAndOffset` (default, `[timestamp, offset minutes as a short]`, Nerdbank's bytes), `Timestamp` (the offset is lost) or `ClockTimeAndOffset` (MessagePack-CSharp). The arrays look the same, readers take them as the option says (`OffsetOfArray`, `TryConvertItems`, Lt `DateTimeOffsetReader`/`DateTimeOffsetArrayReader`) and a bare timestamp in any format. Timestamps before 1970 round the seconds down, the nanoseconds are always added (`MpDateTime.DateTimeToEpoch`), as the spec requires.
- **Values read into other types** (`ValueConverter.ConvertScalar`, as the JSON serializers read text): into `string` numbers (invariant), `true`/`false`, timestamps (ISO 8601), bin 16 as a Guid, other bins as base64; strings into Guids and enums (by name, ignoring case). Number map keys become string keys, except with the indexed schema (`ConvertKey` throws: object keys are indexes, indistinguishable from a dictionary's numbers), and an array that is not `[key, value]` pairs read into a dictionary throws. An object read untyped (`object`, `Dictionary<string, object>`) only has names with `ObjectLayout.Map` without the schema.
- Reading maps uses `MapConversionEqualityComparer`: numbers are equal across types (`(byte)3` equals the property id `(int)3`), strings and integers take a fast path.
- **Type injection** (docs/security.md): a type picked by the data (type id, schema name, custom resolver) must be assignable to the declared type, checked in `TypeResolver.Resolve` (so both serializers) before the instance is created; names with `,` `[` `]` `&` `*` are refused in `TypeResolver.ResolveName` (`Type.GetType` would load the named assembly). Framework assemblies (`TypeResolver.IsFrameworkAssembly`) only offer their public types (`IsVisible`, `TypeResolver.Visible`, also when caching an assembly). `NativeAssemblies` (searched for names) has the collection assemblies, System.Runtime.Numerics and System.Collections.Immutable when it can be loaded. The optional `MsgPackOptions.TypeGuard` (`IMsgPackTypeGuard`, `AllowedTypesGuard`) is asked only when the picked type differs from the declared one: in `TypeResolver.Resolve` and in LtMsgPack's `ObjectReader` fast path. A new place that creates instances of a type from the data must do the same checks (`TypeInjectionTests`).
- **Type names are short by default**, so the classes of an assembly searched for types need unique names (`TypeResolver.Pick` keeps the concrete candidates assignable to the declared type; two fitting classes throw "Type assignment dilamma", a name that fits one is not cached). Every `Deserialize` registers the assemblies the root type reaches (`TypeResolver.CacheReachableAssemblies`: generic arguments, element types, base types, public property types, not framework assemblies; once per root type). Types not reachable (implementations in other assemblies, values declared as `object`) need `MsgPackTypes.CacheAssemblyTypes(typeof(T))` or an `AllowedTypesGuard` that allows them (`AllowAssembly` registers the assembly, `Allow` the type alone: `TypeResolver.CacheType`). docs/schema.md explains the lookup order. The names of a schema are resolved without throwing when it is read: an unresolved entry is found by the name of the type read (`IndexedSchemaTypeResolver.TryGetDef`) or resolved with the declared type when a type id needs it (then "Unable to resolve type").
- `Type.GetProperties()` also returns **public static properties**: `FilterStatic` (in `Default_StaticFilters`) leaves them out, so the data cannot set shared state.
- **`MsgPackOptions.ObjectCreation`** (`Instances`, Lt `ReadPlan.Creator`): `Constructor`, `ConstructorOrUninitialized` (default), `Uninitialized`. Constructor exceptions are passed on as they are (`TargetInvocationException` unwrapped), an uninitialized object always gets `GC.SuppressFinalize` (finalizers of never constructed objects can end the process, docs/security.md). Weak references are never created uninitialized (the GC crashes on them). Collections and dictionaries always use their constructor (`Instances.CreateCollection`). Uninitialized creation costs ~55 ns on .NET 8 (compiled `new T()` ~12 ns): not a speed option on .NET; on .NET Framework it may be faster (not measured, documented as such). An `Expression`-compiled `Func<T>` factory was tried: 63 µs to compile per type, no gain for LsMsgPack's per-`Type` lookup.
- **`MsgPackOptions.MaxDepth`** (256, both serializers): reading refuses arrays and maps nested deeper (LsMsgPack passes the depth to `MpArray`/`MpMap.Read` via `_depth`, the exception is marked in `Exception.Data` so the levels above do not wrap it; under KEEPTRACK an `MpError`), writing refuses deeper objects and collections (cycles; LsMsgPack: the `depth` parameter of `SerializeObject`). Without it deep data ends in a stack overflow.
- Reading from a `Stream`: use `ReadExactly`/`ReadByteExactly`, `Stream.Read` may return fewer bytes (network streams). Data that ends early throws "Unexpected end of data.". Lengths and counts from headers are checked against the rest of the data before anything is allocated (`MsgPackVarLen.SlotsFor` and `ReadBytes`, Lt `MsgPackReader.Count`; only when `CanSeek`): KEEPTRACK allocates the slots the data can fill and reads up to its end, without it the reader throws.

## Open decision

`MsgPackMediaTypes.ToPlain` (application/msgpack, x-msgpack) should default to what `LtMsgPackPresets.Generic()` writes (e.g. DateTimeOffset as a plain timestamp), but the web formatters share one options object with x-lsmsgpack. The maintainer said "leave it for now": don't change it unasked, bring it up when working on the plain media types.
