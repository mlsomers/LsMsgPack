# LsMsgPack.Core

The part of the format and behavior both serializers share (`LsMsgPackDebug`, `LsMsgPack`). The namespaces are `LsMsgPack.*`.

- Contents: `MsgPackMediaTypes` (`ToPlain<T>` works for both libraries' settings), `MsgPackTypes` (`CacheAssemblyTypes`, the serializers' methods of that name delegate), `MsgPackOptions` (the format settings, abstract; LsMsgPackDebug's `MsgPackSettings` adds custom extensions, the KEEPTRACK settings and buffers; `LsMsgPackOptions` the options of LsMsgPack), `MsgPackTypeId`, `MsgPackException`, `Meta/` (`FullPropertyInfo`, `PropertyAccessor`, `TypeResolver`, `CollectionInfo`, `Instances`, `ObjectConstructor`, `ByteWriter`, `NumericTypes`, `MapConversionEqualityComparer`, `SerializationRules` (writing decisions: type ids, collections), `ValueConverter` (converting unpacked values), `FrameworkTypeInfo`), `TypeResolving/` (interfaces, attributes, filters, resolvers, `IndexedSchemaTypeResolver`), `Schema/`, `Differences/`, `Streaming/` (escape codes, the stream index model), `Generated/` (the source generator's contract, see `LsMsgPack.Generator/CLAUDE.md`).
- Core must not reference LsMsgPackDebug: shared helpers live here and the old LsMsgPackDebug members delegate (`MsgPackItem.SwapEndianChoice`, `MpString.DefaultEncoding` → `MsgPackOptions.StringEncoding`, `MsgPackMeta.NumericTypes`, the header writers in `ByteWriter`). Internals are visible to `LsMsgPackDebug`, `LsMsgPack`, `LsMsgPack.Data` (the data reader add-on: `DescribedSchema.WriteColumns`, `SchemaStore.AddWritten`, `ValueConverter`, `ObjectConstructor`), `LsMsgPackUnitTests` (and `LsMsgPackTs`). Resolver and filter interfaces take `MsgPackOptions`.
- Two internal virtuals of the options are used by the described schema: `HasCustomExtension` and `SerializePlainValue`.

## Trim and AOT annotations (Core and LsMsgPack)

The constructors of `LsMsgPackSerializer`/`LsMsgPackHttpSerializer` without a context (and `LsMsgPackSerializer.Default`) carry `[RequiresUnreferencedCode]`/`[RequiresDynamicCode]` (one warning where a reflection serializer is created, like `XmlSerializer`; `Serialize`/`Deserialize` are not annotated); the constructors taking an `LsMsgPackContext` are not (it is prepended to the options' `Contexts`). Inside, every reflection site is fixed or suppressed with `UnconditionalSuppressMessage` and a reason from `Meta/TrimReasons.cs` (ModelTypes, TypeNames, KeptMembers, Instantiations, ImmutableFactories, Fallback): suppress at the site, not by annotating whole classes, so new reflection still warns in the net8.0 build. Framework members used by reflection are kept with `DynamicDependency` (`FrameworkTypeInfo` `Property`/`Method`/`Constructor`/`Operator`, string form with `System.Private.CoreLib` so the .NET Standard builds can name `DateOnly` etc.; net8.0 uses `typeof`). The attributes are polyfilled internally for the .NET Standard builds in `Meta/TrimAttributes.cs` (LsMsgPack uses them through `InternalsVisibleTo`, do not declare them again there; the Web API formatter has its own copy).

**Code that NativeAOT cannot run stays out of the app** only where it is behind a test of `RuntimeFeature.IsDynamicCodeSupported` itself (a constant for ILC, which then drops the branch; a test of a field or of `PropertyAccessor.CanCompile` is not): every place that compiles expressions tests it first (`FieldDelegates`, LsMsgPack's `ObjectPlan.Compile`, `ReadPlan.Compile`, `StructDefault.Create`), so System.Linq.Expressions is not in a NativeAOT app (one small class, .NET 10: 790 KB less). The same for code that instantiates generics for types the app may not use: LsMsgPack's `Serializer.CreateInBulk` leaves its switch over all element types to runtimes with dynamic code, NativeAOT gets only the instantiations of the generated descriptions (197 KB less). Keep the test there when adding expression code, and look at the map file when the size grows (`-p:IlcGenerateMapFile=true`, `obj/.../native/<app>.map.xml`: the `MethodCode` nodes by assembly).

**NativeAOT without the generator** (gaps checklist "NativeAOT without the generator", maintainer's decisions 2026-11-21: make it work, the app keeps its model, a class without members is refused, the app keeps immutable/frozen factories; docs/SourceGenerator.md "Without the generator"): reference type arguments run the shared canonical code, so LsMsgPack's `Serializer.ReflectionInstantiations` keeps the constructors of the generic handlers/readers it creates (and of `List<>`/`Dictionary<,>`/`HashSet<>`, the fields of the System.Numerics structs), referenced only by `DynamicDependency` on the constructors without a context (apps with a context: +12 KB of fallback code, none of these). Value type arguments have no code unless the app uses them: `Serializer.Instantiate` returns null there (`CreateInstantiation` catches NotSupported/MissingMethod/TypeLoad only without dynamic code) and the callers go boxed (see `../LsMsgPack/CLAUDE.md`). Core: `Instances.Create` refuses a framework type whose constructor is trimmed (never uninitialized: a `List` without its array), `Instances.Construct` and `CollectionInfo.Invoke` turn the NativeAOT `NotSupportedException` of a constructor or factory invocation (not of the code it runs: that is a `TargetInvocationException`) into `Instances.NoCode` (names the type, `Display`), `CollectionInfo.NoFactory` names the `[DynamicDependency]` an immutable/frozen collection needs (keeping them in the library cost 304 KB per app). LsMsgPack's `ThrowIfTrimmed` (both plans) refuses a type without any property or field. Test: `LsMsgPackAotReflectionTest` (the smoke test's `Program.cs` with `NO_GENERATOR`, model kept by `Model.xml`, `KeepFactories` as the errors ask), run by `LsMsgPackAotSmokeTest/run.sh`.

The trim tools of .NET 10 report more than the analyzers of the net8.0 build (generic arguments of `MakeGenericType`/`MakeGenericMethod`, the types `GetInterfaces` returns), and an application publishing on .NET 10 sees that with the net8.0 build: `LsMsgPackAotSmokeTest` publishes on .NET 10, but only covers Core and LsMsgPack. For `LsMsgPack.Data` and the formatters, compile a `net10.0` target to see them.

**Trimmers that keep only the attributes whose type the code uses** (Unity's High stripping): an attribute matched by name alone loses its instances, so the .NET Standard attribute types Core matches only by name are named with `typeof` in the class that reads them (`EnumNames.ReadByName`: `[EnumMember]`; `FilterIgnoredAttribute.ReadByName`: `[XmlIgnore]`, `[IgnoreDataMember]`; without it an ignored member was written at High). The others (`[DataMember]`, `[DataContract]`, the XML names, `[DefaultValue]`) are cast to their type already. Add a new by-name .NET Standard attribute there too.

**A boxed struct by reference**: `Meta/BoxedValue.Ref<T>(box)`, not `Unsafe.Unbox<T>`: Unity's IL2CPP (6000.6) fails to compile `Unsafe.Unbox<T>` in a method of a generic class for any struct ("IL2CPP Internal Error: Attempt to access method info data ... for TTarget with Type when no method info would be passed in": the build of a project with a generated context failed; repro without LsMsgPack in `LsMsgPackUnitySmokeTest/Repro`). The .NET Standard builds use `Unsafe.As<StrongBox<T>>(box).Value` (a box has StrongBox's layout), net8.0 keeps `Unsafe.Unbox`. `TypeResolver.NativeAssemblies` has `HashSet<>`'s assembly: System.Core on .NET Framework and Mono (Unity), where its type ids did not resolve.

## Format and behavior

- **Objects** are arrays of their values by default (array layout), or with `ObjectLayout.Map` maps from property id to value. The property id is the name, or what an `IMsgPackPropertyIdResolver` returns (`PropertyNameResolvers`), or with the indexed schema the index of the name in the schema. Filters: static ones decide per property (`FilterNonSettable`, `FilterIgnoredAttribute`, `FilterStatic`), dynamic ones per value (`FilterDefaultValues`: default values are omitted, empty strings are written as the JSON serializers do unless `omitEmptyStrings`; how a value of a value type is compared is decided once per property, `PropertyAttributeSet.ValueType`/`Default`/`IsNullable`, when the value has the property's type and the member is the set's; LsMsgPack's typed `IncludeByDefault` mirrors it and only takes that path for the default configuration). `FilterIgnoredAttribute` recognizes "ignore" attributes by full type name (`IgnoreAttributes` flags; where it looks: `IgnoreAttributeLookup`, the property itself, overridden ones, interfaces, per preset as its library, default everywhere; no references to those libraries, System.Text.Json's `Condition` and PolyType's `Ignore` read by reflection), `[NonSerialized]` on a field is a metadata flag, not an attribute (`IgnoreAttributes.NonSerialized`, in `All` and `LikeNewtonsoft`; the flag 0x80 as a constant: `FieldInfo.IsNotSerialized` is SYSLIB0050 on net8.0), its `Like<Library>` presets are checked in `IgnoreAttributeTests` (interop). Dynamic filters implementing `IMsgPackPropertyIncludeWithOwner` get the object too (both serializers call `MsgPackOptions.IncludeDynamically`; a struct owner is a boxed copy): `FilterShouldSerialize` calls `bool ShouldSerialize{Name}()` (`Meta/ShouldSerializeMethod.cs`, cached per member in `PropertyAttributeSet.ShouldSerialize`; found as Json.NET does: public instance or static, on the member's `DeclaringType`, so a derived class's method for an inherited member is not called; `ShouldSerializeTests` compare the keys with Json.NET). Filters are immutable: results are cached per filter array.
- **Array layout** (`ObjectLayout.Array`, the default, writing only): an object is an array of its values in `PropertyOrder` (LsMsgPackDebug `SerializeAsArray`, LsMsgPack `ObjectPlan.WriteArray`), nil for a value the dynamic filters leave out. Trailing nils are kept by default (the same bytes as MessagePack-CSharp's `[Key(n)]`) and left out with `TrimTrailingNulls` (LsMsgPack reserves the array header and patches it, `MsgPackWriter.PatchArrayHeader`). `MsgPackMediaTypes.ToPlain` and the `LsMsgPackPresets` for other libraries switch to `ObjectLayout.Map`. A type id wraps it: `{ "": typeId, "@": [values] }`; without a type id an ambiguous value throws (`SerializationRules.ThrowIfUnresolvableAsArray`). Readers take an array assigned to an object type by position (`ValueConverter.ConvertPositional`, LsMsgPack `ObjectReader.ReadPositional`): with the indexed schema positions are matched by the schema's names (the writer's order does not matter), without it the reader's order must match the writer's. A nil sets the value the writer leaves out (`FullPropertyInfo.NilValue`, cached in `PropertyAttributeSet.Nil`: the `[DefaultValue]` when it fits the property and the reader's `DynamicFilters` have a `FilterDefaultValues` (`MsgPackOptions.LeavesOutDefaultValues`), otherwise the type's default, as JSON reads null; LsMsgPack `PropReader.ReadNil`); a value missing after the end of the array leaves the property as the constructor made it (like a key not in a map; also what `TrimTrailingNulls` trims), extra values are skipped. The one case nil cannot tell apart: a null where a non-null `[DefaultValue]` is left out too reads as the `[DefaultValue]` (analyzer LSMP006). `omitEmptyStrings` empty strings read as null. The ids are still resolved before the type id and the values, so the schema is the same as for maps.
- **Attribute names** (`AttributePropertyNameResolver`): `[JsonPropertyName]`, `[JsonProperty]`, `[XmlAttribute]`, `[XmlElement]`, `[XmlArray]`, `[DataMember]` (in a `[DataContract]`), read once per property (`PropertyAttributeSet.Names`). Without the schema custom resolvers run per object: keep this path allocation-free. With the indexed schema, a string id a custom property id resolver gives is the property's name in the entry (`FullPropertyInfo.SchemaName`/`SchemaNameOf`, `ComplexTypeDef.ParseProps`, `DescribedSchema.Find`) and its id is the index (`ResolvePropertyId` → `IndexedSchemaTypeResolver.IdOfSchemaName`). Data with the .NET name in the schema and the resolver's id as the key (`AttributeNamesReadReleasedSchemas`): the id stays the string when the entry lacks it, `ValueConverter.BindOlderNames` matches the array layout by the .NET name. Two properties with the same name throw in `ParseProps`. LsMsgPack reads and writes these through Core (custom resolvers are `SlowObjects`/`IdMode.Session`).
- **Case-insensitive names** (`MsgPackOptions.PropertyNameCaseInsensitive`, off by default, on in the HTTP serializer; for camelCase writers such as the TypeScript client): reading maps keyed by names, a key that is no property name sets the one property whose name equals it ignoring case (none when several do, nor when the exact name is in the map too). LsMsgPack's compiled and generated readers take only the keys that are the names straight-line (see `../LsMsgPack/CLAUDE.md`, Compiled readers); `ReadPlan.FindByName` calls `FindOrMatchIgnoringCase` only when the next property does not have the exact name (kept apart: extra code in `FindByName` cost 2-3% on reading names with the option off): the next property's camelCase name (`PropReader.SetCamelName`: System.Text.Json's `CamelCase` for ASCII letters, only for properties no other one equals ignoring case) compared as bytes, the next property ignoring ASCII case when the first byte differs only in case and no property collides (`_ambiguous`), the scan for the exact or camelCase name, then ASCII keys and names compared ignoring case as bytes, other ones as strings (20 × 100 invoices with camelCase keys: 7.2 ms exact, 8.1 ms camelCase, 26 ms with a string per key). Core: `ValueConverter.SetProperties` counts the keys it set and runs `SetIgnoringCase` only when some are left (`ReportUnknownKeys` does not report the matched ones). With the indexed schema the names of an entry are bound to the reader's properties ignoring case by the same rules, once per entry (`ComplexTypeDef.IdsIgnoringCase`: `GetId` (cached on the entry per reader class) and `PropertiesByPosition`, LsMsgPack `BoundSchema.Bind`), and `BindReaderTypes` follows the properties ignoring case.
- **Naming policies** (docs/NamingPolicies.md; `Naming/MsgPackNamingPolicy.cs`; gaps checklist "Naming policy", maintainer's decisions 2026-11-21: three separate options, attribute names verbatim, readers take the policy name, then the .NET name, then ignoring case; off by default everywhere): `MsgPackOptions.PropertyNamingPolicy`, `DictionaryKeyPolicy`, `EnumNamingPolicy` (abstract `MsgPackNamingPolicy`, built-ins ported from System.Text.Json's `JsonCamelCaseNamingPolicy`/`JsonSeparatorNamingPolicy`, `NamingPolicyTests.Policies_SameNamesAsSystemTextJson`; `Convert` refuses null/empty; property and enum policies in `SessionKey`). **Properties**: `FullPropertyInfo.WrittenName` (the .NET name converted, set when an instance is made for the options: `FilterStatically`, `GetFullPropInfo`, copied by the copy constructor) is the id when no resolver gives one (`ResolvePropertyId`, `SchemaNameOf`, `_uniqueName`, `TryAssignIds`), so map keys, schema names, anonymous types follow it; the global `FullPropertyInfo.Cache` only without a policy, `SharedPropsCache.For(policy)` keeps one cache per filter array and policy (`settings._sharedPropsCache` checks both). `OtherName` = the .NET name when it differs and the id is the written name. Reading: `ValueConverter.SetProperties` runs `SetIgnoringCase` → `MatchOtherName` also with a policy (a key that is a property id: nothing; the .NET name exactly; with `PropertyNameCaseInsensitive` the ids then the .NET names ignoring case), `BindOlderNames` binds the array layout by the .NET name too, `IndexedSchemaTypeResolver.GetId` tries `WrittenName`, the .NET name, then ignoring case (`IdIgnoringCase` over the written names), `ValueDef` (v2 pairing) the written then the .NET name. **Dictionary keys**: writing only (as STJ): string keys (a key value that is a string) in LsMsgPackDebug `SerializeKey`, LsMsgPack `WriteKey`, `DictionaryHandler` (`TKey` string or object: `WriteOther`, a loop of its own) and `PairElements`; not extension data, not `KeyValuePair` members. Through `MsgPackNamingPolicy.ConvertKey`: the built-in policies keep 256 recent keys and their names (`_recentKeys`, a slot by length and the outer characters, compared by content, one store per miss; custom policies are asked every time): 20 keys written per call, camelCase 1246 -> 483-492 ns, snake_case 2258 -> 477-508 ns, 2616 -> 376 B (without a policy 372-385 ns). **Enums**: `EnumNames.Of(type, policy)` (a table per policy and type; custom names verbatim, written names first then the .NET names in `_exact`, so readers with the policy take both), every writer and `ValueConverter.ConvertScalar` (takes the settings now) ask with the options; LsMsgPack `EnumNameReading<TEnum>` keeps the last policy's table besides the default one. Tests: `NamingPolicyTests` (Debug, Ls, Gen; `SameBytesAsDebug_RuntimeCompiledGenerated`, `CompiledAndGenerated_ReadTheDotNetNames`), `CrossLibraryTests.SameBytesAndValuesNamingPolicies`, interop `NerdbankTests.SameBytes_CamelCaseNames`, lsmsgpack-ts `NamingPoliciesOfTheOptions`, the NativeAOT smoke test's `naming-policies`.
- **Reserved map keys**: `""` holds the type id and `"@"` the content of a wrapped value (`MsgPackSerializer.TypeIdKey` / `ContentKey`). A collection is written as an array (a dictionary as a map), and only wrapped in a map when it needs a type id or properties (`SerializeEnumerableAttribute.SerializeProperties`).
- **Type ids** are added when the value's type differs from the declared type (`AddTypeIdOption.IfAmbiguious`, default). Short type names by default (`AddTypeIdOption.FullName` for full names), resolved again by name when reading (`Meta/TypeResolver.cs`). Generic arguments are written as `List<Int32>` (parsed back by `SplitByParsing`, recursive descent), a class nested in a generic class with its own arguments per class joined by `+`: `Outer<Int32>+Inner`, `Gen<Int32>+NestedGen<String>` (the short name starts at the outermost generic class).
- **Framework types** without settable properties (`Meta/FrameworkTypeInfo`, LsMsgPackDebug `Meta/FrameworkTypes.cs`) are written as MessagePack-CSharp does: `char` as an integer, `TimeSpan` and `TimeOnly` as ticks, `DateOnly` as its day number, `Uri` as its original string, a `KeyValuePair<,>` as `[key, value]` (`GetPair`, LsMsgPackDebug `SerializePair`, LsMsgPack `TypeKind.Pair`; collections of pairs are maps), tuples as an array of their items (`GetTuple`, LsMsgPackDebug `SerializeTuple`, LsMsgPack `TypeKind.Tuple`; the 8th item, Rest, is a nested array), multidimensional arrays as `[length0, ..., [items]]` (LsMsgPackDebug `SerializeMultidimensional`, LsMsgPack `TypeKind.MultiArray`, `ConvertMultidimensional`; type names `Int32[,]`). Types with a `PlainForm` (`GetPlainForm`/`ToPlain`: `Half` float32, `Version`/`StringBuilder` text, `CultureInfo` name, `Rune` code point, `nint`/`nuint` integers, `Memory<byte>`/`ReadOnlyMemory<byte>`/`ArraySegment<byte>` bin, `Complex` `[real, imaginary]`, `BigInteger`/`Int128`/`UInt128` an integer when they fit in 64 bits, otherwise extension type -2 in big-endian two's complement, minimal length, as the proposals of msgpack/msgpack#206 agree) are written as their plain value (LsMsgPackDebug `FrameworkTypes.PackPlain` in `MsgPackItem.Pack` after the custom extensions, LsMsgPack `TypeKind.Plain`/`WritePlain`) and read by `FrameworkTypeInfo.TryConvert`/`TryConvertItems`/`TryConvertExtension` (also MessagePack-CSharp's bin for big integers). `DateOnly`/`TimeOnly`/`Half`/`Rune`/`Int128`/`UInt128` are found by name (.NET Standard lacks them), conversions by reflection (`Operator`). Immutable and frozen collections are filled by their static factory (`CollectionInfo.FindFactory`: `CreateRange`, `ToFrozenSet`...; `IImmutable*` interfaces map to their implementations), `BitArray` by its `bool[]` constructor. A non-public framework type (the `FrozenSet` of `ToFrozenSet()`, LINQ iterators) gets no type id (`SerializationRules.IsHiddenFrameworkType`): the reader creates the declared type. Framework structs whose state is public fields (`SerializationRules.IsFieldStruct`: a framework value type with a public mutable instance field, not a tuple/`KeyValuePair`/`Nullable`; System.Numerics `Vector2/3/4`, `Quaternion`, `Plane`, `Matrix3x2/4x4`) are written by their public fields only, whatever the fields mode (`FindMembers`; `Vector3` = `[x, y, z]`, MessagePack-CSharp's bytes; not `Matrix4x4.Translation`). **Unity's** (docs/Unity.md; maintainer's decisions 2026-11-22): its engine assemblies (`SerializationRules.IsEngineAssembly`: `UnityEngine`, `UnityEngine.*`, by name) count as the framework for these member rules only (`IsPlatformDeclared`: `HasFieldState`, `FilterNonSettable.KeepsGetOnly`, `AddFieldCandidates`, `NonPublicCandidates`), not for type names, security or refusing: `UnityEngine.Vector3`/`Quaternion`/`Color`/`Matrix4x4` by their public fields (their computed `normalized` returned another struct: written, it never ended), `Vector2Int` by its settable `x`/`y` (not `magnitude` or `m_X`). The generator mirrors it (`TypeWalker.IsPlatform`/`IsEngine`). `[SerializeField]` (`UnityEngine.SerializeField`, by name) opts a field in like `[DataMember]` (`IncludeAttributes`, the generator's and analyzers' `OptsIn`); Unity's public fields need `SerializedFields.Public`. Tests: `UnityTypesTests` (Debug, Ls, Gen) on `LsMsgPackUnityStubs` (an assembly named `UnityEngine.CoreModule`), Unity itself `LsMsgPackUnitySmokeTest`. Other framework types without settable properties (but with readable ones) are refused with a `MsgPackException` when an object of them is planned (`SerializationRules.ThrowIfUnsupportedFrameworkType`, cached per type: LsMsgPackDebug `SerializeObject`, LsMsgPack `ObjectPlan`/`ReadPlan`, Core `ConvertMap`/`ConvertArray`), as are `Type` and `MemberInfo` (the data would pick types) and System.Text.Json's document types (`IsJsonDocumentType`, a message of their own; `JsonObject`/`JsonArray` are collections, so only their values are refused: empty ones are written as `{}`/`[]`, and reading them or `JsonNode` fails with other exceptions). A custom extension for such a type is asked first. LsMsgPackDebug and Core only check when the type has no serialized properties (a check per object cost 3-7% on writing). User classes without settable properties become an empty map (never refused).
- **Converters** (docs/Converters.md; `Converters/MsgPackConverter.cs`): `MsgPackConverter<T, TSurrogate>` (`ToSurrogate`/`FromSurrogate`) on the base `MsgPackConverter` (internal constructor: only the two kinds derive, each with its `IMsgPackConverterVisitor` method), and the binary kind `MsgPackBinaryConverter<T>` (`Converters/MsgPackBinaryConverter.cs`: `GetLength`/`Write(Span)`/`Read(ReadOnlySpan)`, `ExtensionTypeCode` null for bin or 0-127; `SurrogateType` is `byte[]`, so every place that follows surrogates sees bin; Core reads bin or an extension of its code, `ValueConverter.ConvertBinary`; v2 describes an extension as `any`) with the blit converters (`BlitConverter<T>`, `BlitArrayConverter<T>`, `BlitListConverter<T>`, `BlitMemoryConverter<T>`, `BlitReadOnlyMemoryConverter<T>`, `where T : unmanaged`: the memory as it is, the length checked as a whole number of values, refused on big-endian machines; maintainer's decisions 2026-11-15: bin by default with an optional extension code, the length check only, all four shapes; parameterless constructors for the attribute), registered by `MsgPackOptions.Converters` (a checked copy: one per type, not object/interfaces/abstract/`Nullable<T>`, no chain back to a converted type, `ConverterLookup.Checked`; in `SchemaStore.SessionKey`) or `[MsgPackConverter]` on the type (`ConverterLookup.Find`: the options first, then the attribute, cached per type globally; primitives, string, arrays, decimal, DateTime, Guid are not looked up for attributes). Maintainer's decisions (2026-11-14): any type may be converted, built-ins too; exact type only (a derived class is an object with a type id); options, type attribute and (2026-11-15) member attribute. **On a property or field** (`PropertyAttributeSet.Converter`, created once per member by `ConverterLookup.OfMember`: its T is the member's type or a nullable member's underlying type, otherwise a `MsgPackException` at first use; `FullPropertyInfo.MemberConverter`): its own value only, before the type's and the options' converters, through `MsgPackOptions.ConverterFor(type, assignedTo)` (the member's when the type is its converted or declared type: not elements, not derived classes), which every place that has the member asks: `ValueConverter`, LsMsgPackDebug `SerializeObject`, `DescribedSchema.WriteType`/`DefaultOf` (a `[DefaultValue]` as its surrogate), `SchemaTypes.VisitMemberConverted` (the surrogate and the classes deriving from the member's type, not the type itself), `IndexedSchemaTypeResolver.BindReaderTypes` (`WrittenTypeOf`, `ObjectTypeOf` follows converters at every level: members, elements, dictionary values). Asked first, before every built-in format: `MsgPackOptions.ConverterFor(type)` (underlying type of a nullable). The surrogate is written as a value declared as `TSurrogate` (`SurrogateInfo`); where the declared type differs, wrapped as a leaf value is: `{ "": typeId, "@": surrogate }`, the type id written **before** the surrogate (LsMsgPackDebug `SerializeConverted`, LsMsgPack `WriteConverted`: the schema order). Nil is never converted (null/default), a null surrogate is nil, `FilterDefaultValues` compares the member's own value. Property ids and type ids are never converted (LsMsgPack `Serializer.WriteId`; LsMsgPackDebug packs them as items). Reading (`ValueConverter.ConvertDeserializeValue`): `ConvertSurrogate` (the surrogate converted as `SurrogateType`, then `FromSurrogateBoxed`; a result that is not the surrogate type is marked not converted, the converter's exceptions pass as they are), except a map with a type id: `ConvertMap` asks `TypeResolver.NamesSurrogate` (the id resolved against object, without throwing: a class deriving from the surrogate type, not from the converted one) and otherwise resolves it against the declared type (a derived class, or `AddTypeIdOption.Always`'s wrapper of the converted type). Schema: a converted type's entry has no properties (`IndexedSchemaTypeResolver.GetComplex`, LsMsgPack `GetSchemaInfo`), v2 describes the surrogate (`DescribedSchema.WriteType`; `IsObject` false), `SchemaTypes` visits the surrogate and the classes deriving from a converted class. Tests: `ConverterTests`, `CrossLibraryTests.SameBytesAndValuesConverters`/`ConvertedBuiltIns`/`ConvertersWithOtherOptions`.
- **Enums** (docs/Enums.md; `Enums/`; gaps checklist item 8, maintainer's decisions 2026-11-18: an option and an attribute, not a converter, so readers take both forms; numbers stay the default): `MsgPackOptions.EnumFormat` (`Number`/`Name`, in `SessionKey`: v2 describes `string`), `[MsgPackEnumFormat]` on an enum, property or field; `EnumFormatOf(type)` / `EnumFormatOf(type, assignedTo)`: the member's own (only when the value's type is the member's enum or the underlying type of a nullable member, `PropertyAttributeSet.EnumType`/`EnumFormat`; not elements), then the enum's (`EnumFormats.OfType`, cached, the last type first: LsMsgPackDebug asks per value), then the option. Other serializers' attributes by full name over `CustomAttributeData` (nothing loaded or referenced; `EnumFormats.OfOtherSerializer`): System.Text.Json and Json.NET `[JsonConverter]` with their string enum converters (or a class deriving from them; `JsonNumberEnumConverter<T>` is Number; Json.NET's naming arguments are not followed), MessagePack-CSharp `[MessagePackFormatter]` with `EnumAsStringFormatter<T>`/`GenericEnumFormatter<T>`, MsgPack.Cli `[MessagePackEnum]` (no argument: by name, its default) and `[MessagePackEnumMember]` (`Default`: the enum decides); the own attribute wins. `EnumNames` (per type, global): the values as ulong bits (signed sign-extended) with their written names (custom names `[JsonStringEnumMemberName]`, `[EnumMember(Value)]`, PolyType `[EnumMemberShape(Name)]`, in that order; aliases: the first declared, by `GetFields` order), `NameOf` (null: write the number, as STJ/Json.NET: a value without a name, flags bits no name covers), `Combination` (`[Flags]`: greedy from the largest value, joined ascending by `", "`, as Enum.ToString), `TryParse`/`Parse` (written names first, then .NET names, ignoring case, comma-joined parts, integers as text; `ArgumentException` as Enum.Parse, marked by the caller like any conversion). Two values written with one name throw a `MsgPackException` when the table is built (only for name writing or reading a string). Readers take numbers and names whatever the option (`ValueConverter.ConvertScalar` → `EnumNames.Parse`). Writers: LsMsgPackDebug `MsgPackItem.Pack` (the type's format, `PackEnum`) and `SerializeValue` (the member's), LsMsgPack `TypeKind.EnumName` (see `../LsMsgPack/CLAUDE.md`), `DescribedSchema.WriteType`/`DefaultOf` (a member's own format for `[DefaultValue]`). ## Indexed schema

- **Indexed schema** (`UseInexedSchema`, on by default): each `Serialize`/`Deserialize` call is a **session** with its own `IndexedSchemaTypeResolver` and a clone of the settings (`MsgPackSerializer.WithSchema`). The payload is a map `{ typeName: [propertyName, ...] }` followed by the body, in which property keys and type ids are indexes into that map. The resolver is both a type resolver and a property id resolver. Resolvers are consulted **last to first**: the schema is added last to the type resolvers (asked first) and first to the property id resolvers (asked last, so custom property ids win). Readers look property ids up by name in the payload's schema, so schema contents may change between versions. Reading into other classes than the writer's (`BindReaderTypes`, once per root type and schema, called by both readers before the body): the root's class is the first entry, the others follow from the declared types of the writer's properties with the same names; each reader class gets the writer's entry in `ByType`. Without the writer's classes (names that do not resolve) a v2 schema pairs them (`SchemaBytes.Parse` keeps per property the entry its type holds, `ComplexTypeDef.ValueEntries`/`ContentEntry`, `RootEntry`; `RootDef`/`ValueDef`), v1 only the root (first entry); a type id of an unresolved entry gives the reader class paired with it (`PairedWith`). An object (with values) of a class without an entry throws (`ThrowIfNoEntry`, in `ValueConverter` before the ids are resolved), unless differences are reported.
- **Schema version 2** (`SchemaVersion.Described`, writing only; docs/schema.md "Version 2"): each property `[name, type]` or `[name, type, default]` (portable kinds `int`, `guid`, `datetime`..., an entry index, `["list", T]`...; the default of `[DefaultValue]` when `FilterDefaultValues` leaves it out), `["@", type]` first in an entry that is not an object, and a last entry `""` with `[["@", rootType]]`, for readers without the classes (JavaScript). Written by `Schema/DescribedSchema.cs` for both serializers (same bytes, `CrossLibraryTests.SameBytesAndValuesDescribed`): `IndexedSchemaTypeResolver.Pack(byteOrder, root, settings)`, LsMsgPack's inline path through `DescribedInlineSchemas` (cached per root type and sequence of `SchemaTypeInfo`s). Readers take both versions (`SchemaBytes.Parse(raw, settings, out SchemaVersion)`: v2 is recognized by the `""` entry, `"@"` items are not properties; .NET readers keep the names only). The version is hashed into the `SchemaId` (`Compute(bytes)` reads it from the bytes, writers pass it), writer sessions are keyed by it (`SessionKey`), `SessionState.Root` gives the root type when a store publishes. `SchemaBytes.Repack` converts a schema's byte order by copying every value. Over HTTP it is negotiated by the Accept header (see `LsMsgPackFormatters/CLAUDE.md`).
- **Cached schema** (`SchemaStore`, `Schema/`): sessions kept between calls. Writing with `WriteSchemaReference` keeps one session per root type and settings (`SchemaStore.SessionKey`: type resolvers, static filters, property id resolvers, `AddTypeIdOptions`, `EndianAction`, `PropertyOrder`, `CompleteSchemas`, arrays compared by reference) and writes `D8 02` + a 16 byte `SchemaId` (truncated SHA-256 over a format version byte and the schema packed in the spec's byte order) instead of the schema. Reading looks the id up in the store (`SchemaProvider` or `MissingSchemaException`) or, with the schema inline, recognizes the schema by its bytes (`CacheInlineSchemas`). A published `SchemaSession` is **frozen** (shared by threads, `settings._schemaFrozen`, `IndexedSchemaTypeResolver.IsFrozen`): a call that needs a new type, property or cache entry gets the internal `SchemaGrowthException`, then repeats the work under the state's lock with a copy (`Thaw`) published in its place (writing: a new schema id, appended only, so older ids stay valid). `IndexedSchemaTypeResolver.Unpack` reads the schema from the bytes (`SchemaBytes`), without `MsgPackItem`s.
- **Complete schemas** (`MsgPackOptions.CompleteSchemas`; on in the HTTP serializer): the first writer session of a root type (`SchemaStore.NewWriter`, also `PrepareWriter` / `LsMsgPackSerializer.PrepareSchema` / `LsMsgPackHttpSerializer.PrepareSchema`) gets the entries of `Schema/SchemaTypes.cs` (depth first from the root, as a writer adds them: a concrete class with statically included properties, or one that gets a type id; properties, elements, dictionary keys/values, pairs, tuples, nullables; after a non-sealed class or interface the classes deriving from it in the assemblies the root reaches, by full name), so its id only depends on the types and settings (the same in every process; lsmsgpack-ts writes them for clients). Values outside it still grow the session.

## Reporting differences

`ReadDifferences` (`Differences/`, docs/ReadDifferences.md): the `Deserialize` overloads with `out ReadDifferences` (LsMsgPackDebug static, LsMsgPack instance) count unknown properties, extra array values, unmatched classes (no schema entry: skipped and reported, `SkipIfNoEntry`; a reader class `BindReaderTypes` found for two writer classes is remembered in `_ambiguous` and named in `Difference.WriterClasses`), unresolved type ids (`UnresolvedTypeException`, caught in `ConvertMap`: skipped; without the schema `TypeResolver.ResolveOrReport` reads a name that is not found as the declared type and reports it; LsMsgPack's reporting path leaves such names to Core; types found but not fitting still throw) and values that do not convert (`InvalidValue`) per class and name. Errors (`Difference.IsError`: InvalidValue, UnmatchedClass, skipped UnresolvedType) follow `MsgPackOptions.ReadErrors` (`FailFast` default: throw; `FailDeferred`: skip, then `ReadErrorsException` from `ReadDifferences.Collect`; `ReportAndContinue`: skip; the last two collect also without the out parameter). Skippable means **marked at the origin** (`ReadDifferences.NotConverted`/`MarkNotConverted`, `ex.Data[NotConvertedKey]`, only while collecting: conversions in `ValueConverter`, LsMsgPack `Slow`, `IntegerReader` overflow, Guid strings) and caught per property (Core `ReadProperty`, LsMsgPack one handler per object in `ReadReporting`/`ReadPositionalReporting`, which rewinds to the value's start and skips it); setter/constructor exceptions, parse errors and security checks are never marked. The usual path has no exception handlers (`ConvertLeafMarked`, `SetElement` split: a handler on every value cost LsMsgPackDebug 5%), keeps up to 10 sample objects, and finds their paths only in `GenerateReport`/`PathOf` (a walk from `Root` over the statically included properties). The collector is per call: `MsgPackOptions._differences` on a copy of the settings (`WithDifferences`, copied by `Clone`, so session copies collect too), LsMsgPack `ReadContext.Differences` + `SlowSettings` copy. Core hooks: `ValueConverter.SetProperties` (`ReportUnknownKeys`, before the values) and `ConvertPositional`; the parents for unmatched classes are a stack (`Push`/`Pop`). LsMsgPack: `ObjectReader.ReadReporting`/`ReadPositionalReporting` are copies of `Read`/`ReadPositional` with the hooks, chosen by `ReadContext.Unusual` (also `SlowObjects`), so the usual loop has no checks (inline checks and a generic struct switch both measured 2-5% slower): keep the copies the same. A repeated read (`SchemaGrowthException`) calls `Reset`. Exceptions get the differences in `Exception.Data` (exception filter `AttachTo`). Nils in arrays are not counted.

## Caches and their scope

| Cache | Key | Scope |
|---|---|---|
| `FullPropertyInfo.Cache` | MemberInfo | global, only without property id resolvers. Shared by settings with different static filters, so nothing filter dependent is kept on them (`StaticallyIgnored` is only set on the instances of a session or of custom resolvers) |
| `FullPropertyInfo.SharedPropsCaches` | static filter array (by reference, `ConditionalWeakTable`), then Type, one per `PropertyOrder` | global, only without property id resolvers and without a session. The settings remember the cache of their array (`_sharedPropsCache`). Replace the filter array to change filters, an array changed in place keeps its results (like `SchemaStore.SessionKey`). `StaticPerOrder` (same keys) keeps what the static filters keep with the name as id for `GetStaticallyIncludedProps`: each session gets copies (it sets its ids on them), so the filters run once per type, not per call; `IndexedPerOrder` (same keys) the copies with the positions as ids that the sessions with only the indexed schema as property id resolver share |
| `FullPropertyInfo.MembersCache`, `OrderedMembersCache` | Type, one per `MemberSelection` (and per `PropertyOrder` but `Reflection`) | global, static metadata |
| `FullPropertyInfo.AttributesCache` | MemberInfo | global, static metadata |
| `MsgPackOptions._serializedPropsCache`, `_staticPropsCache` | Type | one session (set by `WithSchema` or `SchemaSession.Apply`, not copied by `Clone()`/`CloneOptions()`). Property ids are schema indexes, never share them between sessions. With the schema as the only property id resolver, `IndexedSchemaTypeResolver.TryAssignIds` gives each property its position when the entry has the same names in the same order, without the name lookups |
| `ComplexTypeDef.ByPosition` | the session's property array (by reference) | one schema entry: the reader's properties at the positions of the entry (`ValueConverter.PropertiesByPosition`, array layout), one immutable reference (frozen entries are read by several threads) |
| `SchemaStore` schemas, inline schemas, writer and reader sessions | `SchemaId` / schema bytes / `SessionKey` | one store (shared by the settings that use it). Received schemas limited by `MaxSchemas`, sessions frozen once published |
| `PropertyAccessor.Cache` | MemberInfo | global. Reflection for the first 100 calls, then typed delegates (`Delegate.CreateDelegate` into `TypedAccessor<TTarget, TValue>`; fields: compiled from expression trees, `FieldDelegates`), unless the runtime does not support dynamic code (NativeAOT) or `MsgPackOptions.CompilePropertyAccessors` is off |
| `CollectionInfo`, `ObjectConstructor`, `FilterDefaultValues.DefaultInstances`, `SerializationRules.HasAnonymousType`, `SerializationRules.IsFieldStruct` | Type | global |
| `TypeResolver` name caches | name / Type | global, guarded by one (re-entrant) lock |

Custom property id resolvers without the schema are consulted on every call (by design, they may have their own cache).

## Invariants and gotchas

- **Property ids must be unique per type** and must not be `""` or `"@"`: `FullPropertyInfo.ThrowIfIdsNotUnique` checks once per type, the map entries are then collected in arrays without checks.
- **Exceptions of property getters/setters** are rethrown as they are (not as `TargetInvocationException`), whether the accessor uses reflection or a bound delegate.
- Endianness: MsgPack is big-endian, `EndianAction` can override it. `ByteWriter.WriteEndian` writes the same bytes as `BitConverter.GetBytes` followed by `SwapEndianChoice`.
- **DateTime** (`DateTimeFormat`, maintainer's decision 2026-11-17: drop-in for Json.NET, which read a `Local` value back as local time where a timestamp gave UTC, an hour early on a clock in Amsterdam): `Native` (default) is extension type 6 (`MsgPackOptions.DateTimeExtensionType`, fixext 8) holding `DateTime.ToBinary()` as an integer in the settings' byte order (62 bits of ticks, the Kind in the top 2: Utc and Unspecified as they are, Local the ticks in UTC with the Local flag), read by `MsgPackOptions.FromNative` (Utc/Unspecified without a call; Local through `DateTime.FromBinary`, which converts to the reader's time zone; ticks beyond `MaxValue` are a `MsgPackException`, never `FromBinary`'s `ArgumentException`). It was measured before it was built (microbenchmark, .NET 8, ns per value): write 7.1 -> 3.1 (Utc), read 7.1 -> 4.7, Local 147 -> 138 / 104 -> 104 (the time zone either way), against timestamps with Local values as `[timestamp, offset]`; dates of whole seconds grow 6 -> 10 bytes. Writers: LsMsgPack `MsgPackWriter.NativeDateTime` (`TypeKind.DateTime`; `Timestamp` is `TypeKind.DateTimeTimestamp`), LsMsgPackDebug `MpDateTime` (`IsNative` by its type code: new items take the settings' format, `MpDateTime(settings, native)`; DateTimeOffset items are always timestamps), `KeptValues.WriteNative`. Readers take both formats whatever the option (`TryReadDateTime`: native first, the timestamp path in a method of its own; untyped ext 6 after the custom extensions, as ext 5), `SchemaBytes.CopyExtension` swaps type 6 as a number unless a custom extension has the code (`HasCustomExtensionCode`). Code 6 is refused for custom extensions and converters while `Native` is on (`ReservedCodes`, with code 5 under `Preserve`; `Timestamp` frees it, e.g. for Nerdbank's extension types). `Timestamp` is set by every preset for another library, `MsgPackMediaTypes.ToPlain` and the stream index (`IndexFormat.Options`, its `Modified` and metadata dates). Timestamps: values are returned as UTC by default, they do not keep the `DateTimeKind` (compare with `ToUniversalTime()` in tests). `ReadDateTimeKind` (Utc default, Local, Unspecified = the UTC clock time; `MsgPackOptions.FromTimestamp`, used by `MpDateTime.Value` and LsMsgPack `MsgPackReader.TryReadDateTime`/`ReadPlain`; `TryReadTimestamp` is UTC) and `UnspecifiedDateTimeKind` (Utc default; Unspecified written as Utc or Local, `ToTimestamp`): Utc and Unspecified values keep their clock time in any time zone as System.Text.Json reads them (the Kind becomes Utc), a Local value the moment. A `DateTimeOffset` read from a timestamp gets the local offset for Local, zero otherwise (`OffsetOfTimestamp`). `DateTimeOffset` is written as `DateTimeOffsetFormat` says: `TimestampAndOffset` (default, `[timestamp, offset minutes as a short]`, Nerdbank's bytes), `Timestamp` (the offset is lost) or `ClockTimeAndOffset` (MessagePack-CSharp). The arrays look the same, readers take them as the option says (`OffsetOfArray`, `TryConvertItems`, LsMsgPack `DateTimeOffsetReader`/`DateTimeOffsetArrayReader`) and a bare timestamp in any format. Timestamps before 1970 round the seconds down, the nanoseconds are always added (`MpDateTime.DateTimeToEpoch`), as the spec requires.
- **Values read into other types** (`ValueConverter.ConvertScalar`, as the JSON serializers read text): into `string` numbers (invariant), `true`/`false`, timestamps (ISO 8601), bin 16 as a Guid, other bins as base64; strings into Guids and enums (by name, ignoring case). Number map keys become string keys, except with the indexed schema (`ConvertKey` throws: object keys are indexes, indistinguishable from a dictionary's numbers), and an array that is not `[key, value]` pairs read into a dictionary throws. An object read untyped (`object`, `Dictionary<string, object>`) only has names with `ObjectLayout.Map` without the schema.
- Reading maps uses `MapConversionEqualityComparer`: numbers are equal across types (`(byte)3` equals the property id `(int)3`), strings and integers take a fast path.
- **Type injection** (docs/security.md): a type picked by the data (type id, schema name, custom resolver) must be assignable to the declared type, checked in `TypeResolver.Resolve` (so both serializers) before the instance is created; names with `,` `[` `]` `&` `*` are refused in `TypeResolver.ResolveName` (`Type.GetType` would load the named assembly). Framework assemblies (`TypeResolver.IsFrameworkAssembly`) only offer their public types (`IsVisible`, `TypeResolver.Visible`, also when caching an assembly). `NativeAssemblies` (searched for names) has the collection assemblies, System.Runtime.Numerics and System.Collections.Immutable when it can be loaded. The optional `MsgPackOptions.TypeGuard` (`IMsgPackTypeGuard`, `AllowedTypesGuard`) is asked only when the picked type differs from the declared one: in `TypeResolver.Resolve` and in LsMsgPack's `ObjectReader` fast path. A new place that creates instances of a type from the data must do the same checks (`TypeInjectionTests`).
- **Type names are short by default**, so the classes of an assembly searched for types need unique names (`TypeResolver.Pick` keeps the concrete candidates assignable to the declared type; two fitting classes throw "Type assignment dilamma", a name that fits one is not cached). Every `Deserialize` registers the assemblies the root type reaches (`TypeResolver.CacheReachableAssemblies`: generic arguments, element types, base types, public property types, the types of public and attributed fields, not framework assemblies; once per root type). Types not reachable (implementations in other assemblies, values declared as `object`) need `MsgPackTypes.CacheAssemblyTypes(typeof(T))` or an `AllowedTypesGuard` that allows them (`AllowAssembly` registers the assembly, `Allow` the type alone: `TypeResolver.CacheType`). docs/schema.md explains the lookup order. The names of a schema are resolved without throwing when it is read: an unresolved entry is found by the name of the type read (`IndexedSchemaTypeResolver.TryGetDef`) or resolved with the declared type when a type id needs it (then "Unable to resolve type"). A short name the caches do not have is first looked up among the cached assemblies outside the framework (`OwnTypeNamed`: exactly one such class is it, also when a public framework class has the name; several go on to `Pick`; maintainer's decision 2026-11-15, test `TypeNameResolutionTests.ShortNameOfOwnAndFrameworkClass`), then `Type.GetType`, then the `NativeAssemblies` are cached (`CacheAssemblyLocked`, once per process): a framework assembly by `GetExportedTypes` (the same set as its `IsVisible` types, which `GetTypes` loads twice as many of: System.Private.CoreLib 25.6 -> 14.7 ms when a process reads its first schema or type id). LsMsgPack loads those types on the thread pool when a serializer is created (`LoadNativeTypesInBackground`, once per process, caches untouched; its flag is in a nested class so the caller does not run `TypeResolver`'s static initializers). Reading those names was most of the cold start left with ReadyToRun (see `../LsMsgPack/CLAUDE.md`, round of 2026-11-15).
- `Type.GetProperties()` also returns **public static properties**: `FilterStatic` (in `Default_StaticFilters`) leaves them out, so the data cannot set shared state. Static fields are never candidates (`IsFieldCandidate`), `FilterStatic` leaves them out too.
- **`MsgPackOptions.ObjectCreation`** (`Instances`, LsMsgPack `ReadPlan.Creator`): `Constructor`, `ConstructorOrUninitialized` (default), `Uninitialized`. Constructor exceptions are passed on as they are (`TargetInvocationException` unwrapped), an uninitialized object always gets `GC.SuppressFinalize` (finalizers of never constructed objects can end the process, docs/security.md). Weak references are never created uninitialized (the GC crashes on them). Collections and dictionaries always use their constructor (`Instances.CreateCollection`). Uninitialized creation costs ~55 ns on .NET 8 (compiled `new T()` ~12 ns): not a speed option on .NET; on .NET Framework it may be faster (not measured, documented as such). An `Expression`-compiled `Func<T>` factory was tried: 63 µs to compile per type, no gain for LsMsgPackDebug's per-`Type` lookup.
- **`ReferenceHandling.IgnoreCycles`** (`MsgPackOptions.ReferenceHandling`, `None` by default; internal `IgnoresCycles`, docs/schema.md "Cycles"): writing, an object with properties (a class) that is on the current path is nil, as System.Text.Json's `IgnoreCycles`. LsMsgPackDebug: `SerializeTracked` in `SerializeObject` (the complex-object branch, after collections, pairs and tuples), a `[ThreadStatic]` `CyclePath` whose `Start` the public `SerializeObject` sets per call (a nested call has its own path); a trailing cycle nil is trimmed like any nil (`SerializeAsArray`). LsMsgPack: `CycleHandler<T>` instead of `ObjectHandler<T>` for classes that can contain an object (`Serializer.CanContainObjects`: a property in either list of the plans that is not a number, string, enum, date, Guid or `byte[]`; otherwise nothing below the object can be it, the same bytes untracked; a derived type goes through `WriteBoxed`, which tracks every class) (`ICycleTracking.Tracked`, created by the handler so NativeAOT has it), `WriteTracked` in `WriteBoxed` and the names plan of anonymous types, `WriteContext.EnterObject`/`LeaveObject` (the path is an array of `PathEntry` structs: an `object[]` store is a covariance check, `StelemRef`, 3% of writing small objects), `ClearPath` at the start of a call. Nothing changes without the option (no test in `ObjectPlan.Write`: a field test there cost generated arrays ~3% in some runs). `CycleTests` (bytes equal LsMsgPackDebug's).
- **`ReferenceHandling.Preserve`** (docs/References.md; `References/`; maintainer's decisions 2026-11-16/17, gaps checklist item 6): the second occurrence of an object or collection is extension 5 (`MsgPackOptions.ReferenceExtensionType`) whose content is the path to the first (`ReferencePath.Encode`/`Decode`: positive ints, always big-endian minimal, no array header; the empty path is the root), nothing at the first occurrence. Steps: array index, or map entry number (the value; entries not written don't count), through `{ "": typeId, "@": ... }` wrappers (a path points to the value as written, the wrapper included; readers also look up the wrapper's content, `ContentOf`); a repeat whose declared type differs gets the type id wrapper. Tracked (`SerializationRules.TracksReferences`): objects with properties and collections; not strings, `byte[]`, structs, framework types written as one value or a fixed array, multidimensional arrays; map keys always in full, never a target (Debug `ReferenceTable.InKeys`). Converters: identity follows the original value (`ConvertSurrogate` registers with `replace`). Extension code 5 refused only with Preserve (`ReferenceCode.ThrowIfUsed`: LsMsgPack's `Serializer` constructor, `BinaryConverterHandler`, Debug `SerializePreserving`/`SerializeConverted`); without it a code-5 converter reads ext 5 as its value (`ReadsReferenceItself`). Reading (Core): `MsgPackReference` (a plain value, `IMsgPackExtension`, with its resolver and `Offset`), `ReferenceResolver.Current` ([ThreadStatic], set by the caller for the conversion), `Registered(settings, plain, created)` by the plain node: objects in `ConvertMap`/`ConvertPositional` before their values, arrays before their elements, other collections through `CollectionInfo.CreateBeforeElements`/`FillCreated` (a parameterless constructor and `IList` or `ICollection<T>.Add`: created empty, registered, filled after the elements are converted; maintainer's decision 2026-11-17) or after them when made of them (factories, items constructors of stacks, generated `FromItems`: a cycle back is the error `Cycle`), dictionaries and pairs before their entries. `ConvertDeserializeValue` asks `TryGetMade` first (containers, converted values): Core converts **last to first**, so a reference is often resolved before its target is converted; the resolver then reads the target's bytes (LsMsgPack) or converts its plain node (Debug `PlainReferences`) and registers it, and the later conversion of the target finds it. A target not made (a member the class lacks, another type) is read again (a copy, registered for later references); a path to nothing or not earlier: `NotConverted` (follows `ReadErrors`). **Readers without the option** (maintainer's decision 2026-11-19, gaps checklist item 9): the first reference a resolver resolves throws the internal `ReadAgainPreserving` (`PlainReferences.Resolve` when the settings don't preserve, LsMsgPack's `ByteReferences.Resolve` when the table doesn't), never marked (`MarkNotConverted` skips it), and the call reads again with the option (Debug `ConvertDeserializeValue` with `settings.Preserving()`, a copy sharing the session caches and differences; LsMsgPack `Serializer.PreservingReader()`): copies grew exponentially (a value with two references to the one before it, nested 18 times: 1.2 KB → 1.4 GB), now each target is one instance and cycles resolve; the differences are `Reset`, the first attempt's objects had `OnDeserializing`. Extension data, option (a): `ReferenceResolver.Expand` in `TryKeep` and the positional keep replaces each reference in a kept value by a copy of its target (`PlainAt`); a cycle inside a kept value is an error by depth (kept, maintainer 2026-11-17). The copies of a call are charged (`Charge`: values, 1 per reference and the length of each array/map inside a copy) against `PayloadSize()` + `CopyAllowanceBeyondPayload` (4096) (maintainer's decision 2026-11-19): `ByteReferences` the body's bytes, `PlainReferences` the length Debug passes (`BodyLength`: the stream's rest when it seeks) or the values of the tree; past it `NotConverted` (follows `ReadErrors`); the reused LsMsgPack table starts again (`ResetCopies`). Identity tables: `IdentityMap` (object → int by reference, open addressing, find-or-add in one probe; LsMsgPack's writer and plain offsets: see `../LsMsgPack/CLAUDE.md`), Debug and `PlainReferences` still use `Dictionary` with `IdentityComparer`. Callbacks: once per object (a reference is not called again). Streams: each `WriteObject` is its own root. Tests: `ReferenceTests` (Debug, Ls, Gen; `SameBytesAsDebug`, `Cycles_ThroughCollections`, `ReferencesBeforeTheirTargets_OneInstance`, `Streams_EachValueItsOwnRoot`), `CrossLibraryTests.SameBytesAndValuesPreserved` (the corpus and `ReferenceTests.SharedValues`, identity compared by `Dump(..., seen)`), `CallbackTests.Preserve_EachObjectCalledOnce`.
- **Compression** (docs/Compression.md; `Compression/`; maintainer's decisions 2026-11-21: MessagePack-CSharp's format, the body only, no package dependency in the serializers): `MsgPackOptions.Compression` (a public abstract `MsgPackCompression`: `Layout` Block/BlockArray, `MinimumLength` 64, `BlockSize` 64 KiB, `Compress`/`Decompress` of raw LZ4 blocks; the implementation is the add-on `LsMsgPack.Lz4`) and `MaxDecompressedLength` (unlimited, 64 MiB in `LsMsgPackHttpOptions`). `CompressedBody` (internal, spans, shared by both serializers) writes ext 99 (`d2` + int32 length + block, compact ext header, fixext for 8/16) or `[ext 98 of compact uint lengths, bin 32 per block]`, headers in the options' byte order; returns 0 (write the body as it is) under `MinimumLength` or when not shorter (MessagePack-CSharp writes it anyway). Reading: `StartsCompressed` (headers only), `Read` (LsMsgPack: span, rented array), `DecompressPlain` (LsMsgPackDebug's items: the unpacked ext or `object[]`); every claimed length is checked before allocating: `MaxDecompressedLength`, and `CheckExpansion` (at most 255 bytes per block byte + 64: LZ4's match lengths grow 255 per byte; zeros compress ~250x, `Zeros_WithinTheExpansionCheck`), for every block of an array before the body is allocated; a block must decompress to exactly its length. Only where a body starts (after the schema or its reference; LsMsgPack `Deserialize`/`DeserializeWithSchema`, LsMsgPackDebug items at depth 0) and only with the option (as MessagePack-CSharp). Not the bodies of stream heads (`SerializeBody`) nor values of unknown length. Tests `CompressionTests` (Debug, Ls, Gen; same bytes as Debug in both byte orders, invalid bodies), interop `CompressionInteropTests`.
- **Limits for untrusted data** (gaps checklist item 9, maintainer's decisions 2026-11-19; docs/security.md): `MaxObjects` (arrays and maps read), `MaxItems` (elements + entries, `_maxItems` a long), `MaxStringLength` (bytes as written), `MaxBinLength` (bin and ext 8/16/32, not fixext), all `int.MaxValue` by default, `LsMsgPackHttpOptions` sets 1,000,000 / 10,000,000 / unlimited / unlimited on both media types' options. Security checks: never marked, `MsgPackOptions.OverLimit`/`TooLong` messages. Per call: LsMsgPack counts in `MsgPackReader.Count` (every array/map header read; skipped values are not counted, `Skip` has its own), reset by `Reset` and by `ReadBody` (`ResetCounts`: the schema doesn't count, a read repeated after growth starts again), `ValueReader.Slow` uncounts the header a typed reader read before it falls back (`Uncount`, else `object` values counted twice); a restart halfway (extension data, `Restart`) still counts the members read before it twice. LsMsgPackDebug: `MsgPackVarLen.CountContainer` with [ThreadStatic] counts started by the public `MsgPackItem.Unpack(Stream, MsgPackSettings)`, every value of the item tree (also skipped ones), `ThrowIfTooLong` before `ReadBytes` (only when a limit is set: unlimited keeps the "longer than a .NET array" error); its exceptions are `PassedOn` (not wrapped; under KEEPTRACK an `MpError`). Tests: `ResourceLimitTests` (Debug, Ls, Gen; HTTP defaults).
- **`MsgPackOptions.MaxDepth`** (256, both serializers): reading refuses arrays and maps nested deeper (LsMsgPackDebug passes the depth to `MpArray`/`MpMap.Read` via `_depth`, the exception is marked in `Exception.Data` so the levels above do not wrap it; under KEEPTRACK an `MpError`), writing refuses deeper objects and collections (cycles; LsMsgPackDebug: the `depth` parameter of `SerializeObject`). Without it deep data ends in a stack overflow.
- Reading from a `Stream`: use `ReadExactly`/`ReadByteExactly`, `Stream.Read` may return fewer bytes (network streams). Data that ends early throws "Unexpected end of data.". Lengths and counts from headers are checked against the rest of the data before anything is allocated (`MsgPackVarLen.SlotsFor` and `ReadBytes`, LsMsgPack `MsgPackReader.Count`; only when `CanSeek`): KEEPTRACK allocates the slots the data can fill and reads up to its end, without it the reader throws.
