# TypeScript client `@lsmsgpack/client`

npm, organization `lsmsgpack`; published by `Publish-LsMsgPackTsClient.cmd` outside the repository with the NuGet version `yyyy.M.d.build` as `yyyy.M.(d*100+build)` (e.g. 2026.10.2201). docs/TypeScriptClient.md. ESM, no runtime dependencies, TypeScript 5.9 (`tsc` to `dist/`), tests `test/*.test.mjs` (node:test, against `dist/`, `@msgpack/msgpack` only as a reference). Values follow System.Text.Json except `Date` and `Uint8Array`.

## Sources

- `reader.ts`: all MsgPack formats, lengths checked before allocating, `maxDepth`; strings up to 32 bytes as an array of codes + one `String.fromCharCode.apply`, `TextDecoder` beyond and for non-ASCII; map keys (fixstr) through a 1024-slot cache by their bytes, so a property name is the same, internalized string.
- `schema.ts`: plain or described schema as an ordered entry list (short type names may repeat, `indexOf(name)` the first; the root entry `""` last; `TypeExpr` also `{k: 'model', name}` for the models).
- `decoder.ts`: plans per schema entry and options: defaults per kind, `create`/`fill` generated with `new Function` per entry, and `readArrayFn` for the array layout (`generateReadArray`: the values into variables, then the object at once, a literal or for a model `new Model(...)` of a generated function whose `prototype` is the class's: the class's constructor is not run, its field values come from a probe instance (`initialOf`: primitives as constants, `Date` and `[]` made, anything else `new cls()[name]`), fields the schema lacks keep them, in the class's field order; not for `classes`). Measured: a generated constructor function 41 ns per invoice object, `Object.create` + sets 52 ns, `new` + sets 150 ns, a literal with `__proto__` 103 ns. Names only as JSON string literals, the read functions bound as constants so every call site is monomorphic; a nil is the value the writer left out (`Plan.nilValue`: the schema's or the type's default, also for models and `classes`), a value missing after the end of the array keeps the class's (`Unread` marks the defaults still to be made); `__proto__` and CSP fall back to the generic loop, which copies a template object with a spread (`generateCode`). Read functions with the usual format of a kind read in place (`readString`, `readInt`, `readDate`, decimals, Guids; anything else through `value()` and the converter), defaults that must not be shared (`Date`, structs) made after the values in `complete`; type ids `{ "": k, "@": ... }` anywhere, such an object gets its entry name in `$type`, first (`createTyped`); with `models` an entry of a model's type name is `new cls()` (only the fill is generated; `Plan.missing` = properties the class does not initialize, they get the schema's defaults) and a plain schema takes the property types from the models. With models, `Plans.build` tells the `ModelSet` what the models lack (docs/TypeScriptClient.md "Sent back, nothing is lost", the TS side of extension data): `keep` per model the properties it doesn't have (`ModelClass.kept`, by field: .NET name + `writerType`, the schema's type without entry indexes, `{k:'model', name}`), `learn` the entries of classes the models don't have (`LearnedClass`, by type name, once per schema); the latest schema read wins. Per plan, not per object.
- `models.ts`: `defineModels` of the generated file (`ModelSet` by type name and by constructor, `$type` defined on the prototypes (not enumerable), the declared types parsed into `TypeExpr`; the decoder takes the models' int64/dates/decimal and throws when given others). Keep the grammar in sync with `LsMsgPackTypeScript`.
- `names.ts`: `propertyNames: 'camelCase'` (default; models carry theirs, a `defineModels` without it is `'dotnet'`): a port of System.Text.Json's `JsonNamingPolicy.CamelCase`, `names.test.mjs` pins its output; tests comparing with the test server's PascalCase JSON pass `propertyNames: 'dotnet'`. The decoder's plans get the converted names (`Plan.names`; keys of the map layout are looked up by the writer's names, `indexOfWriterName`), pairs `{ key, value }`; models: `ModelProperty.field` from the .NET name with the same function (the generator uses STJ itself, keep them equal), the writer reads the fields and writes the .NET names; plain objects are written as they are, the server matches ignoring case (camelCase plain request bodies cost the server ~12% more to read than exact names); the decoder throws when the models were generated with other names.
- `store.ts`: as `GetSchemasHeader`/`LearnSchema`: learned only when the hash equals `MsgPack-Schema`, per route (`advertiseByRoute`, default true: `routeOf` the path, segments of digits or 16+ hex digits and dashes are `#`; at most 4 ids per route, 1024 routes per origin; a route not called yet, or no path, gets the MRU per origin, which changes only for ids new to a route), then the `preload`ed ones (the generated schema set, for every origin or one), max 64; `export`/`import` (with `routes`). The client passes `target.pathname` (`read`/`decode` take a path). The same rules as the .NET client (`LsMsgPackHttpSerializer.RouteKey`): change them together.
- `client.ts`: fetch wrapper, `models` and `schemas` options; the Accept also lists plain x-lsmsgpack because ASP.NET Core's negotiation does not match a parameter it does not list. `client.stream(url)` asks for a stream in its Accept (no `*/*`: MVC answers that with JSON), `client.openSeekable(url)`.
- `writer.ts`: plain MsgPack request bodies; `$type` is written as the type id `""`, first (the formatters' plain readers take type ids). Model instances: a `ValueWriter` closure per declared type (WeakMap per `TypeExpr`), names pre-encoded per model, the key order of an instance without other properties remembered (`shape`), Guid text parsed without regex, type id where declared ≠ class, at unknown places when the class extends another; the properties of a model written by a function generated per class (`generateModelWriter`, `EncodeOptions.generateCode`, the client passes its own). Kept properties of a model are written with their .NET name and `writerOf` their type, plain objects of a learned class (their `$type`, or the declared type name) by its plan like a model (`described`: one method for both, the type id decided by the caller; a separate call level cost ~3% writing invoices with models). Plain objects in one `for...in` pass with `hasOwnProperty` (V8 loads the values through the enum cache) and their encoded keys cached, the map header written for every key and made smaller afterwards when values are left out (`patchMapHeader`); strings up to 32 chars by a loop, longer ones with `encodeInto`.

## SignalR

`signalr.ts` (subpath export `./signalr`, docs/SignalR.md and docs/TypeScriptClient.md "SignalR"): `LsMsgPackHubProtocol`, structurally `IHubProtocol` of `@microsoft/signalr` (nothing imported: no runtime dependency; `@microsoft/signalr` and `-protocol-msgpack` are devDependencies for the tests). The envelope as the .NET `LsMsgPack.SignalR` (Microsoft's MessagePack layout: invocations always with the stream ids, close with allowReconnect), VarInt frames; each value read by `Decoder.readValue(..., null)` with `indexedSchema: false` (so `SchemaReader.typeNames`: type ids of the names mode become `$type`, `{ "": name, "@": value }` its value) and written with `w.root(0)` (references per value, as .NET writes each value as a payload). Parsing all 9 message types (the JS client only receives some), unknown types logged at Information and skipped. Tests `test/signalr.test.mjs` (envelope against `@microsoft/signalr-protocol-msgpack`, the test server's `TestHub` with both names, Microsoft's client against "messagepack"); `bench/signalr.mjs` (numbers in docs/SignalR.md).

## References

`references` (DecodeOptions, EncodeOptions; docs/TypeScriptClient.md "Shared objects and cycles", docs/References.md): extension type 5, the path to the first occurrence.
- Decoder (`SchemaReader`): `'preserve'` keeps every object/array/dictionary by the offset of its first byte when it is made (`made`, before its values; the type id wrapper's map offset for a wrapped value), so `Plan.prepare` skips `readArrayFn` under it (it makes the object after the values). `'default'` has no `made`: the first reference throws `ReadAgainPreserving` (a plain object, no stack) and the `Decoder` (`read`, `readValue`, every entry point goes through them) reads the payload again with `'preserve'` and its own plans (`preservingPlansOf`: `prepare` differs), as .NET's `ReadAgainPreserving`; no copies, they grew exponentially (doubling chain, 18 levels, 341 B: 556 ms and 249 MB before, 1.3 ms; the read benchmark unchanged, 2026-11-19). A reference is resolved by walking the bytes from `root` (`itemAt`, element offsets cached per container in `walked`, the non-allocating `MsgPackReader.skip`); not made there (a skipped member's value): the target is read again once with the declared type's read function and kept (`rereading` detects a cycle). A reference with a type id sets `$type` on the shared plain object when it has none (read in a `List<Dog>`, sent back in full where `Animal` is declared: the server needs the class). `prefix`: a stream head's body (`MsgPackStreamReader.bodyPath`, as .NET's `BodyPath`). The reference branch of `readObject` is out of it (`notAnObject`): readObject stays small (models read +4.7% with it inline).
- Writer: `steps` (Int32Array per depth: the element index or entry number written), `refs` (object -> path) only with `'preserve'`; `root(depth)` per stream value; Map keys written with `refs` off. The plain-object loop stores the step only under the option (the store cost ~2.5% writing invoices); the generated model writer gets the entry number as an argument.
- Tests `references.test.mjs` (hand-made payloads, the encoder's bytes, and the test server's `/shared`, `/echo/shared`, `/stream/shared`, `/stream/echo/shared`, serialized with Preserve in the controllers, not by the formatters: Preserve there would put references in the invoices too, the benchmarks' payload).

## Streams

docs/TypeScriptClient.md "Streams" (the maintainer's decisions: read and write, the index with random access, client only). The TS side of LsMsgPack's streaming: the same format, checks and error texts.
- `stream-escape.ts`: the 0xC1 codes, the only TS place with them (change together with Core `Streaming/Escape.cs`); `plain()` rewrites a value with escapes into known lengths from the counts kept while it was passed.
- `stream-sources.ts`: sequential (ReadableStream, Response, (async) iterables, bytes); `RandomAccessSource` with `size`/`read`/`stream(offset)`: `bytesSource`, `blobSource`, `fileSource` (duck-typed Node FileHandle, no `node:` import), `httpSource` (Range requests, refuses a server that answers 200).
- `stream-index.ts`: port of `IndexFormat.cs` (entries, points, tail, CRC-32 in `crc32.ts`, `readAll` with the backward search, the same validation).
- `stream-reader.ts` (`MsgPackStreamReader`): everything synchronous over one buffer; the synchronous steps throw the `NeedMore` symbol when the buffer ends and `run()` refills and calls them again, so **every step must check before it mutates** (or keep its progress in fields: `payloadPending`/`tokenLength` counting down, `tailPending`, `skippingStreamValue`, `passStarted`). A value read whole (`readObject`, `elements`) is first decoded from what is buffered (`Decoder.decodeAt`/`readValue`, internal; `EndOfDataError` or `EscapeError` (errors.ts, not exported) → passed token by token with a mark, then `plain()` and decoded once). Inline schemas are kept per reader (one `Schema` instance per bytes, the plans are per instance) and `store.register`ed (PerStream references). Heads: `readHead`, the declared type of each place in the body follows from the described schema's root (`typeOfNext`: list, dict, pair, tuple, objects in both layouts), or the type passed (a model class, an entry name, a `TypeExpr`).
- `stream-writer.ts` (`MsgPackStreamWriter`): the encoder's `Writer` (exported internally, `take`/`truncate`/`bytesView`), a frame stack as the .NET writer, sink a WritableStream or a function, `ready` for backpressure, the index state as `IndexState`; writes plain MsgPack only: no heads, no indexed schema, no Append, no EndianAction.
- Tests `stream.test.mjs` (1-3 byte chunks), `stream-server.test.mjs` (test-server `StreamController.cs`: .NET writer streams with range processing, `POST /stream/echo` reads a TS-written stream with the .NET reader and its index).

## Test server and benchmarks

- `test-server/` (`LsMsgPackTsTestServer`, in the sln and slnf) serves formatter output on 127.0.0.1 (first stdout line: its address, stops when stdin closes), `/expected/...` as System.Text.Json and `/dotnet/...` as what LsMsgPack reads back (the constructor values a .NET client keeps). Its JSON has `IncludeFields` for `Motion` (`Vector2/3/4` written by their fields, a `[DataMember]` field; no other model has public fields). `test/helpers.mjs` `generateModels` runs lsmsgpack-ts over it into `test/generated/p<pid>-<n>/` (ignored; per process: node --test runs the files in parallel, folders older than 10 minutes are removed) and compiles with `tsc --strict --noImplicitOverride`. `LSMSGPACK_TS_REQUIRE_SERVER` makes a missing server or generator an error (CI job typescript-client).
- `bench/bench.mjs` (100 invoices, Node 22): read 0.68 ms (models 0.67-0.68, CSP 0.95-0.97, CSP with models 0.96; application/msgpack 1.89, @msgpack/msgpack 2.9, text Guids and decimals) vs `JSON.parse` with UTF-8 decoding 1.27 ms; write 1.10-1.19 ms (models 1.11-1.23) vs `JSON.stringify` with UTF-8 encoding 1.58 ms. Tried without effect: a prototype check before the `instanceof` chain of `write`, reusing the grown buffer between `encode` calls, a table of powers of ten for decimals.
- `bench/stream.mjs` (`npm run bench:stream`, 10 000 invoices): read `elements()` 94-104 ms vs `decode` of the same `List<Invoice>` payload 123 ms; write with the stream writer 129 ms vs `encode` of the list 151 ms; the index costs nothing measurable.
