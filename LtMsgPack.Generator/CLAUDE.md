# Source generator

`LtMsgPack.Generator/`: Roslyn 4.8 incremental generator, netstandard2.0, packed into the LtMsgPack package under `analyzers/dotnet/cs` with `buildTransitive/LtMsgPack.props`, docs/SourceGenerator.md. Tests: `LtMsgPack.GeneratorTests` (snapshots, C# 7.3/.NET Standard 2.0 compile, diagnostics, contract fixtures), `LtMsgPackAotSmokeTest/run.sh`.

It writes contexts: classes with `[LtMsgPackSerializable(typeof(T))]` deriving from `LtMsgPackContext`, and the context of the assembly (`[assembly: LtMsgPackGenerate(Include = AllTypes | Serializable | DataContract | JsonSerializable)]` or the MSBuild properties `LtMsgPackGenerate`, `LtMsgPackContextName`, `LtMsgPackAutoRegister`; `GeneratedMsgPackContext` in the root namespace). `TypeWalker` collects the roots and the types they reach (property types, elements, type arguments, base classes) as equatable models, `Emitter` writes C# 7.3 (no `??=`, switch expressions, `#nullable`): `Default`, a constructor passing the contract version, `AddTypes` (`DynamicDependency` when the compilation has it) listing the types by number and `Describe(int)` with a nested class `LtMsgPackType{n}` per type (see Cold start), a writer/reader class per concrete class, and a `[ModuleInitializer]` (C# 9+, polyfilled attribute) calling `GeneratedTypes.Register`.

- **Contract** (`LsMsgPack.Generated` in Core, `LtMsgPack.Generated`; public, `[EditorBrowsable(Never)]`, may change between releases; version 2: `ReadPositional` sets a nil's value (`GeneratedCapabilities.ReadPositionalNil`, `o.X = default(T)` for members without `[DefaultValue]`, `PropReader.ReadNil` for the others); version 3: structs, see below; `ReadMap`; `Describe`; sets, dictionaries and collection interfaces, see below): `GeneratedContract.MinSupported..Current` is the range of versions the runtime uses, otherwise the context is ignored (`IsUsable`); also when `AddTypes` hits missing members. Additive changes raise `Current` only (new capabilities are optional virtuals or `GeneratedCapabilities` flags whose absence means "the runtime does it"), never add abstract members to the types generated code derives from. `ContractFixtureTests` compiles the frozen output of every supported released version (`LtMsgPack.GeneratorTests/Fixtures/v*`, see its README) against the runtime. `Emitter.ContractVersion` must equal `GeneratedContract.Current` (a test checks).
- **Contexts and the registry**: a serializer registers its contexts (constructor + options' `Contexts`) with `GeneratedTypes.Register` when `UseRegisteredContexts` is on (the default), because Core (`Instances.Create` asks the registered creator before reflection, `CollectionInfo` the registered `FromItems`) only sees the registry. Off: it neither uses nor adds to the registry, which the test adapters rely on (`TestMsgPackContext` has `AutoRegister = false` so the Ls/Lt runs keep the runtime paths): never create a serializer with `TestMsgPackContext` and the registry on in tests.
- **Tier 1** (accessors, creators, instantiations): `GeneratedValues` factories create descriptions whose subclasses `new` the generic handlers and readers (`IGeneratedInstantiations.Instantiate`), so AOT compilers see them. The runtime asks the options' `Contexts`, then the registry, where it used reflection: `PropWriter/PropReader.Create`, `ReadPlan` creator, `Serializer.Instantiate` (replaces `MakeGenericType` in `CreateHandler`/`CreateReader`); Core's `PropertyAccessor` and `Instances` use registered ones (LsMsgPack). A generated property is used only when declaring type, name and type equal the runtime's `PropertyInfo` (stale models). Asked when plans are built, never per value.
- **Tier 2** (`GeneratedObjectCode<T>`, a generated subclass per concrete class): `GeneratedMember`s are the class's properties as `FullPropertyInfo.GetProperties` sees them (inherited ones too, in the predicted reflection order: derived class first). `Serializer.GeneratedWritePlan` maps each plan position to a member id once per plan (`-1`: the generated code would write it otherwise than these options do, e.g. `GuidFormat.String`, a custom extension, `[DefaultValue]`), not at all with custom dynamic filters or `AddTypeIdOption.Always`. Members of `GeneratedKind.None` with an accessible getter are read by the generated code and go to the runtime's handler of their type through `GeneratedWritePlan.Value<T>` (what `PropWriter.Write` does after its getter, handler per position made at the first value: no getter delegate and no virtual call; with the other changes of that round a game state 19% faster on .NET 8, 9% on .NET 10, a snapshot 20% / 5%, with names 25% / 19%); `Runtime` remains for inaccessible getters, positions without a member and the code of older versions. `ObjectPlan` keeps headers, type ids, `BeginObject` and depth and calls `Write` (a loop with a switch over the map; keys for maps, nil for left out values in arrays, trimming) or `WriteUnrolled` (array layout untrimmed, when the map equals `UnrolledIds`). Reading: `PropReader.GeneratedId` per property (`ReadMember`), `ObjectReader.ReadPositional` and `ReadGeneratedMap`/`ReadByRef` call the generated loops `ReadPositional` and `ReadMap` (the keys through `GeneratedIO.TryReadKey`; `ReadValue` per value is only for the code of versions 1 and 2); a value in another format leaves the position and the runtime `PropReader` converts it (identical exceptions and `NotConverted` marking). The reporting paths (`Unusual`) stay runtime. Leaf kinds: string, integers, float/double, bool, char, enums, Guid, DateTime, TimeSpan, decimal (built-in extension), nullables of those; nested objects and collections go through the runtime (which uses their generated code). Immutable classes (constructor taking the values) are written, not read.
- **The runtime writes the same code** (`LtMsgPack/Writing/CompiledWriter.cs`, see `../LtMsgPack/CLAUDE.md`): `CompiledObjectCode<T>`/`CompiledStructCode<T>` implement `Write`/`WriteUnrolled` of this contract with expression trees per plan, mirroring `Emitter.Omitted`/`WriteValue`. A change to how the generated writers write a kind (or to `GeneratedWritePlan`/`GeneratedIO`) goes into both; `CompiledWriterTests` and the corpus of `CrossLibraryTests` ("Compiled") check the runtime's.
- **Non-public properties**: `GenerateOptions.NonPublic` (`[LtMsgPackGenerate(NonPublicProperties)]`, MSBuild `LtMsgPackNonPublicProperties`, default `Attributed`; the declared contexts are combined with the options for it), `TypeWalker.IsNonPublicCandidate`/`OptsIn` mirror Core, members after the public ones (never `Unrolled`), inaccessible accessors of covered properties through `[UnsafeAccessor]` (`GenerateOptions.UnsafeAccessors`, `Emitter.Accessors`; not generic or virtual: reflection), `TypeModel.KeepNonPublic` adds `NonPublicProperties` to the `DynamicDependency`. The unit test assembly's context is generated with `All`. Computed properties: `TypeWalker.KeptByDefault` and its own `IsNeverWritten` predict Core's default.
- **A method with the code of every property only once per object**: its frame is zeroed per call and grows with the class (814 bytes for 114 properties). `ReadValue`, called per value, made reading maps slower than the runtime on wide classes (real SDK models of 70-190 properties, `Generic()` preset: reading 0.94-1.55x the time of the runtime; 0.75-0.96x with `ReadMap`), which the invoices of 10-15 properties did not show. Benchmark wide classes too, and keep `ObjectReader.Read` small: the `ReadMap` call inlined there cost the runtime's maps 2-5%.
- **Cold start**: a context is listed at first (`GeneratedTypeSet.Add(Type, int)`, a `typeof` per type) and each type described on its first lookup (`GeneratedContext.TryGetType`, `Describe`; old code adds descriptions, which still works). Each type has its own class so its lambdas are in a closure class of their own: one class with the lambdas of all types has to be loaded whole. 86 types with 1060 properties: load 191 -> 2.8 ms, first write of a small class 215 -> 30 ms (without generated code 28 ms), of a class of 190 properties 260 -> 110 ms (68 ms: its big methods are JIT compiled at tier 0).
- **Debug builds**: generated code is in the user's assembly, so `Optimize=false` means unoptimized, while the library's package is optimized: the generated code is then slower than the runtime plans (1.2-1.9x). Reported as info `LTMP011` (once per compilation with a context), not avoided: skipping the generated code in Debug would run other code than Release. Measure in Release.
- Measured: unrolled vs a switch over the map: write 17% slower with the switch, read 10%, one call per property 54%/26%: so the loop with a switch plus unrolled writing, reading by switch only. Invoices, JIT: write 1.6x, read 1.13-1.15x over the runtime plans (arrays); WebAssembly AOT write 7.4-8.4x, read 2.8x. Reading is dominated by UTF-8 decoding and `ToLocalTime`.
- **Structs** (`TypeModelKind.Struct`, roots of `AllTypes`/`Serializable`/`DataContract` too; not ref structs): `GeneratedValues.Struct<T>(creator, code, StructProperty<T, V>(name, (ref T o) => o.X, (ref T o, V v) => o.X = v)...)` (Core `StructGetter`/`StructSetter`, `GeneratedStructProperty`: LsMsgPack's `PropertyAccessor` gets boxed accessors that work on the box through `Unsafe.Unbox`; explicitly typed `ref` lambdas, C# 7.3 infers no ref parameters). The creator only for a declared parameterless constructor (`HasCreator`), otherwise `StructCreator<T>` (what `ReadPlan.ByRef` recognizes). `GeneratedStructType<T>` (`IGeneratedStruct`: `Serializer.StructPlans` also without dynamic code) instantiates `ObjectHandler`/`ObjectReader`/`StructComputedPropReader`. Tier 2: `GeneratedStructCode<T>` (no struct constraint, so the plans generic over any T call it with `Unsafe.As`; its boxed overrides unbox through `StructUnboxer<T>`, which `GeneratedValues.Struct` sets) is the same code with `ref T o`; the runtime's members through `GeneratedWritePlan.Runtime<T>(..., ref o, ...)` and `GeneratedIO.Read`/`ReadNil(prop, ref o)` (by reference when the prop is `ByRef`, otherwise a copy in a box); `ObjectPlan.WriteStruct`/`ObjectReader.ReadByRef`/`ReadPositionalByRef` call it (see `../LtMsgPack/CLAUDE.md`). UnsafeAccessors of a struct take it by `ref`. `IsDefault` (`GeneratedCapabilities.IsDefault`, `TypeModel.IsDefault`, `TypeWalker.DefaultCheck`): the default check of `FilterDefaultValues` as `StructDefault` compiles it (fields of auto-properties and accessible fields against their defaults, nested structs, typed `Equals` of record structs and of framework types with `IEquatable<T>`), only for source structs where every field is visible and readable (otherwise null: the runtime compares, boxed without dynamic code, which allocated 128 B per write of the smoke test's route); `ObjectHandler` uses it instead of `StructDefault` (`LtStructTests.DefaultCheck_Generated_SameAsValueTypeEquals`). `init` properties of structs (record structs) go through by-reference UnsafeAccessors like the others (without UnsafeAccessor: reflection, `LTMP004`, a box).
- **`init`-only setters**: `o.X = v` only compiles in an object initializer, so accessible ones go through `[UnsafeAccessor]` too, whatever `GenerateOptions.NonPublic` says, since the runtime sets them with every option (`TypeWalker.CanSet`; `CanUseAccessor` has the limits both share). UnsafeAccessor ignores the setter's `modreq(IsExternalInit)`. The cost was only where delegates can't be bound (NativeAOT): with the JIT, the runtime already binds a typed delegate to them. Objects created by a constructor taking the values never call the generated code (`ReadPlan.WithValues`).
- Not covered (runtime): `init`-only and non-public setters the UnsafeAccessor can't call (before .NET 8, generic classes, virtual properties) and non-public setters `NonPublic` doesn't cover (reflection, info `LTMP004`), private types, types only met through type ids unless listed: `LTMP010` (`TypeWalker.ReportUncovered`, only reported when `PublishTrimmed`/`PublishAot`/`IsAotCompatible`/`IsTrimmable`, exposed by the props) names properties of an interface, abstract class or object type (also elements and dictionary values) that no concrete class of the context fits (object always). Generator diagnostics have external-file locations (`LocationInfo`): `#pragma` does not suppress them, `NoWarn`/`.editorconfig` severity does.
- **What NativeAOT needs for collections the runtime fills** (Core `CollectionInfo`/`ValueConverter`): `TypeWalker.AddImplied` also describes the element array `T[]` (not for dictionaries filled by `Add`), the concrete class of an interface (`ConcreteOf`, mirrors `CollectionInfo.GetConcreteType`), and keeps the static factory class of immutable/frozen collections (`TypeModelKind.Factory`, a `DynamicDependency(PublicMethods)` only). Immutable/frozen collections get `GeneratedValues.Collection<T, TElement>(items => Factory.CreateRange<...>(items))` (`FactoryCall` mirrors `CollectionInfo.FindFactory`; Core `GeneratedType.FromItems`), since `MakeGenericMethod` fails for value types under NativeAOT. `CollectionInfo` finds `IDictionary<,>`/`ICollection<>` among the interfaces of the type (`FindInterface`), never with `MakeGenericType`. The smoke test (`LtMsgPackAotSmokeTest`) covers these with the `Extras` class; `run.sh` publishes with `TrimmerSingleWarn=false` and fails on any `warning IL` line (gcc via `-p:CppCompilerAndLinker=gcc` when clang is missing). To check a context passed only to the constructor, run it once with `<LtMsgPackAutoRegister>false</LtMsgPackAutoRegister>` (the "registered" lines then pass only because the explicit runs registered it).
- **Sets, dictionaries, collection interfaces** (contract version 3): exact `HashSet<T>` and `Dictionary<TKey, TValue>` are `GeneratedValues.HashSet`/`Dictionary` (`TypeModelKind.HashSet`, `Dictionary`), a generic interface whose `ConcreteOf` is a `List<T>`, `HashSet<T>` or `Dictionary<TKey, TValue>` is `GeneratedValues.CollectionInterface` (the concrete class is described by `AddImplied`), so NativeAOT has the typed handlers and readers (`Serializer.InstantiateCollection`, `InterfaceReader`). Code of older versions describes them with `Collection<T>`: typed with dynamic code, boxed without. NativeAOT, dynamic code off (20 entries, or 1000 for the set, read): `Dictionary<string, int>` 3.9 -> 1.2 µs, `Dictionary<int, object>` 9.7 -> 2.0 µs, `HashSet<int>` 82 -> 16 µs, `IList<object>` 8.7 -> 1.7 µs; writing 1.3-4.6x. Core's `CollectionInfo.GetConcreteType` tries its candidates one at a time for the same reason (an `IList<struct>` has no `HashSet<struct>` there).
- WebAssembly: the `wasm-tools` workload is only in the user-local SDK `~/.dotnet/dotnet` (10.0.x), not in the system SDKs.
