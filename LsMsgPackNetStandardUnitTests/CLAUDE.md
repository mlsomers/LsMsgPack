# Unit tests (LsMsgPackUnitTests)

- **Shared tests**: the object-level test classes (`SerializingObjects`, `SerializingCollections`, `SerializingFrameworkTypes`, `SerializingGenericTypes`, `SerializingInheritanceHierarchy`, `SerializingPrimitives`, `SerializerRegressionTests`, `DeserializingEdgeCases`, `FilterTests`, `UnknownExtensions`, `CachedSchemaTests`, and in the interop project `MessagePackCSharpTests`, `NerdbankTests`, `IgnoreAttributeTests`) are abstract and call `Serializer` (an `ISerializerUnderTest`, `SerializerUnderTest.cs`, linked into the interop project); `Ls<Name>`/`Lt<Name>` subclasses at the end of each file run them against LsMsgPack and LtMsgPack. Call `Serializer.Serialize(...)`/`Serializer.Deserialize(...)` in them (extension methods mirror the overloads of `MsgPackSerializer`) and describe the settings with `MsgPackSettings`: the Lt adapter copies the format settings into `LtMsgPackOptions` (cached per combination of values) and maps custom extensions through `LtSerializer.ExtensionEquivalents` (decimal built in, the Nerdbank Guid added by the interop project; others make the Lt run inconclusive). Unknown extensions: `Serializer.IsUnknownExtension`.
- Item tests (`Mp*Test`, `MpRootTests`, `Extensions/`), `CompiledPropertyAccessors` and KEEPTRACK stay LsMsgPack-only.
- `Gen<Name>` subclasses run the shared tests against LtMsgPack with the code of the source generator (`Serializers.Gen`: `TestMsgPackContext`, written for all classes of the test assembly by `GeneratedContext.cs`, `AutoRegister = false` so the Ls/Lt runs keep the runtime paths; same in the interop project). `CrossLibraryTests` compares Lt and Gen with Ls (bytes and values for a corpus in all settings), `GeneratedCodeTests` checks that the generated code is used and equals the runtime for every member kind, option variant, cross-option read and rolling upgrade.
- **Tests that inspect the map format** (keys, `MpMap` casts, expected lengths, resolving types by signature, settings for other libraries) set `ObjectLayout = ObjectLayout.Map`, the default writes arrays.
- **Give test classes unique names**: type names are short by default, two classes called `Assorted` (nested in different test classes) make deserializing either throw "Type assignment dilamma".
- The benchmark tests (`TestCategory=Benchmark`, `BenchmarkInvoices`) compare with System.Text.Json (the baseline, default options; also listed: its source generation and Json.NET) and report through `TestContext`: run them with `--logger "console;verbosity=detailed"`. They are Inconclusive under KEEPTRACK.
- `ValidationTests` and other KEEPTRACK tests only run in the KeepTrack configurations (the project defines it there).
